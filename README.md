## 2. 笔记结构约定

每门课在 `<课程>/笔记/` 下组织：

```text
笔记/
├── README.md               # 目录说明（仓库内用；因其会被 MkDocs 当作 index.md，故不发布到站点）
├── 00_索引.md              # 文件列表、一句话摘要、建议阅读顺序、待确认事项（站点入口）
├── 01_<讲次>_<主题>.md
├── 02_<讲次>_<主题>.md
└── assets/                 # 配图，命名 fig_p<页码>_<主题>.png
```

`笔记/README.md` 是目录说明（仓库内用）：因 MkDocs 会把 `README.md` 当作所在目录的 `index.md`，
它与 `网站/check_site.py` 的核对冲突，故不发布到站点（见 `网站/prepare.py` 的 `SKIP_FILES`）——
站点上各课的入口仍是 `笔记/00_索引.md`。另外，`sys2/` 还有课程级 `README.md`（讲义原件与 `笔记/` 的分工、自检与重建步骤）；
`ADS/` 的目录说明见 `ADS/readme.md`，本地规则见 `ADS/AGENTS.md`，`密码学基础/` 的资料来源见 `密码学基础/readme.md`。

- 每篇笔记结构固定：**速览 → 核心概念 → 关键公式与算法 → 例子 → 听课重点与易混点 → 课前自测 → 来源**；
- 每篇笔记的「课前自测 / 课后回顾」都带**本讲小节锚点链接**，并另设「关联知识点」小节做跨讲 / 跨资料交叉引用；
  交付前跑一遍两个自检脚本：`python3 ADS/assets/check_md_links.py .`（相对路径）与 `python3 ADS/assets/check_md_anchors.py .`（标题锚点）；
  站点的构建产物与暂存目录都在点号目录里（`网站/.docs/`、`网站/site/`、`网站/.cache/`），两个脚本会自动跳过，不必额外传参；
  站点自己的核对交给 `python3 网站/check_site.py`（见 `网站/README.md`）；
- 图片一律放对应 `assets/`，在 Markdown 中用**相对路径**引用，不内嵌 base64；
- 标注约定：
  - `【讲义】`：讲义 / 幻灯片原文或直接提炼；
  - `(p.x)`：讲义页码；
  - `待确认`：讲义未写明或存在疑点之处，不做臆断；
  - 图注中注明来源页；标注「自绘」的图不是讲义截图。
- 「密码学基础」的笔记**按主题**编排（`NN_<主题>.md`，不是按讲次），结构同上（速览 → 主题小节 → 关键公式 → 易混点 → 复习清单 → 关联知识点 → 来源）；
  其标注约定为 `🙈`（资料标出的「待自己证明」处）、`教材对照`（按教材 **2007 年第 1 版**给出章节 / 定义 / 定理编号，已逐条核对）、`整理者按语 / 整理者核对 / 整理者作答`（AI 自己的推导与作答，**不是官方答案**）与 `待确认`；教材没有的课程内容标为「课程补充」；**不标注资料代号**（资料名与链接保留在 `密码学基础/readme.md`）。

## 3. 内容免责

- 笔记由 AI 依据讲义与参考资料（`密码学基础/` 依据的是其 `readme.md` 里列出的两份资料）整理，用于**课前预习与课后复习**，只做提炼与串讲，不添加原始资料之外的结论；
- 公式、算法细节、编码与页码以原始资料和教材为准，可能有遗漏；
- 发现与原始资料不符之处，以原始资料为准并欢迎提 issue。

## 4. 版本控制约定

`.gitignore` 采用**白名单模式**（`*` 排除一切，再按需放行），只追踪：

- Markdown：`*.md`
- 图片：`*.png`、`*.jpg`、`*.jpeg`、`*.gif`、`*.bmp`、`*.webp`、`*.svg`、`*.tif(f)`、`*.heic`、`*.ico`

显式排除：`AGENTS.md`（本地规则文件）。
**笔记自检脚本与配图脚本也是显式例外**（`.gitignore` §10）：
`ADS/assets/check_md_anchors.py`、`ADS/assets/check_md_links.py` 与 `ADS/笔记/assets/*.py` 入库 ——
网站自检脚本 `网站/check_site.py` 把 `check_md_anchors.py` 当作锚点规则的**唯一标准**，
笔记正文也直接链接那些「生成配图」的重绘脚本；这些 `.py` 被忽略时，
GitHub Actions 检出后缺文件，自检会直接报错退出（构建失败）。
**网站工程是白名单的显式例外**（`.gitignore` §8、§9）：`网站/mkdocs.yml`、`网站/requirements.txt`、
`网站/*.py`、`网站/static/*.js` 与本地打包的 MathJax（`网站/vendor/**/*.js`、`*.woff`）入库，
自动部署工作流 `.github/workflows/pages.yml` 也入库；
`网站/.docs/`、`网站/site/`、`网站/.cache/` 等暂存目录与构建产物不入库（§7）。
其余文件（PDF / PPT / DOC(X) / 代码 / 数据 / 压缩包 / 缓存 / 环境变量）默认不入库。
如需临时追踪某个被忽略的文件，使用 `git add -f <路径>`。
