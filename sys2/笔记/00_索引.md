## 1. 怎么用这份笔记

- 上课前看一份：先读「本讲速览」，再按小节顺序读正文，最后做「课前自测」。
- 每份文件结构固定：**本讲速览 → 按小节展开（带 PDF 页码）→ 听课重点与易混点 → 课前自测 → 来源、页码对照与待确认**。
- 「复习清单 / 课前自测」的每条问题都带**小节链接**（GitHub 风格标题锚点），可点击直接跳回本讲对应知识点回查；
  清单末尾另有「**关联知识点**」小节，把本讲与其他讲（以及讲义 PDF、配图清单）的相关小节链接起来。
  锚点写法与 GitHub / VS Code 预览一致，改标题后可用 `../ADS/assets/check_md_anchors.py .` 自查（该脚本与本课程无关，放在 ADS 目录下）。
- 标注约定：
  - `【讲义】`：幻灯片原文或直接提炼；
  - `(p.x)`：**PDF 页码**（不是幻灯片上印的页码；第 1–6 讲统一使用）；
  - `(s.x)`：**PPTX 幻灯片页码**（仅第 5 讲附录 A 使用，指旧版 `lec05.pptx`）；
  - `待确认`：讲义未写明或存在疑点之处（例如编号不一致、疑似笔误）；

## 3. 建议阅读顺序

按文件编号顺序（与讲义顺序一致）。六讲的关系：

- 第 1 讲末尾「多周期也不够快」→ 第 2 讲把流水线讲透（概念 → 分类 → 实现 → 性能），p.66 的路线图指向下一讲的三种冒险；
- → 第 3 讲搭起五级流水的数据通路与控制，并**预告**三类冒险与 stall / forwarding → 第 4 讲把三类冒险**讲到底**；
- → 第 5 讲先复习分类，再用「预约表 + 冲突向量」解决**非线性流水线**的调度，最后转向**多发射**：让一个周期启动多条指令；
- → 第 6 讲先处理多发射带来的**异常 / 中断**（另一种控制冒险），再从「程序怎么从 C 变成内存里的进程」讲清**软硬件接口**，最后用 OS 说明接口之上还站着谁。

> 第 3、4 讲有重叠：第 3 讲 §3.1.1 与第 4 讲 §4.0–§4.2 用的是同一组幻灯片（冒险总览、单存储器结构冒险、转发的检测条件等），
> 第 3 讲 §3.4 的 `Stall Condition Detection` 就是第 4 讲 §4.2 的前身。**第 4 讲里重复的概念段已压缩成指向第 3 讲的链接**
> （§4.0 总览、§4.1 结构冒险、§3.1 的 `add`/`sub` 例子与转发动机、§3.5 与 §3.7 的重复叙述），只保留独有判据与讲义原页。
> 先读第 3 讲建立数据通路 / 控制的语境，再读第 4 讲抠判定条件与硬件，顺序不要颠倒；两讲的**一处口径差异**（停顿时清零 `EX/MEM` 还是 `ID/EX`）已在 `04_…` 的待确认清单里列出。
>
> 第 5 讲与第 2 讲接得上：第 2 讲 §2.3 已给出流水线的六组分类，第 5 讲 §5.1 用同一组术语复习，§5.2 再把「线性 / 非线性」变成可执行的调度算法；
> 第 5 讲 §5.3 的「同包内不能转发」「load-use 仍停 1 拍」直接复用第 4 讲的判据。若时间紧，可先读第 5 讲的 §2（五步法）
> 与 §4（重点与易混点），再回头补 §3 的硬件细节。
>
> 第 6 讲与第 4、5 讲接得上：§6.1 的异常冲刷就是第 4 讲控制冒险的延伸；第 5 讲的乱序执行 / ROB 正是为了在复杂流水线里维持**精确异常**。
> §6.2 的「C → 可执行文件」是第 1 讲 ISA 与过程调用的落地；§6.3 的 OS 则是后续操作系统课程的入口。
