## 2. 核心概念

- **Index**：在文本中定位某个词项的机制【讲义定义】。
- **Inverted file**：包含指向该词项在文本中**所有出现位置**的指针（pointer）列表（例如页码）【讲义定义】；之所以叫 "inverted"，是因为它是"**由词项列出所有包含它的文档**"，与"由文档到词项"的自然方向相反。
- **词项—文档关联矩阵**：行是词项、列是文档，取 0/1 表示出现与否。查询 "silver AND truck" = 两行按位与，讲义例子：
  $$1010\ \&\ 1011=1010$$
- **倒排表（posting list）**：形如 `<出现次数; 文档号列表>`，例如 `silver <2; 1,3>`；进一步可记到 `<次数; (文档号; 位置)…>`，这样才能**打印并高亮（highlighting）包含查询词的句子**——所以"**为什么要记次数**"的答案是：频率（frequency） + 位置支持短语查询、相关性排序（relevance ranking）与高亮。
- **Term dictionary**（词典）+ **posting list**（倒排表）是索引的两个组成部分。

## 3. 构造流程与工程要点

### 3.1 索引生成器（【讲义】伪代码）

```text
while ( read a document D ) {
    while ( read a term T in D ) {
        if ( Find( Dictionary, T ) == false )  Insert( Dictionary, T );
        Get T's posting list;
        Insert a node to T's posting list;
    }
}
Write the inverted index to disk;
```

讲义列出的模块：**Token Analyzer**（分词）→ **Stop Filter**（去停用词）→ **Vocabulary Scanner** → **Vocabulary Insertor** → **Memory management**。

### 3.2 文本处理

- **Word Stemming（词干化）**：只保留词根，讲义例子：`process / processing / processes / processed → process`；`says / said / saying → say`。
- **Stop Words（停用词）**：几乎所有文档都含的词（`a`、`the`、`it` …）没有索引价值，可在原始文档中**直接删除（deletion）**。

### 3.3 词项存哪里（While accessing a term）

- 方案 1：**搜索树（search tree）**（B 树、B+ 树、Trie…）；方案 2：**散列（hashing）**。
- 【讲义】把两者的优劣留成 *Discussion 3*。预习时可以先想：有序结构支持**前缀 / 范围查询**但查询代价含比较，散列**平均 $O(1)$** 但不支持范围与顺序遍历（traversal）——这正好呼应第 ADS02 讲的 B+ 树与教材的散列章节（代码见 `../Materials/Code/hashquad.c`、`hashsep.c`）。

### 3.4 内存不够时：分块建索引

【讲义】伪代码（pseudocode）的关键改动：

```text
while ( read a document D ) { ...
    if ( out of memory ) { Write BlockIndex[BlockCnt] to disk; BlockCnt++; FreeMemory; }
...
}
for ( i=0; i<BlockCnt; i++ )  Merge( InvertedIndex, BlockIndex[i] );
```

> 讲稿备注：**写盘前先排序**，这样归并效率高。

### 3.5 分布式索引（web 规模）

- **Term-partitioned index**：按词项分区（如 `A~C`、`D~F`、`X~Z` 各一台机器）；
- **Document-partitioned index**：按文档区间分区（如 `1~10000`、`10001~20000`、…）。
- 讲义提醒：web 规模不要在家尝试（*don't try this at home!*）。

### 3.6 动态索引（dynamic index）

新文档不断到来时，维护 **Main index + auxiliary index**；新文档先进入辅助索引（auxiliary index），检索时**主索引与辅助索引的结果合并返回**。要回答两个问题：**何时重建索引（reindexing）**、**如何删除文档**。

### 3.7 压缩（compression）与阈值化

- **压缩**：倒排表存"**文档号增量（gap）**"，讲义指出 *Most gaps can be encoded with far fewer than 20 bits*。
- **阈值化（Thresholding）**：
  - Document 级：只返回按权重（weight）排序（sorting）的前 $x$ 篇；
  - Query 级：把查询词按出现频率**升序**排序，只检索其中一定百分比的词（低频词更有区分度）；
  - 缺点：**不适用于布尔查询**，截断可能漏掉相关文档（relevant document）。

## 4. 检索系统的评价

### 4.1 讲义列的"好不好用"清单

- 索引有多快（**文档数/小时**）；
- 检索有多快（**延迟随索引规模的变化**）；
- 查询语言的表达能力与复杂查询的速度；
- 用户满意度 → 分两层评价：数据检索（响应时间、索引空间）与信息检索（**答案有多相关**）。

### 4.2 Precision / Recall

相关性（relevancy）度量需要三样东西：基准文档集、基准查询集、逐"查询—文档"对的**二元相关判定（binary relevance judgment）**。记 $RR$ = 检索到的相关文档数、$IR$ = 检索到的无关文档数、$RN$ = 未检索到的相关文档数：

$$
P=\frac{RR}{RR+IR},\qquad R=\frac{RR}{RR+RN} \tag{1}
$$

讲义用"精度（precision）—召回率（recall）"曲线说明两端极端的坏处：只求精确会**漏掉大量有用文档**，只求召回会**夹带大量垃圾**。另外还有一个开放讨论：*How to improve the relevancy of search results?*（*Discussion 4*）。

## 5. 听课重点与易混点

1. **倒排索引（inverted index）解决的是"contains 什么"，不是"哪个更相关"**——相关性排序是另一套机制（权重、阈值化）。
2. **为什么要保存位置信息**：短语查询（phrase query）与高亮都要用到，光有文档号不够。
3. **停用词删除发生在索引阶段**，但会牺牲对短语中停用词的精确匹配（讲义只讲了删除的好处）。
4. **阈值化的两种口径**（文档级 / 查询级）不要混；两者都可能漏检。
5. **词干化是"近似"**：`process` 与 `processed` 合并后，检索精度会略降。
