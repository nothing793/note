## 2. 核心概念

- **Index**：在文本中定位某个词项的机制【讲义定义】。
- **Inverted file**：包含指向该词项在文本中**所有出现位置**的指针（pointer）列表（例如页码）【讲义定义】；之所以叫 "inverted"，是因为它是"**由词项列出所有包含它的文档**"，与"由文档到词项"的自然方向相反。
- **词项—文档关联矩阵**：行是词项、列是文档，取 0/1 表示出现与否。查询 "silver AND truck" = 两行按位与，讲义例子：
  $$1010\ \&\ 1011=1010$$
- **倒排表（posting list）**：形如 `<出现次数; 文档号列表>`，例如 `silver <2; 1,3>`；进一步可记到 `<次数; (文档号; 位置)…>`，这样才能**打印并高亮（highlighting）包含查询词的句子**——所以"**为什么要记次数**"的答案是：频率（frequency） + 位置支持短语查询、相关性排序（relevance ranking）与高亮。
  > 研习室（检索阶段的核心"算法"）：两条**严格递增**的 docID 表用**双指针**求交——相等就输出该 docID 并同时推进；不等就推进**较小**的那个（它的当前位置已经落后，A 中更大的值以后不可能再匹配它）。
  > 循环不变量：已越过的前缀中的共同元素都已输出，尚未判定的答案只可能在 `A[i:]` 与 `B[j:]` 中；每轮至少推进一个指针且从不回退，因此至多 $a+b$ 次推进 $\Rightarrow T(a,b)=O(a+b)$，正确性与复杂度一起得证。
  > `OR` 是"归并去重"，`NOT` 必须相对于明确定义的**文档全集**——否则"补集"没有意义。
- **Term dictionary**（词典）+ **posting list**（倒排表）是索引的两个组成部分。
- **最简 posting 就是文档号（docID）**：同一个词在同一篇文档里出现多次时，**布尔索引只保留一次 docID**（这才是倒排表的长度）。要区分"包含该词的**文档数** $df$（document frequency）"与"**总词频**"：$df$ 数的是不同文档数，总词频把同文档内的重复出现也算进去（研习室）；存 docID 表还是词频 / 位置表，决定了能回答哪类查询。
- **检索阶段的成本口径**：两条已排序 postings 长度分别为 $a,b$ 时，求交 $O(a+b)$、额外输出空间 $O(\min(a,b))$——这是**检索**的成本，不含建索引与读取全部文档（研习室）。

## 3. 构造流程与工程要点

### 3.1 索引生成器（【讲义】伪代码）

```text
while ( read a document D ) {
    while ( read a term T in D ) {
        if ( Find( Dictionary, T ) == false )  Insert( Dictionary, T );
        Get T's posting list;
        Insert a node to T's posting list;
    }
}
Write the inverted index to disk;
```

模块：**Token Analyzer**（分词）→ **Stop Filter**（去停用词）→ **Vocabulary Scanner** → **Vocabulary Insertor** → **Memory management**。

### 3.2 文本处理

- **Word Stemming（词干化）**：只保留词根，讲义例子：`process / processing / processes / processed → process`；`says / said / saying → say`。
- **Stop Words（停用词）**：几乎所有文档都含的词（`a`、`the`、`it` …）没有索引价值，可在原始文档中**直接删除（deletion）**。
- **索引时与查询时必须用兼容的规范化规则**（分词、大小写、停用词、词干化）：两边形态不一致必然漏检。词干化有助于召回但可能合并本应区分的词，去停用词会破坏某些短语的精确匹配（讲义只讲了删除的好处）。
- **中文需要显式的分词策略**（不能沿用英文的空格切分）：本讲讲义的所有例子都是英文，中文检索必须另配分词器，且分词规则一变，词典与 postings 都要重建（研习室）。

### 3.3 词项存哪里（While accessing a term）

- 方案 1：**搜索树（search tree）**（B 树、B+ 树、Trie…）；方案 2：**散列（hashing）**。
- 【讲义】把两者的优劣留成 *Discussion 3*：*What are the pros and cons of using hashing, comparing to using search trees?*

**Discussion 3 参考解答（散列 vs 搜索树）**——讨论题没有标准答案；下表按【讲义】给出的两个方案与教材（Weiss 的树 / 散列章节）的口径整理，结论是"按**查询类型**取舍"，而不是比谁的平均查找更快：

| 比较维度 | 搜索树（search tree：B 树 / B+ 树 / 前缀树（trie），课件写作 *Tries*） | 散列（hashing） |
|---|---|---|
| 精确查找词项 | $O(\log N)$ 次键比较（B+ 树为 $O(\log_B N)$ 次结点访问） | 平均 $O(1)$，最坏 $O(N)$（全部撞进一个桶） |
| 前缀 / 通配符（wildcard）查询 | 支持：trie 按字符逐层下走，$O(\text{前缀长})$；B+ 树叶子有序，可定位区间 | **不支持**（散列函数（hash function）把顺序打乱了） |
| 范围查询 / 按字典序（lexicographic order）遍历 | 支持（B+ 树叶子链可顺序访问） | 不支持，要另存一份有序副本 |
| 顺序输出、词典压缩 | 天然有序，可直接按序写盘 | 无序，须全量导出后排序 |
| 插入新词项（本讲的词典是动态的，见 §3.6） | 摊还 $O(\log N)$，结点分裂 / 再平衡实现复杂 | 摊还 $O(1)$；负载因子（load factor）超限后倍增 + 再散列（rehashing），那一步是 $O(N)$ |
| 空间与常数因子 | 每个键都存字符串本身，trie 在稀疏词典下更费空间 | 只存键与桶指针，常数小 |
| 实现复杂度 | 高（分裂、平衡、顺序维护） | 低（散列函数 + 冲突（collision）处理：分离链接（separate chaining）或开放定址（open addressing）） |

**结论**：

- 词典只做**精确匹配** → 散列就够，这正是课件方案 2 的写法（代码见 `../Materials/Code/hashquad.c`、`hashsep.c`）；
- 还要支持**前缀补全 / 通配符查询 / 按字典序输出词典 / 范围查询** → 搜索树或 trie（B+ 树在倒排索引里的用法见 [`03_ADS02` §3.2 结构要点](03_ADS02_红黑树与B+树.md#32-结构要点讲义)）；
- 两者可以并存：工程上常见"散列做主词典 + trie / 有序副本做前缀与纠错"，只比查找速度会漏掉**查询能力**这一半；
- 注意本讲的词典是**动态**的：散列要处理再散列、B+ 树要处理结点分裂，两者每次操作的摊还代价都是常数，但散列的常数更小。

### 3.4 内存不够时：分块建索引

【讲义】伪代码（pseudocode）的关键改动：

```text
while ( read a document D ) { ...
    if ( out of memory ) { Write BlockIndex[BlockCnt] to disk; BlockCnt++; FreeMemory; }
...
}
for ( i=0; i<BlockCnt; i++ )  Merge( InvertedIndex, BlockIndex[i] );
```

> 讲稿备注：**写盘前先排序**，这样归并效率高。

### 3.5 分布式索引（web 规模）

- **Term-partitioned index**：按词项分区（如 `A~C`、`D~F`、`X~Z` 各一台机器）；
- **Document-partitioned index**：按文档区间分区（如 `1~10000`、`10001~20000`、…）。
- 讲义提醒：web 规模不要在家尝试（*don't try this at home!*）。

### 3.6 动态索引（dynamic index）

新文档不断到来时，维护 **Main index + auxiliary index**；新文档先进入辅助索引（auxiliary index），检索时**主索引与辅助索引的结果合并返回**。要回答两个问题：**何时重建索引（reindexing）**、**如何删除文档**。

### 3.7 压缩（compression）与阈值化

- **压缩**：倒排表存"**文档号增量（gap）**"，讲义指出 *Most gaps can be encoded with far fewer than 20 bits*。
- **阈值化（Thresholding）**：
  - Document 级：只返回按权重（weight）排序（sorting）的前 $x$ 篇；
  - Query 级：把查询词按出现频率**升序**排序，只检索其中一定百分比的词（低频词更有区分度）；
  - 缺点：**不适用于布尔查询**，截断可能漏掉相关文档（relevant document）。
  > 研习室把这两件事分得很清：
  > - **精确优化**：AND 查询先处理**文档频率小**的表可以缩小中间结果集，**结果不变**——所以"先短后长"不是截断；
  > - **语义改变**：只检索查询词的一部分、或截断 postings，会改变布尔语义（课件 p.14 自己就提醒这类阈值优化**可能漏掉答案**）；
  > - 压缩方面：对递增 docID 存**相邻差值（gap）**之外还有 variable-byte、位打包（bit packing）等编码，它们在压缩率与解码速度之间权衡；**跳跃指针（skip pointer）/ 块级边界**能减少长表的扫描量。

## 4. 检索系统的评价

### 4.1 讲义列的"好不好用"清单

- 索引有多快（**文档数/小时**）；
- 检索有多快（**延迟随索引规模的变化**）；
- 查询语言的表达能力与复杂查询的速度；
- 用户满意度 → 分两层评价：数据检索-**data treival**（响应时间、索引空间）与信息检索 **information treival**（**答案有多相关**）。

### 4.2 Precision / Recall

相关性（relevancy）度量需要三样东西：基准文档集、基准查询集、逐"查询—文档"对的**二元相关判定（binary relevance judgment）**。记 $RR$ = 检索到的相关文档数、$IR$ = 检索到的无关文档数、$RN$ = 未检索到的相关文档数：

$$
P=\frac{RR}{RR+IR},\qquad R=\frac{RR}{RR+RN} \tag{1}
$$

讲义用"精度（precision）—召回率（recall）"曲线说明两端极端的坏处：只求精确会**漏掉大量有用文档**，只求召回会**夹带大量垃圾**。另外还有一个开放讨论：*How to improve the relevancy of search results?*（*Discussion 4*）。

**Discussion 4 参考解答（如何提高检索结果的相关性）**——课件只留讨论题，没有标准答案；下面按课件 §3.7（权重与阈值化）的线索、以及研习室该章列出的 Stanford《Introduction to Information Retrieval》这一补充材料整理：

- **给词项加权再排序**：用词频（term frequency）与逆文档频率（idf）一类统计量给"查询—文档"打分（tf-idf、BM25），把最强的文档排在前面，而不是只返回布尔匹配的全部文档；这正是讲义 §3.7 里"按权重排序（ranked by weight）"的一般化。
- **用位置与邻近（proximity）关系**：位置 postings 能判断两词是否相邻，短语与邻近加权比"同篇出现"更准（见 §2 核心概念"为什么要记次数"）。
- **用超链接与文档结构**：把指向文档的链接当作投票（PageRank / HITS 一类链接分析（link analysis）），以及标题、锚文本（anchor text）、字段权重——这正呼应讲义开篇的 *How did Google do?*。
- **改查询侧**：查询扩展（query expansion）、同义词（synonym）、拼写纠错（spelling correction）、字段限定；停用词与词干化（stemming）的取舍也会改变相关性（§3.2）。
- **用用户反馈**：点击等行为信号、个性化（personalization）、排序学习（learning to rank）。
- **必须有评价闭环**：任何改动都要回到 §4.2 的 $P/R$（排名字典可用 MAP / NDCG 之类的指标）在**基准文档集 + 基准查询集 + 二元相关判定**上验证；
- **分清"改语义"与"改排序"**：§3.7 的阈值化 / 截断是**丢掉**可能相关的文档，属于改变结果集，不是提高相关性；把"更快"（时延、索引规模）当成"更相关"，也是本讲明确要避免的混淆。

> 研习室补充的评测约定：**检索结果为空集时 precision 的分母为 0**，必须事先声明怎么处理（记 0、记 1 还是跳过该查询）；
> 另外**时延、吞吐、索引大小只是系统效率**，不能替代相关性评价——P / R 要配上基准文档集、基准查询集与逐对二元相关判定才谈得上。

## 5. 听课重点与易混点

1. **倒排索引（inverted index）解决的是"contains 什么"，不是"哪个更相关"**——相关性排序是另一套机制（权重、阈值化）。
2. **为什么要保存位置信息**：短语查询（phrase query）与高亮都要用到，光有文档号不够。
3. **停用词删除发生在索引阶段**，但会牺牲对短语中停用词的精确匹配（讲义只讲了删除的好处）。
4. **阈值化的两种口径**（文档级 / 查询级）不要混；两者都可能漏检。
5. **词干化是"近似"**：`process` 与 `processed` 合并后，检索精度会略降。
