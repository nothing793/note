## 1. 一页速览

| 概念 | 讲义给的说明 |
|---|---|
| 两种并行（parallelism） | **机器并行**（处理器并行、流水线、VLIW）与**并行算法** |
| 两种描述模型 | **PRAM**（Parallel Random Access Machine）与 **Work-Depth（WD）** |
| 衡量指标 | **工作量（work） $W(n)$**（总操作数）与**时间 $T(n)$**；处理器（processor）数 $P(n)=W(n)/T(n)$ |

| 三个经典算法 | 求和（$W=O(n),T=O(\log n)$）、前缀和（$W=O(n),T=O(\log n)$）、归并（划分范式，$W=O(n),T=O(\log n)$） |
| 最大值问题 | 求和算法把 "+"换成 "max"；全对比较 $W=O(n^2),T=O(1)$；还有双对数范式与随机采样 |

## 2. 两个模型

### 2.1 PRAM

- 若干处理器 + **共享内存（shared memory）**，一次访问（读/写/计算）算**单位时间**；
- 并行循环写法：`for Pi, 1 ≤ i ≤ n pardo`，例如 `A(i) := B(i)`。
- **访问冲突的三种约定**【讲义】：
  1. **EREW**（Exclusive-Read Exclusive-Write）：同一时刻不能有多个处理器读/写同一单元；
  2. **CREW**：允许并发（concurrent）读，写必须互斥（exclusive）；
  3. **CRCW**：读写都可并发，写冲突（write conflict）的解决规则又分三种——**arbitrary**（任选一个）、**priority**（编号最小的处理器胜出）、**common**（所有处理器写同一个值时才允许）。
- 【讲义】指出的缺点：PRAM 的表述**不揭示**算法在"处理器数不同"的机器上如何运行，也**不必要地**要求指明每条指令分配到哪个处理器。

### 2.2 Work-Depth（WD）

- 只描述"每一时刻有多少操作可以做"（不指定处理器编号），于是能同时给出 $W(n)$ 与 $T(n)$。
- **【WD 充足性定理】**：WD 表述的算法可以由**任意** $P(n)$ 个处理器在
  $$O\!\left(\frac{W(n)}{P(n)}+T(n)\right) \tag{1}$$
  时间内实现，写冲突约定与 WD 表述相同。
- 性能的四种等价说法【讲义】：有 $W(n)$ 个操作、$T(n)$ 时间 ⇒ 用 $P(n)=W(n)/T(n)$ 个处理器、$T(n)$ 时间；用任意 $p\le W(n)/T(n)$ 个处理器需 $W(n)/p$ 时间；用任意 $p$ 个处理器需 $W(n)/p+T(n)$ 时间——它们**渐近等价**。

## 3. 三个基本算法

### 3.1 求和（Summation）

输入 $A(1..n)$，输出总和。用平衡二叉树（balanced binary tree）自底向上（bottom-up）两两相加：

$$B(h,i)=B(h-1,2i-1)+B(h-1,2i) \tag{2}$$

```text
for Pi, 1 ≤ i ≤ n pardo   B(0,i) := A(i)
for h = 1 to log n
    for Pi, 1 ≤ i ≤ n/2^h pardo
        B(h,i) := B(h-1,2i-1) + B(h-1,2i)
for i = 1 pardo   output B(log n, 1)
```

$$T(n)=\log n+2,\qquad W(n)=2n=O(n) \tag{3}$$

### 3.2 前缀和（Prefix-Sums）

输出 $C(k)=\sum_{i\le k}A(i)$。技术同样是**平衡二叉树**：先自底向上算出各子树（subtree）和 $B(h,i)$，再**自顶向下（top-down）**传播：

- $i=1$：$C(h,1):=B(h,1)$；
- $i$ 为**偶**：$C(h,i):=C(h+1,i/2)$（直接继承父节点的前缀和）；
- $i$ 为**奇**且 $i\ne1$：$C(h,i):=C(h+1,(i-1)/2)+B(h,i)$（继承父节点前缀和，再加上左兄弟的子树和）。

最终输出 $C(0,i)$。结论：$T(n)=O(\log n)$，$W(n)=O(n)$（每个节点上的操作只被计一次）。

### 3.3 归并（Merging）——划分（partition）范式（Partitioning）

- **问题**：把两个已排序（sorting）数组（array） $A(1..n)$、$B(1..m)$ 合并为 $C$。为简化，假设元素互不相同、$n=m$、$\log n$ 与 $n/\log n$ 都是整数。
- **划分范式**【讲义】：把输入切成 $p$ 个独立的小任务，使最大任务规模约为 $n/p$；再并发地用（可能串行的）算法处理每个小任务。
- **排名（ranking）定义**【讲义】：

$$RANK(j,A)=i \iff A(i)<B(j)<A(i+1);\quad RANK(j,A)=0 \iff B(j)<A(1);\quad RANK(j,A)=n \iff B(j)>A(n)$$

- **Claim**：只要算出了所有 $RANK$，归并只需 $O(1)$ 时间、$O(n+m)$ 工作量：

```text
for Pi, 1 ≤ i ≤ n pardo   C( i + RANK(i,B) ) := A(i)
for Pi, 1 ≤ i ≤ n pardo   C( i + RANK(i,A) ) := B(i)
```

- 三种算 $RANK$ 的方式【讲义】：
  1. **二分查找（binary search）**：每个位置并发做一次 `BS`，$W=O(n\log n)$ 时间 $T=O(\log n)$；
  2. **串行（serial）排名**：$W=O(n)$ 但 $T=O(n)$；
  3. **并行排名（Parallel Ranking）**：分两阶段——
     - Stage 1（划分）：取 $A\_Select(i)=A(1+(i-1)\log n)$、$B\_Select(i)$ 各约 $p=n/\log n$ 个"代表元（representative）"，对它们算 $RANK$（总工作量 $O(n)$）；
     - Stage 2（实际排名）：每个代表元把区间切成至多 $2p$ 个规模 $O(\log n)$ 的小问题，并发（串行算法）求解。
     结论：$T(n)=O(\log n)$、$W(n)=O(n)$。

## 4. 最大值问题（Maximum Finding）

- **把求和算法里的 "+" 换成 "max"** 即可，$T=O(\log n),W=O(n)$。
- **全对比较（All-pairs）**：

```text
for i and j, 1 ≤ i, j ≤ n pardo
    if ( (A(i) < A(j)) || ((A(i) = A(j)) && (i < j)) )  B(i) = 1;
    else  B(j) = 1;
```

  $W=O(n^2)$、$T=O(1)$；但这里有大量**写冲突**，讲义留了 *Discussion 21: How to resolve access conflicts?*（答案要用 CRCW 的写规则或改用其他判定方式）。

- **双对数范式**【讲义】：设 $h=\log\log n$ 为整数（即 $n=2^{2^h}$），按 $h$ 分块并行，可以进一步降低时间（讲义该页的块划分与结论式为图片，**具体界请以课堂讲解为准**）。
- **随机采样（Random Sampling）**【讲义】：以 $n^{7/8}$、$n^{3/4}$ 等规模的随机样本块维护一个当前最大值候选 $M$，循环"把大于 $M$ 的元素重新随机投递到新的块里，再算新的 $M$"，直到没有元素大于 $M$。
  > **【定理】** 该算法能找到最大值，且**以极高概率（with high probability）**在 $O(1)$ 时间、$O(n)$ 工作量内完成；失败概率（failure probability）为 $O(1/n^c)$。

## 5. 听课重点与易混点

1. **两种模型的分工**：PRAM 说"多少处理器做多少事"，WD 说"每一步有多少操作"；WD 的关键优势是**不绑定处理器数**。
2. **并行复杂度必须同时报 $W(n)$ 与 $T(n)$**：只说时间会掩盖"用了多少操作"。
3. **求和的二叉树（binary tree）结构与前缀和、归并的划分是同一套"平衡二叉树技术"**。
4. **CRCW 的三种写规则要能对号入座**（arbitrary / priority / common）。
5. **排名是归并的核心**：$RANK$ 一算出来，写回 $C$ 就只剩 $O(1)$ 时间。
