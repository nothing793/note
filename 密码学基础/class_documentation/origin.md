## 二、什么是密码学：从词源到核心应用

**课堂互动**：问大家“说起密码学，脑海里想的是什么？”有同学回答“各种信息的保护手段”，教师肯定了这一回答。教师补充：更多人会联想到口令/登录密码（passcode），他夫人向别人解释他的方向时，文科生常问“你丈夫是研究加密密码/登录密码的吗？”——其实密码学跟口令不太相关，但它确实是一种**保护手段**，关键是要考虑它到底保护什么。

**词源**：cryptography 由两个希腊字母组成，语义学追溯其本义是“隐藏”+“书写”，本质上研究的是**隐写术**——最原始的应用环境是把写作的内容隐藏起来。

**最 fundamental 的应用：信息传输**。Alice 和 Bob 想通信，但通信信道可能被劫持（如两位军事主官意见交流，信使传递路径已被间谍渗透），所有传递的信息都公开给攻击者。密码学最 fundamental 的 application 就是：**在不安全信道中，如何保证 Alice 和 Bob 传输信息的安全**。

**核心观察**：Alice 和 Bob 必须有点别人没有的东西。如果 Alice 有的、Bob 有的，攻击者也有，就无法把信息隐藏起来。由此推论：通信前 Alice 和 Bob 必须各自拥有一个 secret key（就像登录网页时用的密钥，服务器与用户需提前共享密钥）。密钥具体怎么产生，这里先“挖个坑”，课程中后期再填。现在假设有一个非常 nice 的“神仙”/oracle，在通信前提前把 key 同时分发给 Alice 和 Bob（暂且不管这条线怎么运行）。

**基本流程**：有了密钥后，发送方用密钥和 message 做编码（encryption），把编码后的密文发给 Bob；Bob 收到后用同样的 key 解码（decryption）得到 message。攻击者/窃听者没有 key，因此有了保证 message 安全的机会。

## 三、密码系统的六个基本元素

一个成熟的密码系统包含**三个空间 + 三个算法**：

**三个空间**：
- 明文空间 M（message 从哪来）
- 密文空间 C（加密后到哪去）
- 密钥空间 K（k 属于哪里）

**三个算法**：
1. **密钥生成算法（Key Generation）**：核心作用是 oracle 如何产生密钥。它 take 一个东西（第三堂课再解释是什么），输出一个 key。
2. **加密算法（Encryption）**：输入 SK 和 message，输出密文。
3. **解密算法（Decryption）**：输入 SK 和密文，输出明文。

（第一次课写得严格一点，以后不再写这么严格。算法暂时就理解成脑海里那个“算法”东西，不按图灵机解释。）

## 四、三个算法的属性分析

**问题一：算法是否需要保密？**

- 军方加密算法等特殊情况需要保密，但正常情况下我们希望算法**不保密**。原因：即使算法被知道，系统仍然是安全的，那才是真正的安全；如果安全性依赖于算法保密，一旦算法泄露（如通过人文攻击骗出来）就不安全了。
- 这就是 **Kerckhoffs 原则**（奥古斯特·柯克霍夫原则）：算法完全公开，即使算法完全公开的情况下依然安全，才是好的安全算法。
- 第二个论证：算法公开后，才会让世界上聪明人去攻击它。比如算法征集（如 AES 等），都是被全球顶尖科学家攻击了很多年依然安全，才被公开应用。整门课都 follow 这个传统：希望这些东西完全公开。

**问题二：算法是随机算法还是确定性算法？**

- **密钥生成算法**：应该是 **randomized**。如果是确定性算法，攻击者就可以运行确定性算法直接得到 SK，进而攻破 message。所以 key generation 必须随机。
- **解密算法**：**确定性**（高概率）。在 beginner 接触的范围内应该全是确定的，只有极少数很 weird 的算法可能考虑非确定的东西。因为希望发过去的东西能解密，而不是发过去一个 garbage 解密不了——功能性需要有所保障。
- **加密算法**：**既可以是确定性也可以是随机，现阶段绝大多数用的是随机算法**。确定性算法的问题会在第五、六堂课解释（当尝试理解“什么叫安全”时，会看到确定性算法的缺陷）。一些古典加密算法是确定性的，容易形成固有认知，所以现在要强调：加密算法应当随机。至于“加密算法是随机的话怎么对敌手公开”——公开的是算法电路本身，告诉敌手电路长什么样、key 和 message 怎么接进去，但不告诉那一步的具体值。

## 五、密码系统“好”的属性与正确性的形式化

一个密码系统想要：正确性、安全性、高效性等——“既要又还要”。但关键是要把这些属性**用数学语言 formal 出来**。正确性争议不大，但“安全性”在 A 脑子里和 B 脑子里可能完全不一样。必须用确定性的数学语言把安全性定义下来，使讨论不是“公说公有理婆说婆有理”。

**正确性**：希望解密的人解出来的东西，真的是加密的人发出去的信息，即解密后的信息 = 加密前的信息。

**形式化表达**：用概率论方法。解密后的东西形成一个分布，加密后的东西形成一个分布。因为密钥空间里可能有很多 SK，对某个 SK 解密很好，但可能有那么一个非常坏的 SK 解不出来——需要处理这种“不喜欢的”情况。希望对于每个 SK、每个 message，解密结果等于原文；通过这样的写法把坏的情况直接“忘掉”。

- 这是“完美正确性”：对于每个 key、每个 message，解出来都是加密前的东西。
- 但有时可以做一些 relaxation：比如 key 空间很大但坏 key 只有一两个、处理得比较少，某些情况下能容忍。
- 于是用概率方法理解：变成可调的东西，概率分布是 over SK。加密是随机算法，会诱导出 K 上的分布，进而诱导出关于密文的分布。完美正确性时，这个分布就等于 m 本身（分布退化为定值）。用概率形式可以表达“大于 99%”这类可调的、更 flexible 的正确性，不再只能表达完美正确性。这个关键词以后不再解释，本课重点在后面什么是 security。

## 六、什么是“安全”：从传统安全到可证明安全

**课堂互动**：已经有了三个算法和知识之后，如果让你定义一个 formal 的、跟数学沾边的“安全”，一个密码系统是安全的应该长什么样？有同学说“复杂度低”。

**古代/传统如何定义安全**：古代设计密码算法的逻辑是“我比你聪明你就得信我的”——科学家提出算法，大家尊重他都在用，直到某天一个“宅男”直接把它攻破、给出 attack，算法就完全不能用了，然后需要另一个更聪明的科学家提出新算法，日复一日。在 Shannon 理论可证安全提出之前，这是整个密码学的研究路径。

- **Traditional security**：算法如果没有人攻破就是安全的。这是从反馈/结果的角度说的——只需要“你干不死我”，不需要任何证明。
- 这个逻辑很不爽：你不知道“明天”或“干脆什么时候”会来。尤其有了计算机之后，攻破变得简单；有了 AI 之后更简单，“最近的进展把我们都催得没饭吃了”。

**凯撒密码的例子**：
- 最简单的凯撒密码非常脆弱：a 变 b、b 变 c……把密钥给定死了，而密钥生成应是随机算法，所以设计完全不合理。
- 改成“移位密码”（置换密码）：k 每次从 0～25 之间选取（如 k=3 时 a→d，k=4 时 a→e 等），把 k 变成 1～25 上的均匀分布。
- **攻击一：暴力攻击**。密钥空间只有 26 个元素，try all possible keys 解密，看哪条像人话（明文应是文化/有意义的内容而不是 garbage），就能定位到正确 key。被干掉的原因是 key space 太小。如果 key space 大到正常电脑暴力攻击搞不定，就抵抗了暴力攻击——**但抵抗暴力攻击不代表安全**，只是抵抗了暴力攻击。
- **攻击二：频率分析**。这个算法是确定性的：每次加密 a 都映射到同一个密文字母，如果语言环境中 a 出现概率高于 b，密文中对应字母的概率也会更高，这就是可利用的信息。英文中 e 出现最多，可用频率信息做探索。这从小小角度说明了为什么将来更喜欢 randomized 的表达。
- 课堂还展示了一段用置换做的密文，说明用纸笔在 10 分钟内破译虽然看起来很扯、很费劲，但方法就是：第一步数频率（小学生能干，纸上 3～5 分钟）；第二步做图、猜测（出现最高的 r 先猜成 e，第二高的猜 t 等），高概率的几个先拉开差距；然后语义分析、代入、迭代，一层层往下叠，最后完全解出来。

**传统安全的缺陷**：这种“没人攻破就安全”的 philosophy 不好，因为它依赖于“别人有没有攻破”这个反馈属性。构建无条件安全的东西非常难（要 100% 安全、无条件安全很难），所以现实中要找**世界公认的背书**——找一个基石。如果信任基础换成全人类的共识（如“两点之间线段最短”），信心会更高。可以从数学上找一些难的数学问题、困难的计算机问题，比如假设 P≠NP，信心会足一点（虽然有些极端科学家声称做出来了，但大家普遍认为 P≠NP）。以它为基石来构建好的密码系统。

## 七、可证明安全（Provable Security）的三个基本元素

这是本课程的核心话题：**学会可证明安全**。前面传统安全纯粹靠个人声誉背书；可证明安全则要说“我这套密码系统是可证明安全的”。

三个基本元素：
1. **Assumption（基石/前提）**：一个全人类公信的东西，可以想象成 P≠NP 这类假设。
2. **Definition（安全刻画）**：你想实现什么样的安全——把“message 保密”等目标刻画成数学。
3. **Reduction（归约）**：连接 Definition 和 Assumption 的桥梁。意思是：我的安全性与你（假设）强绑定。如果我提了一个很牛的 assumption/definition 说“我这东西是安全的”，你不认怎么办？我就给出一个 reduction：**如果你能攻破我的系统，我就用你的攻击去解决 P≠NP 这个共识问题**。因为全人类信这个基石，所以全人类必须信我的系统——保持因果关系。如果你能干碎我的 definition，我就打碎全人类的共识。

如何理解 definition、如何构建 proper reduction、如何选 assumption，都是可以展开很多的话题，这门课就是一点点从这个角度拆解开：如何选取合适的方式、如何选取合适的 assumption、如何做 reduction。

**重要提醒**：assumption 只是全人类的共识，不代表它一定对。它比个人强大（可能经过上百年锤炼还没被干掉），但历史上也出过事情——从底层把上面碎掉，地基碎了房子就没用了。所以 assumption 一定要选好；同时要兼顾“好用”：有些假设信心很足但很难用、不知道怎么用它构建东西，所以要在“好用可靠”之间选取，一点点往上走，找到合适的东西、合适的内审（definition）去做，中间还要兼顾效率等——这是 provable security 设计的核心概念。

## 八、密码学的现代应用小例子（拓展视野）

现代密码学的应用远不止加密通信。第一堂课讲几个不太 serious、好懂但不那么严格的小例子：

### 1. 安全多方计算（Secure Multi-Party Computation, MPC）

场景：A 有信息 x，B 有信息 y，两人想共同计算函数 f(x,y)，A 想得到结果、B 也想得到结果，但 A 不希望 B 知道 x，B 也不希望 A 知道 y。

**类比**：两个女生想比体重但不想泄露自己的体重——去公园找个跷跷板（物理方法）。问题是在网络世界（cyberspace）里怎么建立这个“跷跷板”。

**交友软件例子**：A 看到 B 的图片选择喜欢（1）/不喜欢（0），B 同样。希望最后只得出“A 和 B 是否同时喜欢对方”：都为 1 则匹配成功继续发展；有一方不喜欢就及时止损。同时希望三种情况无法区分：如果 A 选 0，结果必然是 0，B 知道 A 不喜欢他；但 B 不想让 A 知道自己是不是“舔狗”（B 选 1 而 A 选 0 时，A 不应知道 B 喜欢他）。所以要求：输出 1 的情况与另外两种输出 0 的情况无法区分。

**扑克牌协议**（用 3 张红桃、2 张黑桃）：中间放一张共用红桃，A 和 B 各有一张红桃一张黑桃。选 1 则把红桃放得离中间红桃更近，选 0 则放黑桃（或反过来放）。四种情况中，需要做到：两方都选 1 的那条线能与另外三种情况区分开（通过排列区分），同时另外三种情况彼此无法区分。通过一个 shift（A 在背后做置换/切牌，B 猜是否交换）来实现：A 把牌拿到背后，以 1/2 概率交换、1/2 概率不动，摊出来后问 B“我有没有交换”。如果两球/牌真的完全一样，B 猜对的概率只有 1/2；如果 B 每次都能猜对，A 的信心就越来越足（100 次都对，概率极低），从而确信 B 真的能区分。这里有个问题：**必须 A 和 B 都是 honest 的**——如果一方内心选 0 却故意选 1，就想看 B 是不是“舔狗”，信息就泄露了。所以要保证参与者不玩 malicious，或者构造即使 malicious 也能搞定的协议，这需要高级技术。这个例子也说明：**definition 本身非常重要**，它告诉你 A 和 B 的表现方式；表现方式不同对应不同的 definition，不同 definition 下安全性完全不一样。

### 2. 零知识证明（Zero-Knowledge Proof）

**GPA 例子**：去面试，公司要求 GPA 超过 90 分，但你不想让对方知道你真正的 GPA、不把成绩单给他。如何在不泄露成绩单的情况下让对方确认你的成绩超过 90？对方得不到任何信息，但能被说服——这是零知识证明。区块链很火带火了 ZKP，这是一个非常大的方向。隐私保护计算/隐私计算中，MPC 是基石；ZKP 在区块链/稳定币方向有大量落地应用，这两个方向很容易形成落地应用。

**色盲与两个球的例子**：A 是色盲，有两个外形一模一样、只有颜色（红/绿）不同的球，A 无法区分颜色。B 的任务是让 A 确信“这俩球不一样”，但不告诉 A 哪个是红、哪个是绿。方法：A 把球拿到手背后，以 1/2 概率交换、1/2 概率不动，摊出来后问 B“我有没有交换”。如果两球真的一样，B 只能纯猜，猜对概率 1/2；如果 B 每次都能猜对（n 次，如 100 次），A 的信心就非常足，确信 B 真的知道一些自己不知道的事情——即两球确实不一样。这就是零知识证明的直观思想。

**零知识证明最神奇的一点**：正常逻辑应先定义什么叫 knowledge，再定义什么叫 zero knowledge；但 knowledge 完全无法定义（你眼中的 knowledge 在别人眼中可能是 garbage，教授也无法证明“这东西就是 knowledge”）。**ZKP 在没有定义什么叫 knowledge 的情况下，定义了什么叫 zero knowledge**。直观理解：问“这堂课有没有学到新内容”——“新内容”无法定义；但如果你在宿舍里对着空气把老师讲的东西全部讲一遍，说明你肯定没学到新知识（学了跟没学一样，没有 additional 的知识）。所以 zero knowledge 的核心：A 没有获得 additional 的信息。做 definition 时，不 care 你“有”什么知识，只 care 你看到我的东西、运行之后有没有得到新的东西；证明“你折腾半天跟没折腾一样”，就是安全的——这是一种很好的思路。

## 九、下堂课预告与结尾

下堂课将从 Alice-Bob 通信出发，尝试做一个密码系统的 definition。按 Kerckhoffs 原则，除密钥外其他东西攻击者全知道，所以安全性仅仅依赖于密钥的安全性。

**一个看似正确但会被反例击碎的定义**：第一个想法是“攻击者折腾半天，对密钥一无所知”——这看起来对，但一个反例就能击碎它。因为**真正要保护的对象是 message**，message 才是“爹”；密钥只是“大表哥”，是保护安全的**必要条件**而非重点。做 definition 时一定要抓住 message。

课程结尾：今天主要给一些 high-level 的 idea，让大家知道密码学到底在玩啥。很多学校的密码学课程不是这么上的，教师想做一点正确的事情，所以 PPT 可能只剩一两页，其余全是板书。希望大家多听、回去思考、多记笔记；有兴趣可读经典教科书（常读常新，教师自己每次读都发现有不懂的地方）。今天就到这。

# 9.21 香农与完美安全
## 一、开场：回顾与本节课目标

老师先回顾上节课内容：密码算法包含**密钥生成、加密、解密**三个算法，并介绍了算法的**随机性/确定性**以及**正确性定义**。随后用一个简单例子展示了“只保证密钥不泄露”这种朴素安全性定义的缺陷。

本节课的目标是实现三件事：
1. 给出一个**正确的加密算法**；
2. 它至少满足一个**好的安全性定义**；
3. 它必须是**高效的**。

老师强调，后面所有构造都从这三方面考量。本节课要做的是先给出好的 definition，看看能不能像“一加一等于二”这种**无条件共识**一样，不依赖任何计算假设。

## 二、第一次尝试：只要求“密钥不泄露”——必要但不充分

老师回顾上节课讲的 **Kerckhoffs 原则**：除了密钥，其他一切（算法、明文统计特性等）都可以泄露。于是第一个候选定义是：

> 密码算法保证**密钥完全不泄露**。

但老师给出**反例**：如果加密是恒等映射（密文=明文），密钥确实没泄露，但明文完全暴露。所以这个定义**必要但不充分**——密钥必须保密，但只保密密钥远远不够。

老师强调：应用中真正要保护的是**信息（明文）**，密钥只是手段。所以这个定义不行。

## 三、第二次尝试：连明文长度/语言属性也不能泄露——太强，不可实现

第二个候选定义是：密文不能泄露关于明文的**任何信息**，包括明文的语言属性（是不是英文）、长度等。

老师指出这**太强**：
- 解密要保证正确性，密文必须“携带”明文，因此很难完全掩盖；
- 更直接的是**长度泄露**：短明文加密出的密文短，长明文加密出的密文长，攻击者只看密文长度就知道明文长短。

所以“什么都不泄露”这个定义**无条件地不成立**，无法实现。

## 四、回到中间：香农的折中——允许攻击者拥有先验知识

老师指出，香农（1949）提出的是介于两者之间的东西：

> **不要求攻击者什么都不知道**；允许攻击者事先知道关于明文的某些信息（先验知识），但要求**看到密文之后，他对明文的认知不比看到之前更多**。

老师用“A 欠 B 100 万”举例说明“什么算 information”本身很难定义，所以香农的思想是：**提前给攻击者一个关于明文的先验知识**（比如明文是 128 比特、是英文/中文等），这些信息“不准备藏了，直接给你”。然后要求：攻击者分析密文忙活半天，对明文的理解**仍然只是这个先验信息**，一比特都没多获得。

老师原话大意：“你在啥都没看到之前只知道这是 128 比特的明文；看到密文之后，还是仅仅知道这是 128 比特的明文。那我就对这个密码算法比较有信心了。”

## 五、把语义翻译成数学：先验分布与后验概率

老师问：这句话怎么数学化？

**先验知识的刻画**：提前确定一个**明文上的概率分布 \( D \)**。例如“只知道是 128 比特”就对应明文空间为 \(\{0,1\}^{128}\) 上的均匀分布。攻击者按这个分布去猜明文，猜对概率就完全由 \( D \) 决定（若 \( D \) 把全部质量放在 \( m_1 \) 上，攻击者百分之百猜中）。

**后验概率的刻画**：用**条件概率** \(\Pr[M=m \mid C=c]\) 表示看到密文 \( c \) 之后对明文 \( m \) 的信念。

**香农安全的语义**：先验概率与后验概率**完全相同（identical）**。

## 六、香农安全的正式定义

（老师先假设加密是**确定性算法**，随机算法情形留作扩展/作业。）

对任意明文分布 \( D \)、任意明文 \( m \in M \)、任意密文 \( c \in C \)（满足 \(\Pr[C=c]>0\)）：

\[
\Pr[M=m \mid C=c] = \Pr[M=m]
\]

其中 \( M \sim D \)，\( C = \mathrm{Enc}(K, M) \)，\( K \sim \mathrm{Gen}() \)。老师特别提醒：**密文分布是通过密钥生成算法导出的，不是随机选取的**。

若算法对**任意分布 \( D \)** 都满足上式，就说它是**香农安全的（Shannon security）**。

老师指出这个定义的**痛点**：要证明它，必须对**所有可能的明文分布**逐一验证，非常麻烦。所以希望找一个**数学上更友好**的等价定义。

## 七、第二个定义：密文分布不可区分（完美安全）

老师给出另一种定义：

> 对任意两个明文 \( m_1, m_2 \)，由它们导出的**密文分布完全相同**：
> \[
> \{\mathrm{Enc}(K, m_1)\} \equiv \{\mathrm{Enc}(K, m_2)\}
> \]

直观：即使攻击者算力无限、存储无限、用量子算法、是外星人，他也无法区分密文来自 \( m_1 \) 还是 \( m_2 \)。老师用“两个完全一样的蛋糕，从中抽变量 X 或 Y，超级强大的对手也无法区分”来比喻。

老师说明两个定义的风格差异：
- **定义一（先验=后验）**：语义上友好，“讲给街边大妈也能听懂”，但数学上要遍历所有分布，证明麻烦；
- **定义二（密文分布相同）**：数学上友好，证明时只需考虑分布，但语义上不那么直观。

老师个人习惯：教材里常把定义二叫**完美安全（perfect secrecy）**，定义一叫**香农安全**；两者本质一致，只是同一事物的两个角度。

## 八、证明两个定义等价

### 8.1 方向一：完美安全 ⇒ 香农安全

从 \(\Pr[M=m \mid C=c] = \dfrac{\Pr[M=m \wedge C=c]}{\Pr[C=c]}\) 出发，把联合概率按全概率公式展开为对密钥的求和：

\[
\Pr[M=m \wedge C=c] = \Pr[M=m]\sum_{k:\,\mathrm{Enc}(k,m)=c}\Pr[K=k]
\]

由完美安全条件，对任意 \( m_1, m_2 \)，\(\sum_{k:\mathrm{Enc}(k,m_1)=c}\Pr[K=k] = \sum_{k:\mathrm{Enc}(k,m_2)=c}\Pr[K=k]\)，即这个和**与 \( m \) 无关**，可提到求和号外，记为常数。于是分子中的 \( m \) 依赖被消掉，得到

\[
\Pr[M=m \mid C=c] = \Pr[M=m]
\]

即香农安全成立。

### 8.2 方向二：香农安全 ⇒ 完美安全

老师用“**甲方**”比喻：既然香农安全对**任意分布**成立，我们就可以**精心挑选一个对自己有利的分布 \( D \)** 来证明目标。具体做法：固定两个明文 \( m_1, m_2 \)，构造只在 \( m_1, m_2 \) 上有质量的分布（老师口述为“二分之一、二分之一，其他全零”），在这个分布下香农安全条件成立，代入条件概率公式，即可推出 \(\Pr[\mathrm{Enc}(K,m_1)=c] = \Pr[\mathrm{Enc}(K,m_2)=c]\)。

课堂上对此有较长讨论，核心是：
- 香农安全的定义是“**对任意分布**成立”，所以证明时可以**任选一个分布**来用（“我是甲方，我想怎么用怎么用”）；
- 需注意 \(\Pr[C=c]=0\) 的退化情形：若分母为零，则分子也为零，等式平凡成立，不影响结论。

老师总结：这个等价性的核心就是一个**条件概率展开 + 全概率公式**的化简，正方向用一次、反方向用一次，两边打通后，以后证明完美安全就可以用数学上更友好的定义二。

## 九、构造满足完美安全的方案：一次一密（One-Time Pad）

方案：密钥、明文、密文均为 \( n \) 比特串，\( K \) 均匀随机；

\[
\mathrm{Enc}(K,M) = K \oplus M,\qquad \mathrm{Dec}(K,C) = K \oplus C
\]

**证明**：固定任意 \( m_1, m_2 \) 和密文 \( c \)，存在唯一密钥 \( k_1 = m_1 \oplus c \) 使 \( \mathrm{Enc}(k_1,m_1)=c \)，同样唯一 \( k_2 = m_2 \oplus c \)。由于 \( K \) 在 \(\{0,1\}^n\) 上均匀，\(\Pr[\mathrm{Enc}(K,m_1)=c] = 1/2^n = \Pr[\mathrm{Enc}(K,m_2)=c]\)，满足完美安全。

## 十、课堂追问：为什么移位密码被攻破，而一次一密安全？

老师提出这个很好的问题：两者形式上都是“加一个密钥”，为什么一个被干碎、一个完美安全？

答案：**移位密码的密钥空间太小**（如 26 种），且密钥**重复使用**；一次一密要求密钥**均匀随机、与消息等长、且每次加密只能用一次**。移位密码没有 follow “one-time” 的要求，本质上密钥分布和密钥空间都不满足完美安全的条件。

## 十一、完美安全的代价与香农定理

老师回到“初心”：我们要的是**不基于任何计算假设的无条件安全**——攻击者算力无限、存储无限、用量子算法都行，只要求他承认“一加一等于二”。这样的对手下，唯一能骗过他的就是**两个完全相同的分布**。这就是完美安全的本质。

但代价是：
- **密钥必须与明文等长**，且**只能用一次**；
- 实现高效性困难。老师提到历史上 60 年代白宫与莫斯科之间的“热线”确实用过类似一次一密的方法，属于极特殊场景。

随后老师证明**香农定理的必要性方向**：若方案完美安全，则**密钥空间不小于明文空间**（\(|K| \geq |M|\)）。证明思路（转写较乱，按标准证明还原）：
- 反设 \(|K| < |M|\)，则对某个密文 \( c \) 和某明文 \( m^* \)，不存在密钥使 \( \mathrm{Enc}(k,m^*)=c \)，即 \(\Pr[C=c \mid M=m^*]=0\)，而存在另一明文 \( m \) 使该概率非零，从而两个明文导出的密文分布不同，违反完美安全。
- 老师课上的具体写法是：取密文 \( c \) 及其对应的一组密钥 \( k_1,\dots,k_s \)（\(s \le |K|\)），对每个 \( k_i \) 解密得到 \( m_i \)；因 \(|K|<|M|\)，存在明文 \( m^* \) 不在这些 \( m_i \) 中，于是 \(\Pr[\mathrm{Enc}(K,m^*)=c]=0\)，而 \(\Pr[\mathrm{Enc}(K,m_1)=c]>0\)，两者不等，故不满足完美安全。

老师强调：这说明完美安全的局限性**不是一次一密不够聪明，而是定义本身的内在缺陷**——只要要求完美安全，密钥长度就不可压缩。

## 十二、课堂讨论与作业

- **作业/扩展**：把加密算法当作**随机算法**，重新推导两个定义的等价性（联合分布需再扩张一个随机变量），以加深理解。
- 老师多次用“甲方/乙方”“打游戏推水晶”“从中国到印度只要证明存在一条路线”等比喻，解释“香农安全对任意分布成立，所以证明时任选一个分布即可”这一逻辑，课堂讨论较热烈。
- 收尾：下节课将从完美安全的这个“雷”（密钥不可压缩）出发，引入**计算安全**——只要求对多项式时间攻击者安全，从而允许短密钥（如伪随机生成器扩展密钥）。

## 二、回顾上节课：从“无条件安全”到效率问题

上节课的路线：

1. 从 security 角度“死命地推”，希望从最坚实的基石出发——类似“坚信 1+1=2”这样的公理（老师称之为“公里”，即公理/axiom），在此基础上构建一个好的密码系统。

3. 但发现一个很大的 bug：**效率（efficiency）非常差**。在无条件安全的情况下，可以很好地实现“1 和 2”（指某些安全目标），但“3”（效率）完全无法接受。

老师强调：这门课不是教大家“别人给你一个方案你就在这边做”，而是希望大家**深度思考**——assumption 的选择也是需要深思熟虑的。

## 三、攻击者的刻画：为什么选多项式时间（PPT）

### 3.1 无条件安全下攻击者能力无穷大

- 说“无条件安全”时，攻击者的能力（power）是**无穷大**的：无穷计算能力、无穷存储能力，可以跑任何算法，包括量子算法等等。
- 举例：大数分解（给出两个大素数，给定 N，输出 P 或 Q）。在无穷算力攻击者眼中，大数分解和计算 1+1=2 是**等价**的，非常简单（枚举即可）。
- 所以必须**画一条线**，限制攻击者的能力，使假设有意义。

### 3.2 线不能画得太大，也不能太小

- **太大**（无穷算力）：大数分解没意义。
- **太小**：比如一个攻击者“甭管你输出啥，我都输出 1”——这是非常傻的 dummy，屁用没有；到这个级别连 1+1=2 都算不了，任何数都等于 1，也没意义。
- 所以要找一个**合适**的边界：既能涵盖现实中那些算法，又不能小到荒唐。

### 3.3 选择多项式时间（polynomial time）

有同学回答“多项式时间”，老师肯定：现在一般选择的就是**多项式时间**。但老师反复追问：**为什么多项式时间是好的？**

**例子**：老师博士一年级上复杂度课时，老师说“有一个算法复杂度是 3 的 80 次方，这是一个非常好的算法，因为它是常数”。但现实中这个算法非常垃圾。这说明：说“多项式时间”时一定要深入反复理解，不能别人说多项式时间就认。

关键点：**看增长速率，不是看绝对数值**。多项式时间刻画的是增长趋势。

老师从多个角度解释为什么 poly 是“硬通货”：

1. **现实中绝大多数高效算法都是 poly 的**，且很多限制在低次（比如 1 到 3 次左右，n、n²、n³，中间可能有 log 因子）。这是统计性观察，不是说所有。
2. **传递性/语言无关性**：一个算法在 C++ 里是多项式时间，转成 Java 或 Python 也是多项式的；不会出现在这个语言里是多项式、到那个语言里就变成指数级的情况。老师说“封闭性”这个词不太严格，但意思是：只要在一个语言里是 poly，在其他语言里编也是 poly，不用考虑底层原语是什么。
3. **可组合性（composition）**：如果 F 是 poly，G 是 poly，那么组合起来也是 poly；可以叠加，但不能叠加太多次（常数次叠加没问题；如果叠加次数本身爆炸就不行）。在常数级别的组合下，poly 是封闭的。

### 3.4 现实世界中的“好算法”与“坏算法”分布

老师画图说明：

- 现实中好的高效算法基本集中在多项式时间这一块（n、n²、n³ 等低次）。
- 坏的东西（如 3 的 80 次方这种极度垃圾的例子）在很外面。
- 而解决 RSA、离散对数这类问题的算法，都是指数级或亚指数级（sub-exponential）的——即 super-polynomial。
- 老师用“癌细胞”比喻：希望现实中好算法都离这条线远远的，切割得干净；不希望癌细胞扩散得很厉害，希望它待在那儿，好的组织被清晰包进去。

### 3.5 攻击者本质上是什么？

- 攻击者本质上**是一个算法**（老师说自己第一印象把它当成人，但它本质上是算法）。
- 衡量算法复杂度时，一般把它推导/归约到**确定性图灵机**上看 steps（步数）。
- 然后老师展示形式化定义：一个图灵机 M 是多项式时间的，如果存在一个常数 C，使得对于任何长度为 n 的输入字符串，M 最多在 n^C 步内停机（running time 的上界是 n 的 C 次方）。
- 但确定性不够：第一节课说过算法很多时候希望是**随机的（randomized）**。所以再加一条**随机带（random tape）**，变成三条带子。随机带上的随机是**纯随机**（真随机，不考虑随机数质量好不好），由“神仙”给的，可以随便挥霍。
- 随机算法的定义与确定性类似，唯一区别是加了随机带；运行时间上界仍然是 n^C。

### 3.6 PPT 的定义

于是我们有了对攻击者的刻画：**概率多项式时间（Probabilistic Polynomial-Time，PPT）**——即随机的、多项式时间的攻击者。以后说起攻击者，一般就限定在这个角度，统称 PPT。

## 四、寻找困难问题：从信仰 P≠NP 出发

### 4.1 需要攻击者在多项式时间内解不了的难题

- 回到主题：我们要找一个 assumption，使得它有用；它应该是**攻击者解不了的东西**（如大数分解，希望攻击者解不了）。
- 我们要找难题，使得攻击者在多项式时间内解不了。**为什么这么期望？** 因为如果他能解，那这几百年来牛逼的数学大家早就把它解了——我们是这样“欺骗自己”的：没有说它真的解不了，只是说如果在约定时间内被解了，那这些大牛早就提出来了。

### 4.2 停机问题：真困难但没用

- 首先想到的著名困难问题：**停机问题**（判断一个图灵机是否停机）。它确实解不了，是非常著名的困难问题，但**对我们没多大用**。

### 4.3 P≠NP：计算机人的信仰

- 作为计算机人，更喜欢的是 **P≠NP** 这个信仰。如果 AI 证明出来 P=NP，那老师也认了，“那就失业吧”；但现在它还是我们的信仰。
- 基于 P≠NP 提出困难问题，比如 **NP 完全问题（NP-complete）**。P 是多项式时间可解的语言类，NP 是多项式时间可验证的语言类；如果 P=NP，那什么都别说了，直接蔓延过来。
- 但 NP 完全问题**不是无条件困难**的：它只是在“现在/多项式时间内”不困难；如果 P=NP 它就不困难了。老师强调：这是**我们的信仰**，你要是想构造一个基于它的加密算法，那基本上也是世界级贡献（飞沫思维=非凡思维）。
- 目标：用这一类基于信仰的困难问题去构造一个 assumption，并且它正好有用——能实现加密算法。

## 五、从加密系统的必要条件推出单向函数（One-Way Function）

### 5.1 加密系统需要的两条必要条件

老师从加密系统出发，看它需要什么：

- **正确性**：加密后能解密。
- **高效性**：给定密钥 k 和消息 m，能很快计算密文 c（加密不能太慢）；解密先忽略，最后补上。
- **安全性**：攻击者或任何算法只拿到密文 c 时，想得到 k 或 m 是**难**的（从 c 反推 k/m 难）。

这两条（正向好算、反向难算）是任何有意义的加密系统的**必要条件**（不充分，但必须满足）。先从必要条件入手去推 assumption。

### 5.2 单向函数的直觉

这给我们的感觉就是**单向性**：像二极管一样，只能从一个方向走，不能逆行；像高速公路只能往前开，不能逆行。函数进去就出不来：有 k、m 可以算 c，但有 c 不能反推 k、m。

这个函数就叫 **单向函数（One-Way Function）**：它是一个 function，并且“这边好过，那边不好过”。

### 5.3 从最极端的“好”出发：worst-case 单向函数

老师想提一个**跟 1+1=2 最近**的东西——假设越少越好，不想提得太高（安全性特别不好），要提一个离“基石”最近的、假设最少的东西。

这就是 **worst-case 单向函数**（最坏情况单向函数），它是起点，之后慢慢扩张成其他类型的单向函数。

定义（两个条件）：

1. **易于计算（easy to compute）**：存在多项式时间算法，对任何 x 都能算出 f(x)。
2. **难以还原（hard to invert）**：不存在这样的 PPT 攻击者，使得他**每个**都能还原。

关键理解“还原（invert）”：

- 还原不是要求一定把原来的 x 计算出来；而是说**计算不出一个 y 使得 f(x)=f(y)**（即找不到一个原像）。
- 例子：截断函数 f(x) 把 x 的一半切掉。它不是单向函数，因为把任何一半补上任意数都能相等——攻击者很容易找到碰撞。
- 所以单向函数中，攻击者“赢”的条件是：只要他找到任何一个 y 使得 f(y)=f(x) 就算赢；不要求 y 和 x 相同。

关键理解“worst-case（最坏情况）”：

- 对于任何攻击者，他**不可能把所有的 x 都搞定**；总有几个搞不定的。至少有一个搞不定，就叫 worst-case。
- 即：哪怕攻击者能还原绝大多数，也总有一两个“别扭”的点还原不了。

### 5.4 worst-case 单向函数与 P≠NP 的关系

- worst-case 单向函数和“NP not in BPP”（NP 不在 BPP 中）是**等价**的（老师提到 BPP，大家现在认为 BPP=P，但没人证明出来，这是世界级贡献难题；先不管）。
- 换句话说，它跟我们“信仰”很近很近。老师讲故事：这个 assumption 的根源来源于原始信仰 P≠NP；它是我们信仰力量的传承——如果这个东西坏掉，后面所有的话都是 garbage；如果你信这个东西，它就慢慢进行力量的传承。
- 第一条原则：我们找 assumption 要满足原始信仰，不是乱来的。

### 5.5 worst-case 单向函数“没用”

- 但 worst-case 的定义是：不存在攻击者能**百分之百**还原；即对任何攻击者，总有那么一两个点还原不了。
- 问题是：攻击者可以还原绝大多数，只有少数几个不能还原——这**没法用**！
- 加密时我们希望的是**全部不能还原**（任何东西都不能还原），而不是“绝大多数能还原、少数不能”。攻击者如果能把绝大多数 message/key 都搞出来，我们不能接受。
- 所以虽然它很好地传承了信仰力量，但真的没法用，必须调整。

### 5.6 退而求其次：strong 单向函数

- 我们希望“所有东西都不能还原”，但这**不可能**：比如提前定死一个 X，不管什么输入都输出 X——这是一个 dummy 算法，它在 X 这个点上绝对能还原（至少有一个饱和点）。
- 所以“所有都不能还原”太过分，退而求其次：**不能还原的点是绝大多数，允许很小很小一部分可以被还原**。
- 比喻（“金主爸爸”的要求）：饭里绝大多数是米，可能有那么一两粒沙子，我们希望吃不到；不能接受“全是沙子里面放几粒米”（那是 worst-case 反过来，吃不下去）。也不能要求“必须全部是米”（搞不起）。
- 即：能接受很小比例的可还原点，绝大多数不可还原。

**如何定义“小（small）”？**

- 用小=1/大来定义；先定义“大”，再取倒数。
- **大 = super-polynomial（超多项式）**：不是多项式，即对于任何常数 C，都无法被 n^C 支配；等价地，对于任何 C，存在无穷多个 n 使得 f(n) > n^C（老师用“存在一个 N，当 n>N 时 f(n)>n^C”来刻画，并强调这是**存在性**的，不是对所有 n 都满足）。
- 例子：2^n 是 super-poly；n^100 不是（它是 poly，因为存在 C=100 使它被 n^C 支配）；2^(log n)² 不是 super-poly（它等于 n^(log n)，可以被 n^C 支配？老师课上讨论后认为它被 n 的某次方支配，不是 super-poly）；而 2^(n^ε) 这类（离散对数算法常见复杂度）是 super-poly。
- 老师强调定义要抓住**增长速率**，并且 super-poly 的定义是“存在一个 N，越过之后就被支配”，但也提醒：真正想要的是越过某条临界线之后一直表现得很亮眼，而不是脉冲函数/阶梯函数——即对任何 C，存在 N，使得对任何 n>N，f(n)>n^C。
- **小（negligible，可忽略）**：小 = 1/super-poly。密码学里通常不用 small，而用 **negligible**，语义完全等价。

**strong 单向函数的定义**：

- 存在一个可忽略函数 negl，使得对于任何 PPT 攻击者 A，A 拿到 f(x) 后能还原成功的概率小于 negl(n)。
- 即：能还原的部分非常非常小。
- 关于 n 小的时候：下节课会讲，n 本身是参数，n 小时不 care（比如密钥只有 1 比特，肯定容易被猜，本身有信息量问题，不相关）；密码安全性建立在参数足够大时是好的就行了。

### 5.7 现实中的函数很难达到 strong

- 从 worst-case 到 strong，看起来适合“金主爸爸”的先进要求；worst-case 离信仰最近，但做不到 strong。
- 现实中我们用的一些函数，也很难实现 strong 这个等级。
- 所以**逼着还要再往回退一步**：允许很多能搞定，但希望你搞不定的部分也不是那么小（不像 strong 那么小）。比喻：允许饭里很多沙子，但饭团里米也不能太少，不能让我过分到找不到 1 厘米的米。
- 这个降低条件不是不想代表几种办法，而是真的搞不定，必须给自己划一条能搞定的线。
- 老师提醒：图上画的 worst-case 和 strong 看起来近，事实上它们有天差地别（本质等价性的讨论下节课讲，通过构造可以证明某些等价性）。

## 六、week 单向函数及其构造

### 6.1 week 单向函数的定义

- 存在一个多项式（poly）的东西，而对于任何 PPT 攻击者 A，A 可以还原的部分**不是可忽略的**（即有一个不可忽略的 fraction 还原不了？老师表述为：所有攻击者总有至少这么一个 fraction 你还原不了；换句话说，可还原部分不能小到 negligible）。
- 老师这里讲得较绕，核心是：**允许攻击者还原不少，但要求存在一个不可忽略比例的部分攻击者还原不了**（即“搞不定的部分不是那么小”）。

### 6.2 构造：乘法函数

- 老师说这个 one-way function 大家可能第一次听，感觉很神秘，但构造非常简单：**乘法**。f(x,y)=x·y。
- 但显然这**不是**单向函数：对于任何 x，取 y=1，f(x,1)=x，攻击者很容易还原（任何 x 都能被搞定）。
- 做一点改动：f(x,y)=x·y，但要求 x≠1 且 y≠1（“只要有一个等于 1 就都等于 1 了”，所以排除）。这样大多数值比如 100，不管怎么乘都可以分解成 2 和 50（2×50=100），绝大多数都能搞定；但我们期望有些地方搞不定。
- 讲构造时老师只讲**性质/直觉**，不做 reduction（第一个 reduction 在线上面，时间关系不讲），说明它为什么“牛逼”：
  - 当 x 和 y 都是**大素数**时，给出 x·y 计算 x、y 是很难的（大数分解）。
  - x 和 y 是从 n 比特里**随机选**的；如果 x、y 同时为大素数的概率不低（数学上可证明：n 比特随机数中是素数的比例不低，约 1/n 量级，老师给了比较松的界），那么只要 x、y 落在这个“好的素数”比例里，我们就很难分解。
  - 换句话说，只要有一个不小的比例落在好地方，它就是一个 week 单向函数。

### 6.3 从 week 到 strong 的扩张

- 假设有 N 个 week 单向函数 f₁, f₂, …, f_N。
- 定义 F(x) = f₁(x₁) ‖ f₂(x₂) ‖ … ‖ f_N(x_N)（把输入 x 分成 N 份，分别作用后拼接）。
- 通过这个扩张，F 就变成了 **strong** 单向函数：只要有一个 f_i 搞不定，你就搞不定——哪怕你解出来很多，但有一个卡住你就吐血了。
- 所以通过简单的扩张，可以看到 week 和 strong 的**等价性**（在构造意义上没有本质不同）。这条线（从 worst-case 到 week 到 strong）是为了让我们更好地构造这样的函数。

## 二、回顾：为什么必须走 assumption 这条路

1. 第二节课提出了一个非常好的 notion，叫 **perfect secrecy（完美保密）**，但实现它需要一个额外限制条件：**密钥空间不小于消息空间**（|K| ≥ |M|），这是已学知识。

4. 于是退而求其次，**引入 assumption 和 reduction**。

   - 为什么要想 one-way function；

## 三、补充 one-way function 的性质（为构造做准备）

在做构造之前，先对 one-way function 的 property 做更细致的阐释（上节课没讲清楚的补充）：

**性质一：one-way function 只保护“全部信息”，不保护“部分信息”。**

- 直觉上单向函数不会泄露 X 的信息，但**看定义要仔细**：one-way 的定义是“不泄露你的全部信息”。
- 形式化地：不存在 PPT 攻击者，给定 f(x) 能找到一个 y 使 f(y)=f(x)（概率不可忽略）。也就是说，攻击者不能“完全还原”某个原像。
- 含义推导：哪怕攻击者能还原出 X 的 **1/2、1/3、1/5、4/5** 甚至很大一部分——只要还有那么一部分没被挖掉、没被攻破，它就仍然是 one-way 的。换句话说，**经过 F 之后，攻击者可以回答出前面那些比特，但后面的东西怎么都搞不定，它也是 one-way 的**。
- 结论：one-way function **只保证全部信息不泄露，不保护部分信息**。

**性质二：f(x) 不需要长得很 random，可以有结构（structure）。**

- 如果 F 是 one-way function，那么加一些结构/变换后的函数是不是 one-way？显然也是。
- 它可以用无数个 structure 去换掉 output，可以没有任何“保干净”的要求；**不必长得很随机、不必长得很好，可以很 weird、很有结构，只需要有些部分是好的就行**。
- 举例：一个 one-way function 的**第一个比特可能是定死的，第二个比特也可能定死**，只要某些部分比特比较“泛”就可以了。

老师强调：这两点（只保护全部信息、可以有结构）正是**直接用 one-way function 构造加密时会出问题的地方**。

## 四、直接尝试用 one-way function 构造加密：为什么不行

假设 F 是 one-way function，尝试构造：密文 c = F(sk)（或类似形式），看行不行。

**问题一：无法解密。** 拿到 sk 之后完全没办法解密（因为 F 不可逆，sk 本身也被“单向”掉了）。

**问题二：F 可能泄露全部信息（把 message 全干出来），但 sk 干不出来。** 即攻击者有可能把消息全还原出来，而这正是我们不能接受的。

所以**直接用 one-way function 肯定不行**。

## 五、回顾 one-time pad 的思路：把密钥分成“mask”和“好用的部分”

回顾之前（one-time pad）是怎么做的：

- 不是把 sk 和 message 当成一坨直接塞进去，而是可以看成**两个部分**：
  - 一部分可以看成一个 **mask（掩码）**；
  - 另一部分可以看成“好的东西/皮”，把消息包起来。
- 按照这个思想，我们要做的是：**把 mask 换个样子**，完全 follow 一次一密的格式。
- 具体地：把 sk 里这个“好的皮”换成**一层新的皮**——用 one-way function 生成的东西来做 mask。行不行？

**对照刚才讲的两点问题分析：**

- 多次使用问题不是核心（可以展示用几次，小问题）。
- **核心问题**是：F 的结构可能是固定的（比如前面全是 1，后面是什么东西），那么 M 异或（XOR）上 S 之后，**S 的前面部分全部被干掉了**，M 的前面这些比特就**没有任何保障**——这不能接受。
- 写成 G 更好理解：如果 G 前面全是一，那么 M 的前面的比特没有任何保障。

**结论**：one-way function 挺好，但在构造加密这个目标上，“in some fashion”还是不够。我们之所以考虑 one-way function：第一，必须考虑 assumption；第二，考虑 assumption 时必须有个“根儿”——这个根就是从 DCS（决策/复杂度）里、从 P≠NP 那个“口碑/信仰”里出来的 one-way function，是最接近信仰的“大表哥”。找到它没问题，因为它和 P≠NP 最近；但**它不够（insufficient）**，还是要对它进行**升级**。

我们的核心目的是构建一个 **sufficient** 的东西，最好是最重要的；做不到最重要，至少要做到充分条件——不能只罗列实现目标的必要条件，必须给出充分条件。

**两条路线的判断：**

- 直接拿 one-way function 当加密：**无法解密**，注定这条路不容易走通。
- 另一条线：它有 one-way 方面的印证，**有可能是条路子**，“现在长得下来像个人样”，我们按这条线走。这条线的问题在于 **structure**。

## 六、做梦/蓝图：需要“看起来随机”的东西

如果有一个 function，使得它**没有 structure**，比如看起来像纯随机——纯随机肯定不行（“王太太多了”=随机性太多/太强），先不说伪随机这么专业的词，用最最简单的“人话”：**看起来自己看起来随机的东西**。

如果我们有一个方法可以把某个东西弄成一个**看起来随机**的东西，把它当做 mask，我们就比较安心了——至少看起来这是能走通的路。

**目标（blueprint）**：搞一个看起来随机的东西，希望它有两点：

1. **不可区分性（indistinguishability）**：看起来随机；
2. **输出比输入长（length extension）**：f(sk) 的长度要大于 sk 的长度。如果 sk 长度不够大，我们直接用它在 OTP 里就行了，何必绕一圈给自己找麻烦？

记住目标：构建一个好的加密系统，**shorter security（更短的密钥/更短的安全参数）+ 上述两点**都必须有。

**关于“structure”的澄清**（同学提问）：

- 结构不一定指代数结构；前面 100 个比特全是 1，这也是结构（固定的东西）。
- 代数结构是更窄的说法（比如群/环上的运算）；一般说 structure 是比较宽泛的名词，指比较固定、不太好的东西出现了，看起来不随机。

## 七、如何精确定义“看起来随机（random-looking）”

### 7.1 先限定攻击者：PPT

- 什么叫 random-looking？先看谁在看：**超强计算能力**的攻击者能区分，那不就成 perfect 了吗？不行。
- 比喻：一个人高度近视，戴上非常精妙的眼镜能区分“谷子”和“米”；但如果配不起好眼镜，从地摊上买 10 块钱 2 斤的眼镜，就分不清。**超强攻击者 = 好眼镜**，我们搞不定；所以退而求其次，**只带 10 块钱眼镜的攻击者 = PPT 攻击者**，我们搞得定。
- 所以 random-looking 里的“looking”首先限定在**计算能力有限**：在 **PPT 下无法区分**。
- 形式化含义：对于任何多项式时间的攻击者，无法区分，区分优势（advantage）大于某个常数/多项式分之一？不——是**很小很小**，但不一定是均匀分布。攻击者输出 0/1，看他对分布的反映。

### 7.2 从“不 random”的例子反推

先说什么**不是** random（逐步逼近）：

- 例 1：0 和 1 的比例不一样（random 的东西希望 0 和 1 各占大约 1/2，不要求 exactly 1/2）。
- 例 2：满足比例大约 1/2 了，但某个 pattern 的比例不对——**任何 pattern 的比例都要差不多**。
- 例 3：更长/更复杂的模式，比如某些块的比例不对等。

但要小心：**把一眼假的东西去掉，剩下的不一定是真的 random**。比喻：一个瓷器上写着“微波炉专用”，肯定是假的；但一个瓷器上没写“微波炉专用”，也不一定就是古董。所以这些例子只是帮助思考，不是定义。

### 7.3 关键启发：两个分布之间的关系

回顾超强攻击者下什么做不到：**如果两个 distribution 是 identical（完全相同）的**，从这儿采样一个变量和从那儿采样一个变量给他，**超强攻击者也区分不出来**（即使再强也做不了）。

这给出一个启发：**考虑两个分布之间的关系**。如果攻击者无法区分这两个分布，那就好了——这是一个比较可能的方法，去画这个圈子（定义 random-looking）。

老师强调：前面这些例子**纯粹是帮助思考**，不是定义；思路是：从最简单的入手，感受不行的点在哪里，再尝试刻画行的点。

### 7.4 计算不可区分（Computational Indistinguishability, CI）的直觉

- 画一个 reduction 图：一个简单的 copy，从这儿外包，用普通的“无法区分”。
- 如果伪随机（pseudorandom）把它当 uniform，这是完全 mimic 以前做过的事情，只是把 AI（攻击者）换成拿到里面的东西。
- 先把这个 high-level 甩出来，大家觉得直觉 match，再细化。

**两个必须考量的因素**（因为攻击者是 PPT，不是无穷算力）：

1. **攻击者的运行时间**；
2. **地址/问题的规模（security parameter 的规模）**。

老师用两个小游戏/图让大家体会：

- 第一个游戏：给你 10 秒钟找不同点，可能找不到；给 1 分钟就可能找到。说明**运行时间必须精确考量**——问题规模可能是一分钟级别，但 10 秒钟就是搞不定。
- 第二个游戏：找相互 overlap 的点是 3 个还是 2 个，规模小的时候一眼真、数一下也行、10 秒差不多；规模变大就痛苦了。说明**固定时间下规模也很重要**。

结论：必须搞一把**尺子**，精准衡量攻击者的时间（不能简单说它是一个 T），也要精准衡量问题的规模。以后这堂课只会用 PPT。

## 八、安全参数（security parameter）

回顾第一堂课留的“坑”：给 generation 的输入，当时说这里有个坑先不管。今天讲清楚该把什么东西放进去。

- 为了刻画“攻击者时间”和“问题规模”这两个变量，分布不能再是固定分布，必须是**变量性的**，要用一个**参数**来处理。
- 定义 **安全参数（security parameter）**，通常用 λ（“栏目的/拿不拿/拉不到”）或 n 表示。
- 交叉验证：AES-256、RSA-2048/512 里的 256、512 就是安全参数。
- 第一节课的坑就变成：generation 输入 **1^λ**（“一天 35/打一天 35”即 1^λ），只打这个，产生的 sk。
  - 正常情况：从 λ 比特里取 1 个 sk（most case，不是所有 case）。
  - sk 的 size 至少是 λ（安全参数）。
- **AES-256 的含义**：这份设计可以抵抗**现阶段最好的攻击算法**，并且这些攻击算法的复杂度至少是 **2^256**（要攻破至少做 2^256 次运算）。前提条件：**best known**——只是现阶段人类能想出来的最好算法，没准明天 AI 就把它干碎了，这不知道。但设计安全参数时，从安全层面讲，涵盖的就是“现阶段已知最好攻击的复杂度是 2^λ”。
- 第二个作用：用安全参数作为**统一的尺子**去衡量问题的规模。
  - 回顾 PPT 定义：对每个固定的 A，总有一个常数 c（Q）；现在用这把尺子衡量问题规模。
  - 定义成一个 **family of distributions / ensemble**（分布族），不是单个分布，而是**由 index/参数 n 索引的分布序列（sequence of distributions indexed by n）**。选取 n=λ 时考虑对应分布；n 变大分布变复杂。

老师解释“为什么可以这么定义”：如果两个东西定死，就引入不了规模；而例子说明规模很重要，所以必须引入。index 只是为了和参数配平——**N 越大分布越复杂，只是正相关，不一定是 2^N**。

## 九、计算不可区分（CI）的形式化定义

**定义（CI）**：两个分布族 {X_n}、{Y_n} 是计算不可区分的，如果存在一个**可忽略函数 negl**（上节课定义的 negligible），使得对于**任何 PPT 攻击者 A**：

|Pr[A(X_n)=1] − Pr[A(Y_n)=1]| ≤ negl(n)

（即“这个概率减去这个概率是小的”。）

**几个关键澄清：**

1. **为什么只考虑“等于 1”而不考虑其他输出？** 因为输出 0/1 就足够了；输出多个也可以，但可以包装成一个比特（留作作业/思考）。攻击者本质上做的是**区分（distinguishing）**。
2. **不要求概率等于 1/2。** 很多人有误区，以为必须等于 1/2。实际上：把其中一个概率想成**基线 baseline**，我们要求的是“你能在基线上的提升是小的”，当参数足够大时。绝对值是多少不 care，只 care **差（gap）**。
3. **negligible 只在 n 足够大时有意义**：n 小时我们没做任何声明（n=1 时没有任何限制）。这是很多人（包括老师交流过的学生）的认知误区，要直接纠正。
4. **攻击者只调用一次分布**（定义里是对分布采样一次）。如果调用多次（比如给 X_1…X_p 都从分布采样）会怎样？这是留的问题——通过传递性/hybrid argument 可以处理，多调用与单次调用本质等价（“看一次和看 polynomial 次一样”）。

**CI 的美妙之处：传递性（transitivity）。**

- 如果 X ≈ Y 且 Y ≈ Z，则 X ≈ Z。以后就可以进行拆分（hybrid argument）。
- 老师演示：用 hybrid 序列，相邻两个只差一处，每个相邻对都是 CI 的，通过传递性得到首尾也是 CI 的。

**回应“攻击者只能看一眼不爽”的质疑：**

- 有人觉得定义里攻击者只能看一次太弱小，应该让他看很多次才 mining for。
- 但通过传递性可以证明：**看一次和看多次（polynomial 次）本质等价**，所以这个定义是精妙的，不是缺陷。
- 老师留了作业/思考：让 A 输出 stream、只输出一个比特，也是一样的；多调用也等价。大家通过怼定义来加深理解。

**老师对“怼定义”的态度**：给出定义后要批判性检验（“捶他”），从不同角度问。如果怼了没被反怼回来，理解就增加一分；不怼是不对的。

## 十、伪随机数生成器（PRG）的定义

有了 CI 这个统一框架，定义伪随机就非常简单：

- 用尺子：输入是一个 λ 比特的种子（seed），输出是 L(λ) 比特（L 是多项式，且 **L(λ) > λ**，即扩张）。
- **伪随机性**：{G(s) : s ← {0,1}^λ} 与 **uniform {0,1}^{L(λ)}** 是**计算不可区分**的（CI）。
- 即：G 的输出“长得像”均匀随机。

**PRG 的两个条件：**

1. **扩张性（length extension）**：对任何 n（λ 足够大时），输出长度 L(n) > 输入长度 n。因为我们的 goal 是用 sk 生成 mask 去 XOR 消息 M，所以必须有扩张，不扩张没意义（直接用 OTP 就行了）。
2. **伪随机性**：输出分布与均匀分布计算不可区分。

**关于分布的澄清（同学提问）：**

- 分布由 X（种子）的分布导出：X 是 λ 比特均匀随机（1/2^λ 每个），所以 f(sk) 的分布就是种子均匀分布经 G 导出的分布。
- 我们要对比的是：**G(sk) 的分布**（sk 均匀）与 **uniform {0,1}^{L(λ)} 的分布**，二者 CI。
- 有人问“统计距离是不是很近”——**不是**！统计距离可能非常非常大（接近 1），如果有无限 power 一眼假；但在计算能力有限（PPT）下看不清楚。这就是“米和谷子在地摊眼镜下分不清”的比喻：统计距离很远，但计算不可区分。
- index/参数：G 是一个 family，由 n 索引；当 n 调大时输入输出一起调大，只是正相关，不要求 exact match。

## 十一、用 PRG 构造加密（第一次尝试）

现在武器升级完成（有了 PRG），尝试构造加密：

- 密钥 sk 是 λ 比特（n 比特）。
- 用 PRG 生成 mask：G(sk) 是 L(n) 比特，L(n) > n。
- 加密：c = m ⊕ G(sk)（m 是 L(n) 比特）。
- 解密：m = c ⊕ G(sk)。

**正确性**：显然成立（XOR 可逆）。

**密钥比消息短**：sk 是 n 比特，m 是 L(n) > n 比特，实现了 shorter key。

**难点：如何证明安全性？** 不能说“我用了 PRG 所以安全”——这只是直觉，绝对不能当 proof。provable security 必须给出 assumption + definition + reduction 三样齐全。

- 不能拿 statistical privacy（统计保密）来证，因为 PRG 本来就不是统计保密，跟它不沾边。
- 要证明构造安全，首先要给出一个**合适的、大家认可的 definition**，有了 definition 才能做 reduction。

## 十二、安全性定义：从 perfect secrecy 自然扩展

**方法**：从 one-time pad 里那个好的、被认可的定义（perfect secrecy）中**吸取灵魂**，取其精华放到这儿——因为它被很好地“粘”/验证过，作为一个好的 mimic 比较好抓。这是一个通用的方法（将来做测试也可以看别人怎么做再做一个相关类型的 mimic）。

**Perfect secrecy 的定义**：对任何 M1、M2，由 M1 导出的密文分布与由 M2 导出的密文分布是 **identical（完全相同）** 的。

**Natural extension + CI 工具**：把“identical”换成“**computational indistinguishable（CI）**”——对任何 M1、M2，两个密文分布是 CI 的。这是我们的思想。

**另一种更 base 的方法：Game-based definition（Q 币/游戏基定义）**——这是密码学里常用的方法：

- 两个角色：**攻击者 A** 和 **挑战者（challenger）**。
- 第一步：把所有 public 信息（包括 encryption 怎么运行、distribution 怎么运行等）全部告诉 A——符合 **Kerckhoffs 原则**（“客户服务原则”）。
- 第二步：体现“区分 M1、M2”。方法：**放权给 A**，让 A 自己选 M1、M2（要求长度相等；长度不等的话太容易区分了，我们不 care 这种事）。
  - 为什么让 A 选？因为领先的攻击者肯定找最容易区分的来；如果 best case 都区分不了，那 for all 都区分不了（worst-case 论证思路）。
- 挑战者自己投一个硬币 b ← {0,1}（“自己 free 一个 coin”），把 sk 给 A（或公开），加密 M_b 得到 c，把 c 给 A。
- A 输出猜测 b'；**A 赢**当且仅当 b' = b。

**这里反直觉**：看起来我们需要 A 不赢，但显然他能赢（猜对概率至少 1/2）。真正 care 的不是他赢不赢，而是他赢的概率**跟 1/2 的关系**：

- A 啥也不干（不看密文），猜对概率是 1/2（基线）。
- 我们期望 **advantage（优势）**：|Pr[A 赢] − 1/2| 是**小的**（可忽略）。即 A 不会比 1/2 多很多概率去赢；他啥都不干和费半天劲得到的效果几乎一样——那这个加密就非常非常对了。

这个 game 本质上体现的就是：**M0 和 M1 的两个密文分布是计算不可区分的**。以后写 definition 也建议尝试用 CI 的方法去理解，从各个角度去看会理解深很多。

## 十三、Reduction 的核心思想（时间关系只讲直觉，下节课详细推）

- 核心思想：**如果你能赢我这个 game（以较高概率区分密文），那我就能打掉你这个 PRG**（把 PRG 的伪随机性打破）。
- 即：如果你能以较高概率赢（优势不可忽略），那么我打破 PRG 的概率也是不可忽略的。
- 比喻：**外包公司**——你能干这个事情没问题，我作为外包公司把你买过来，用你 A 作为核心技术去解决 PRG 的问题；解决了我就 be famous 了。
- 但我们相信 PRG 是好的（安全的），所以这样的 A **不存在**。也就是说：如果存在这样的 A，PRG 也不行；如果相信 PRG 行，那这样的 A 肯定不存在——对所有 A 都不行。
- 下节课会一步一步详细推这个 reduction。

**老师最后的话**：前两年很多同学上完课对 reduction 没有任何 sense，后续 advanced crypto 课很多老师反馈同学对 reduction 没 sense。所以这次讲得慢，包括 CI、这些定义，关键是多“怼一怼”（从各个角度批判性检验），帮助大家思考引申意义。

## 二、继续：用 PRG 实现加密（第一阶段目标）

上节课我们有了一个非常强的工具 **PRG（伪随机数生成器）**：从短的种子生成长的、看起来随机的串。

**回顾 one-time pad**：加密就是 m ⊕ k（简单异或），其中 k 是**纯随机**字符串——在 perfect secrecy 的定义里，密钥生成算法从 {0,1}^n 里均匀随机取 sk。

**简单的替换**：如果我们有了 PRG G，就把它替换成**伪随机字符串**：

- **密钥生成**：sk 是 n 比特字符串（从 {0,1}^n 取）。
- **加密**：c = m ⊕ G(sk)。
- **解密**：m = c ⊕ G(sk)。

**和 one-time pad 相比只改了一个地方**：把真随机字符串换成了伪随机字符串，其他什么都没变。

**好处**：

1. **正确性**很好验证。
2. **长度扩张**：G 是 PRG，输入短（n 比特）、输出长（L(n) 比特，L(n) 严格大于 n）。只要输出比输入多一个比特，PRG 就可以“想怎么着怎么着”（但不能太过分，L 还是 polynomial 的）。
3. **伪随机性（pseudorandomness）**：G 的输出看起来随机。
4. **消息空间扩张**：消息空间从 n 比特变成 L(n) 比特（因为 m 和 G(sk) 异或，消息可以到 L(n) 比特）。
5. **密钥比消息短**：密钥只有 n 比特，明文可以到 L(n) 比特，且 L(n) > n——这正好满足第二节课提出的、我们非常想要的“密钥空间小于消息空间”的目标（第二节课说的是密钥不小于消息空间是“不好的点”，现在反过来了）。

**直觉上的安全性**：G(sk) 这块看起来随机，所以它是个不错的 mask；加密后密文也看起来随机。但老师强调：**这只是直觉，不是证明**，下面要做严格的 reduction。

---

## 三、三个要素：assumption + definition + reduction

老师强调：provable security 必须有三个元素，希望大家有 sense：

1. **Assumption（假设）**：这里 assumption 就是“G 是一个 PRG”。我们这个算法的安全性依赖于 G 是 PRG；如果 G 不是 PRG，我们不知道它是否安全，我们也不 care——我们只说“如果 G 是 PRG，那么怎样”。
2. **Definition（定义）**：上节课讲的窃听安全游戏（EAV/IND 类），再完整复习一遍。
3. **Reduction（归约）**：这次是**人生中第一次**正式讲 reduction（如果之前没学过复杂度归约的话），会讲得非常非常慢，有任何不懂一定要提。

---

## 四、复习定义一：Perfect Secrecy 与“诱导分布”

**Perfect secrecy 的定义**：对任何 M1、M2，由 M1 导出的密文分布与由 M2 导出的密文分布**完全一样（identical）**。

**“由 M 导出的分布（induced distribution）”**——老师特意重新解释（因为很多同学默认知道，其实不知道）：

- 密钥生成算法 kg 输出 sk，sk 本身是一个分布（如 sk1, …, skn 每个均匀）。
- 固定一个 M，加密算法 Enc(sk, M) 的输出 c 的分布，就是“**由 M 导出的分布**”——它完全依赖于 sk 的分布，唯一的变量是 sk，再叠加 M 的加密。
- 例如：如果 kg 的分布变成了某个固定值，那么诱导分布也相应变成固定的；如果 sk 是什么样，密文就是什么样，两边完全绑定。

**Perfect secrecy 就是用“分布完全一样”这把精细的尺子来衡量。**

---

## 五、复习定义二：计算不可区分（CI）与 EAV 游戏

**CI 版本**：对任何 M1、M2，由 M1 导出的分布与由 M2 导出的分布是 **CI（计算不可区分）** 的。

- 老师比喻：我们买不起“完全一样”这把精细的尺子，就换了一把**看起来有点模糊、但能接受的尺子**——主体框架没变，只换了一把尺子。
- 因为我们已经花了很长时间接受 perfect secrecy，又花了很长时间接受 CI，从直觉上看这是对的。

**等价的 game-based 定义（EAV 游戏）**——更 base、有两个人（挑战者、攻击者）：

1. **第一步**：把 public 信息（加密算法怎么做、kg 怎么做、conversation 怎么做）全部告诉攻击者——符合 Kerckhoffs 原则（“客户服务原则”）；具体选的 sk 是什么不告诉。
2. **第二步**：挑战者选一个安全参数 n（“选一个 q partner/安全参数”）。
3. **第三步**：挑战者选取一个 sk（不告诉攻击者）。
4. **第四步**：攻击者选取 M0、M1（长度相等；以后默认，不再强调）。
5. **第五步**：挑战者自己投一个比特 b ← {0,1}。
6. **第六步**：b=0 时给 Enc(sk, M0)，b=1 时给 Enc(sk, M1)。
7. **第七步**：攻击者输出猜测 b'。

**等价性原理**：sk 是随机选的，所以 Enc(sk, M_b) 这个值可以看成**从第一个分布（M0 导出）或第二个分布（M1 导出）里的一次抽样**。如果 A 无法区分这两个值到底来自哪个分布，就说明它们是 CI 的。所以 EAV 游戏和 CI 定义本质等价。

**优势（advantage）**：A 至少有 1/2 概率赢（瞎猜）。我们怕的是“比 1/2 高很多的概率赢”。定义 advantage = |Pr[A 赢] − 1/2|；如果这个值是可忽略的（小的），就说算法是 EAV 安全的。

**PRG 的 game-based 定义**（与 CI 完全共通）：

1. 第一步：把安全参数和算法 G 全部公开（G 的 code 完全知道，唯一不知道的是选的是哪个 seed）。
2. 第二步：挑战者从 {0,1}^n 采一个 x，从 {0,1}^{L(n)} 采一个 y（纯随机）。
3. 第三步：挑战者投一个比特 b；b=0 给 x（即 G 的抽样），b=1 给 y（uniform 抽样）。
4. 攻击者猜 b'。

如果 A 无法区分，就说明 G(x) 与 uniform 是 CI 的——这就是 PRG 的 game-based 定义。

老师强调：**希望大家从各个角度理解，把定义内化**，不要只读书上的定义、不往深里想。这堂课就是帮大家内化，并分享老师读书时的认知技巧。

---

## 六、Reduction 的核心思想：外包公司比喻

现在有了 assumption（G 是 PRG）和 definition（EAV 安全），要做 reduction：

**要证**：如果 G 是 PRG，那么我们的构造是 EAV 安全的。

**Reduction 本质上是一个“外包”**：

- 假设有一个非常厉害的人 A，能干碎 EAV 游戏（能区分密文）。
- 我们（reduction）把他“包下来”，当作外包公司的员工：对外我们是**乙方**接活（接 PRG 挑战者给的活），对内我们是**甲方**，把活交给 A 去做。
- 换句话说，reduction 有**两个身份**：外面是乙方（接 PRG 的挑战），里面是甲方（指挥 A）。
- 核心：**把甲方给的任务和 A 能处理的任务对接（match）起来**——A 的能力变现为解决我甲方问题的能力。
- 如果 A 能打碎 EAV，我就能利用 A 的能力去打碎 PRG（拿到奖/解决公开问题）。

老师强调：A 是非常敏感的——**你只要让他感觉不爽，他自杀**（不玩了）。所以 reduction 每一步都必须精确处理，保证 A 看到的分布和他真正玩游戏时看到的分布**完全一致**；否则 A 不玩了，你最后依赖他的输出，你就完蛋了。以后的 reduction 不会像这次这么简单，员工必须精细对待。

---

## 七、Reduction 的详细步骤（B=0 的情形）

**目标**：如果 A 赢 EAV 的 advantage 是 δ，那 reduction 打碎 PRG 的 advantage 也是 δ（可能有 loss，但只要不太小就行）。

**Reduction 流程**：

1. **甲方（PRG 挑战者）给 reduction**：public parameter（加密算法、G 等）——第一步全部告诉 A（因为 Kerckhoffs 原则）。有了算法，加密/解密算法就有了，具体 sk 不知道。
2. **A 开始发力**：A 选 M0、M1。
3. **问题**：reduction 要加密，但**没有 sk**，怎么产生密文？
   - 正常情况下有 sk 才能加密，但现在 reduction 是“甩手掌柜”，没有密钥。
   - 本质：**reduction 要在没有密钥的情况下把密文加密出来**——这是它必须做的事情。
4. **解决办法**：甲方（PRG 挑战者）并不是啥都没给——它给了一个 string（样本）。
   - 当**B=0** 时，甲方给的 string 就是 **G(x)**（x 是甲方选的 seed）。
   - 我们知道 sk 是加密的充分条件，但**不是必要条件**——知道 G(sk) 也能加密，不一定要找到 sk 本身；找一个更弱的充分条件就行了。
   - 所以当 B=0 时，reduction 直接用甲方给的 string（即 G(x)）作为 mask，**假装它是 G(sk)**，加密得到密文给 A。
5. **模拟的正确性**：当 B=0 时，这个 string 就是 G(x)，x 是均匀分布的 n 比特，所以它和“从 G(sk) 分布里抽样”**完全一致**（exactly）。A 看到的流程和真实 EAV 游戏**百分之百一致**——reduction 完美模拟了 EAV 游戏。
6. A 最后输出 b'。reduction 拿 b' 做什么？

---

## 八、Reduction 的输出策略与概率分析

**策略**：reduction 不是纯白痴外包（接活赚差价），它要对 b' 做二次加工：

- 如果 **b' = 我（reduction）自己投的 b**，我就认为甲方给的是 G(x)（伪随机），输出“伪随机”；
- 如果 **b' ≠ b**，我就认为甲方给的是纯随机（uniform），输出“随机”。

**为什么这样猜**：

- 当 B=0 时，A 玩的是真正的 EAV 游戏，A 赢的概率 = 1/2 + δ（δ 是 advantage）。
- 当 B=1 时，甲方给的 string 是纯随机，A 玩的是 one-time pad 游戏（完美安全），A 的 advantage = 0，A 赢的概率 = 1/2。
- 两个 game 之间有 gap（δ），用 A 的输出作为锚点来区分：A 经常猜对 → 更可能在玩 EAV 游戏（B=0）；A 猜错 → 更可能在玩 OTP（B=1）。

**概率计算**：

- Pr[reduction 赢] = Pr[B=0] · Pr[A 赢 | B=0] + Pr[B=1] · Pr[A 输 | B=1]
  = (1/2)(1/2 + δ) + (1/2)(1/2)
  = 1/2 + δ/2。

**结论**：如果 A 有 δ 的 advantage 赢 EAV，reduction 就有 **δ/2** 的 advantage 赢 PRG 游戏。

- 这里有一个 **loss（损失）**：δ 变成 δ/2。但只要 δ 是不可忽略的，δ/2 也是不可忽略的（除非 δ 小到可忽略，那就无所谓了）。
- 所以：如果 PRG 是安全的（不存在能赢 PRG 游戏的 PPT 攻击者），那么这样的 A 不存在，我们的构造是 EAV 安全的。**第一阶段目标达成**。

---

## 九、重新审视定义：EAV 够不够？——reuse 需求

第一阶段达成后，重新看定义哪点值得往下跑：

- EAV 定义里，**A 只允许 make inquiry 一次**（只加密一次）——因为我们的构造完全脱胎于 one-time pad，继承了 “one time” 的属性。
- 但现实中我们**更希望**：密钥定死之后可以**多次使用（reuse）**——用同一个密钥加密第一条、第二条、……第 q 条消息。我们不希望像 OTP 那样只能用一次。
- 虽然追求短密钥（密钥是密文的 1/2，确实短了），但只能用一次很不爽；密钥长度和密文线性相关也不爽；我们希望**密钥是常数值，定死之后随便加密多少条消息都用它**。现实中不可能家里加密 10G 数据还要保存 1G 的密钥。
- 所以第二阶段目标：**在有短密钥的情况下实现 reuse（密钥重用）**。

---

## 十、Reuse 的定义：联合分布的计算不可区分

**如果实现 reuse，定义应该长这样**：

- 对任何消息序列 M0_1, …, M0_q 和 M1_1, …, M1_q（q 是 polynomial），
- 由第一个序列（M0 序列）**在同一 sk 下**导出的**联合分布**（sk, Enc(sk,M0_1), …, Enc(sk,M0_q)），
- 与由第二个序列（M1 序列）在同一 sk 下导出的联合分布，
- 二者是 **CI（计算不可区分）** 的。

**关键点**：

- 不再是单一分布，而是**联合分布**；
- 所有 sk 都是**同一个、定死的 sk**（exactly one sk），不是每次独立采样；
- 这是“由 message sequence 导出的联合分布”，两边对比。

如果构造满足这个条件，我们就比较 confident 它支持 reuse——因为每次用的 sk 都是一样的，只是选取不同的 message。

**Game-based 版本（升级版 EAV）**：

1. 公开 public parameter（把那一坨公开信息用 pp 代替，不再全部写出）。
2. 挑战者产生 sk。
3. 攻击者输出两个 message sequence（M0 序列、M1 序列）。
4. 挑战者投 b；b=0 时用**同一个 sk** 加密 M0 序列，b=1 时用**同一个 sk** 加密 M1 序列。
5. 攻击者猜 b'。

这和上面 CI 定义完全等价，只是做了一个扩张（从单条消息到序列）。

---

## 十一、EAV 构造为什么实现不了 reuse：确定性加密的问题

**新能力/新攻击**：A 现在可以选 message sequence，能做哪些“坏事”？

- 关键：如果加密算法是**确定性算法**，那么同样的 message 加密出来**完全一样**（exactly the same）。
- A 可以在第一个 sequence 里让前两个块一样，在第二个 sequence 里让前两个块不一样；然后观察：如果密文前两块一样，就说明是第一个 sequence（M0）；如果不一样，就是第二个 sequence（M1）。
- 虽然不知道密钥是什么，但**绝对能区分**——这就能以很大优势赢游戏。

**结论**：

- **确定性加密百分之百实现不了 multiple message 安全（reuse）**。
- 这也是为什么第一堂课说：密钥生成一定是随机算法；解密在绝大多数情况下是确定性算法；**加密算法可以是确定性的也可以是随机性的，但我们推荐随机性的**——这里给出了很大的理由。
- 多重消息安全（multiple message）对标的正是 reuse 需求；想实现 reuse，用确定性算法就是实现不了。
- 老师补上第一堂课留的“坑”的补丁。

---

## 十二、第一次尝试随机化：直接加随机数——为什么不行

目标明确：**随机化加密，引入随机数**。

**尝试 1**：简单粗暴地把随机数 r 也 XOR 进去：c = m ⊕ G(sk) ⊕ r。

- **问题：无法解密**。解密时只有 sk 和 c，没有 r；解密算法只有那两步，拿不到 r，所以不行。

**尝试 2**：把 r 直接甩给解密方（把 r 也放进密文）？——老师继续分析这种“更粗暴”的做法。

具体设定：

- G 从 n 比特到 L(n) 比特，L(n) > 2n；
- r 从 {0,1}^n 随机选，sk 从 {0,1}^n 选；
- 密文包含 r 和 m ⊕ G(sk)（或类似形式）。

**看起来对，但问题在哪？**

- 在 PRG 游戏里，攻击者**只看到 G(x)**，不允许看到关于 seed x 的任何信息。
- 但在我们的构造里，攻击者看到了 r（一半信息），这相当于**泄露了 seed 的一部分信息**。
- PRG 的安全性只保证“**你完全不知道 seed 时**，输出是伪随机的”；一旦泄露一部分信息，PRG 什么都保证不了。
- 具体攻击：令 G'(sk‖r) = r ‖ G(sk)。这可以构造出一个“新 PRG” G'，但 G' 的前 n 比特直接就是 r，完全泄露——说明“泄露一部分后仍伪随机”不是 PRG 能保证的。
- 更形式化：如果做 reduction，要把 r 做出来；但 PRG 游戏不给 r，reduction 无法模拟，义务变重了，match 不上。

**结论**：这条路不行。我们需要**进一步升级工具**：

> **即使一部分（比如 r）泄露出来了，剩下的部分（mask）仍然是伪随机的**——只要 sk 没泄露。

这是下一阶段的目标：开发下一款“共聚产品”，即更强的 PRG 变体（后续会讲，比如伪随机函数 PRF、或者能抵抗部分泄露的 PRG 等）。

---

## 十三、总结与下节课预告

- 本节课完成：用 PRG 构造 EAV 安全加密，并做了完整的 reduction（δ → δ/2）。
- 发现 EAV 只支持一次加密，不满足现实的 reuse 需求；reuse 的定义是联合分布的 CI。
- 分析发现：确定性加密无法实现 reuse；直接加随机数会泄露 seed 信息，PRG 保证不了。
- 下一步目标：升级工具，使得**即使一部分信息泄露，剩余部分仍伪随机**（只要 sk 不泄露）。
- 下次课详细讲这一点。老师留话：前面 notion 有问题可以线下发信息问。

## 一、开场：继续上节课的 IND-CPA 游戏（Phase 1 允许任意询问）

老师接着上节课的内容，展示 IND-CPA 游戏的完整结构。首先强调：**Phase 1 中攻击者可以任意询问加密信息，且这些 message 完全由 A 自己选取**。

- 攻击者额外获得的信息（询问得到的密文）**可以跟后面的 M0*、M1* 强相关**，甚至直接就是 M0*/M1* 本身——老师明确说“我现在不做任何限制”，把 A 能拿到的信息全部放开，看他能做成什么。
- A 拿到这些消息后，相应地把密文发过去（挑战者回答）。
- 但 A 还不满意，**还可以继续问 message**——比如问到了 M100，还可以继续问 M101，**问到满意为止**，什么时候满意？什么时候输出 b'（猜测比特）。

**老师点出问题**：在 multiple message security 的对话里，还有一个**静态局限性**——攻击者在做决定之前是“全盲”的。现在要对他进行**高强度的增强**：

> 你做这个决定之前，不再是线下全盲的；你现在可以**依靠这些询问得到的密文**去做决定。如果我连这个都能保住（即攻击者拥有这些信息后仍然安全），那你显然就是一个 multiple-message-secure 的；我连更强的高手都能打得过，打你肯定能打得过。所以这边我们只是对 A 进行增强，A 只强不弱。

---

## 二、简化：把“发很多消息”改成“发两个消息”

老师指出定义里有个**臃肿的点**：每次发很多消息。做 reduction 时如果以这种形式，作为单个定义非常不简洁，所以做一个**取巧的简化**：

- 不再发一坨消息，而是**只发两个消息 M0*、M1***（要求长度相等）。
- 挑战者拿到这两个消息后，加密其中一个（按比特 b）返回密文。
- 这个简化**不损失任何安全性**：简化后的版本照样能包住（比增强版只强不弱），照样比原来强。如果简化损害了安全性，那肯定不行。

---

## 三、IND-CPA 的五个阶段（著名定义）

老师给出 IND-CPA 的完整五阶段定义（这是图灵奖得主 Goldwasser–Micali 提出的著名 notion）：

1. **Initial phase（初始化阶段）**：挑战者把 public parameter（安全参数、算法等）发给攻击者。
2. **Phase 1（询问阶段一）**：攻击者可以**任意询问**加密信息，message 完全由 A 自己选取（“你问我答”）。
3. **Challenge phase（挑战阶段）**：A 基于已有信息**选取两个消息 M0*、M1***（length equal）。
   - 关键：**M0*、M1* 完全可以跟 Phase 1 询问的消息强相关**——可以把 Phase 1 得到的密文直接放在 M0* 上、M1* 上，可以设成任何函数，“你想怎么搞怎么搞，我不做任何限制”。
4. **挑战者投 b**，加密 M_b* 返回给 A。
5. **Phase 2（询问阶段二）**：A 还不满意，**可以再来一轮“你问我答”**——看了挑战密文之后，还可以继续问、继续看，**很多轮，只要是多项式次**。
6. **Guess（猜测阶段）**：A 拿到全部信息后，输出猜测 b'。

老师强调：相比于我们一开始非常认可的 EAV 定义，IND-CPA **仅仅给 A 多加了 Phase 1 和 Phase 2 这两个东西**，其他完全一样。所以问题来了：**凭什么给 A 这个额外待遇？背后的原理是什么？**

---

## 四、为什么允许攻击者“选择明文”（Phase 1/2 的合理性）

**最朴素的加密应用认知**：Alice 和 Bob 通信，攻击者在旁边窃听；message 是 Alice/Bob 自己选的。攻击者“呆呆地”去窃听密文，**凭什么能看到他想看到的密文**？人家加密 M=100，你凭什么想让人家加密 M=1？按正常道理，你不应该看到 M=1 的密文。

**但现实中，攻击者有能力诱导 Alice/Bob 去加密他想要的信息**。老师举了**中途岛战役**的经典例子（这是 IND-CPA 思想的一个真实应用）：

- 二战中途岛战役时，白宫和海军司令部认知不一致：海军认为日本要攻击中途岛，白宫认为另一个岛，不确定该集中防守哪里。
- 美军在窃听到的日本海军密文中，经常看到一个加密符号 **“AF”**，但不知道 AF 对应什么明文（无法解密）。
- 于是美军**散布假消息**：中途岛缺少淡水（或电力）。
- 随后收到日本电文：“**AF is short of water**”——通过这个“钓鱼执法”，确定了 AF 代表的就是中途岛。
- 所以美军在中途岛集中防守，赢得了战役。

**结论**：攻击者确实有人文手段（钓鱼、诱导）使用户加密相应的明文。现实中真的有攻击者可以拿到他想要的密文。所以赋予 A 这个权利**并不过分，而且非常 nice、非常必要**。

## 五、IND-CPA 为什么能防住“确定性加密攻击”（high-level 直觉）

老师回顾之前的攻击：攻击者发两个消息——一个两条相等（M0=M0），一个两条不相等（M1≠M2）。如果是确定性加密，C1=C2；如果不是，C1≠C2，一眼就能区分。**IND-CPA 能不能防住这个攻击？** 如果连这个都防不了，那想都不要想。

**确定性加密为什么实现不了 IND-CPA**：

- 攻击者可以选取 M1 得到密文，再选取 M2 得到密文；然后把 M0* 设为 M1、M1* 设为 M2，观察挑战密文和哪个相等，就能判断是哪个。
- 换句话说，IND-CPA 在抵抗这种攻击时没问题。

**IND-CPA 好的核心原因**：

> 因为 M0*、M1* 的选取完全可以跟 Phase 1 询问的消息**强相关**，所以你加密的时候也必须做到：**即使加密同一个消息，加密出来的密文必须长得完全不一样**。如果消息加密的也是 M1，那么这个消息和这个消息必须看起来非常不一样才行，否则一眼能看出来。**即使对于同一个明文，用不同的随机数加密出来的密文必须长得非常非常随机**——这就是 CPA 的好处，也是 IND-CPA 的 high-level idea。

老师强调：这只是 high-level 直觉，我们的目标是 multiple message security（reuse），必须证明 IND-CPA 真的能保证 multiple message security，才能真正被 convince。

---

## 六、证明策略：找一个与 IND-CPA 等价、且一眼能包住 multiple message 的新 notion（LR-CPA）

老师说明：证明 IND-CPA ⇒ multiple message security 有无数种方法，这里只展示其中一种。

**策略**：找一个**新的 security notion**，满足：

1. 它与 IND-CPA **等价**；
2. 它**一眼就能包住（严格强于）multiple message security**（即如果满足这个 notion，就显然满足 multi-message）。

这个 notion 就是 **LR-CPA（Left-or-Right CPA 游戏）**。

### 6.1 LR-CPA 的结构（三个阶段的交互式游戏）

LR-CPA 本质上也是**三个阶段**（和 multiple message 的“三个阶段”对应）：

1. **初始化/挑战阶段**：挑战者自己**先把 sk 和 b 都选好**（b 是挑战比特）。
2. **交互式 challenge phase**：A 发送 M0_1、M1_1，挑战者回答 **Enc(sk, M_b1)**（即按 b 选左边或右边加密）；A 根据密文再选 M0_2、M1_2，挑战者回答 Enc(sk, M_b2)；……一直到第 q 个，回答 Enc(sk, M_bq)。
3. **Guess**：A 输出 b'。

**与 multiple message 的区别**：

- multiple message 是**静态策略**：A 必须一次性把全部 message 准备好交上去。
- LR-CPA 是**动态策略**：A 看到密文之后，可以**一步一步调整策略**，再选下一组 message。
- 所以 LR-CPA 中 A 收到的信息就是“这一坨”叠起来，**A 只强不弱**（严格强于 multiple message）。

**逻辑**：如果 A 连 LR-CPA 都打不过（LR-CPA 安全），那显然 multiple message 也打不过（因为 LR-CPA 更强）。所以 **LR-CPA 安全 ⇒ multiple message 安全**。

### 6.2 证明 LR-CPA 与 IND-CPA 等价（reduction 方向）

**要证**：LR-CPA 和 IND-CPA **等价**。

老师特别讲了证明方向的“反直觉”之处，强调**严格走定义**：

- 要证的是：“如果 IND-CPA 安全，则 LR-CPA 安全。”
- 反过来说（逆否）：**如果存在攻击者 A 能攻破 LR-CPA，那么就存在 reduction 能攻破 IND-CPA**。
- 老师提醒：这个方向有点反直觉，不清楚时就严格把定义写下来、对照着走；还可以对照上节课 PRG 的 reduction。

**Reduction 的双游戏结构**（老师反复强调这是 reduction 的本质）：

> reduction 本质上在玩**两个游戏**：一个是他和真正的“金主爸爸”（外部挑战者）玩，一个是内部对 A 玩的游戏。做 reduction 时，**把左边的放到外面，右边的放到里面**。

具体到 LR-CPA ⇒ IND-CPA：

- **外面**：reduction 和 IND-CPA 的挑战者（金主爸爸）玩。
- **里面**：reduction 扮演挑战者，和攻破 LR-CPA 的 A 玩。
- 逻辑：如果 A 能以高概率攻破 LR-CPA，那么 reduction 就能以高概率攻破 IND-CPA。

### 6.3 Reduction 的详细步骤（逐步模拟）

老师一步一步展示 reduction 如何“骗”A：

1. **第一步（public parameter）**：IND-CPA 挑战者给 reduction 的 public parameter，**直接转发**给 A（不需要改装，因为这里不是改装 PRG，而是玩 IND-CPA）。
2. **第二步（生成 sk 和 b）**：正常 IND-CPA 中挑战者要自己生成 sk 和 b；现在 reduction **不知道 sk**，所以**假装有**这个 sk（“假装防锈的，假装有的，他没有真有”）。
   - A 说：你假装有没有问题我不管，我也不需要你给我 sk 的信息，但**你必须做好加密**——我发一个 M，你必须回答我。
3. **Phase 1 询问**：A 每次发送 M，reduction 需要回答 Enc(sk, M_b)。但 reduction 不知道 b，怎么办？
   - **策略**：把 M 同时作为 M0 和 M1 发给金主爸爸（即令 M0 = M1 = M）。**甭管金主爸爸的 b 是什么，他回答的都是 Enc(sk, M)**——通过这个简单策略就解决了。
   - 可以看到 LR-CPA 完全能把 Phase 1/Phase 2 发酵出来的新能力**包住**。
4. **继续询问 M2、M3……**：同样把 M 同时作为 M0=M1 发过去，拿到密文后直接转发给 A。
5. **Challenge phase**：A 发 M0*、M1*。reduction **直接把这两个甩给金主爸爸**（作为 IND-CPA 的挑战消息），金主爸爸返回 Enc(sk, M_b*)。
   - 注意：这里 reduction **自己投 b 的环节少了**——它把金主爸爸的 b 直接用了（“金主爸爸里面的秘密他全用了”）。
6. **Phase 2**：A 继续问，reduction 同样用 M0=M1 的策略回答（把同一个消息同时作为左右发过去）。
7. **Guess**：A 输出 b'。reduction 的策略是“**你猜什么，我猜什么**”（直接把 b' 作为自己的猜测），不做任何处理。

**概率分析**：

- 如果 A 赢了（b' = b），那么 reduction 也赢（因为 reduction 用的 b 就是金主爸爸的 b，A 猜对 b 等价于 reduction 猜对）。
- 所以 Pr[reduction 赢] ≥ Pr[A 赢] = 1/2 + δ（δ 是 A 攻破 LR-CPA 的优势）。
- 结论：reduction 的优势至少是 δ，δ 不小，所以 reduction 能攻破 IND-CPA。

老师强调：这个分析和上次 reduction 不太一样，但逻辑很直接——**A 赢显然这边就会赢**，因为用的东西完全一样。

## 七、核心难点：如何用“1 块钱”满足“无穷欲望”的攻击者（hybrid argument）

老师提出两个定义之间的矛盾点：

- 在 LR-CPA 里，A 可以**享受很多次关于 sk 和 b 的信息**（可以问很多次、花很多钱）。
- 但在 IND-CPA 里，A **只能问一次**（“只能花 1 块钱”）。
- 问题：**如何用 1 块钱去满足这个无穷欲望的攻击者？**

### 7.1 难点具体化

Reduction 的策略：

1. 第一步 public parameter 直接转发（没问题）。
2. Reduction 想依靠金主爸爸的能力，自己不生成 sk 和 b（“自己不确诊，不去产生这个 SK 和 b”）。
3. A 开始问 M0、M1：
   - 如果 M0 = M1，很简单，直接甩过去（同时作为左右）。
   - **但 A 为什么要听你的？M0、M1 是 A 自己选的，如果 M0 ≠ M1，你怎么伪装？** 你现在既没有 sk，也没有 b，但要回答一个 Enc(sk, M_b) 给 A——这是你的任务。
4. 金主爸爸（IND-CPA 挑战者）**只给你 1 块钱**：你只能发一次 M0、M1，拿到一个挑战密文后，他就进入“只回答一次”的模式。
   - 你可以“上来就把金主爸爸的所有钱花完”，满足 A 一次；但 A 是**无穷欲望**的攻击者，第二次问题就搞不定了，金主爸爸不再搭理你。
   - 你自己随机选 b 的话，怎么保证你选的 b 和金主爸爸的 b 相等？不相等就会很麻烦。

### 7.2 解决：用“时间换空间”——hybrid argument（混合论证）

**核心思想**：金主爸爸只让花 1 块钱没问题，但你挡不住我**玩很多次游戏**（不同的变种）。

- 比喻：**分期付款**——我第一天花你一块，第二天换你一块，一共 100 天就能换你 100 块钱。
- 把 LR-CPA 游戏**拆解成很多个 hybrid 游戏**，每个游戏只花一次金主爸爸的钱；合起来就组装成功了。

**Hybrid 游戏的定义**（把“回答左边还是右边”定死，不猜）：

- **Game Left**：甭管 A 怎么问，**全部回答左边的**（M0 的加密）。这是定死的，没有 b。
- **Game 1**：除了**第一个**回答右边的（M1），其他都回答左边的。
- **Game 2**：前两个回答右边的，剩下的回答左边的。
- ……
- **Game i**：前 i 个回答右边的，剩下的回答左边的。
- ……
- **Game Right**：**全部回答右边的**（M1 的加密）。

**关键对应**：

- **B = 0** 时，挑战者玩的是 **Game Left**（全部左边）。
- **B = 1** 时，挑战者玩的是 **Game Right**（全部右边）。
- 中间是各种 hybrid Game i。

**证明思路**：

1. 我们知道 **Game Left 和 Game Right 是 CI 的**（计算不可区分）——这正是 multiple message security 要证的（左信息的联合分布 vs 右信息的联合分布无法区分）。
2. 相邻两个 hybrid 游戏 **Game i 和 Game i+1 只差一个位置**（第 i+1 个消息从左边变右边）。
3. 每个相邻对都可以用**一次 IND-CPA 的金主爸爸的钱**来证明它们是 CI 的：
   - 对于 Game i 和 Game i+1，前 i 个消息都回答左边，第 i+1 个位置分别回答左/右，之后都回答左边。
   - 把第 i+1 个位置的 M0、M1 作为挑战消息发给 IND-CPA 挑战者，拿到挑战密文；其他位置的消息用“M0=M1 同时发过去”的策略回答。
   - 如果 A 能区分 Game i 和 Game i+1，就能攻破 IND-CPA。
4. 利用 **CI 的传递性**：Game Left ≈ Game 1 ≈ Game 2 ≈ … ≈ Game Right，所以 Game Left 和 Game Right 是 CI 的。
5. 于是 multiple message security 得证。

**老师比喻**：这就像小学中学里画**辅助线**——直接证 LR-CPA 搞不定太累，我们找一些中间体（hybrid）作为辅助线，帮我们解决问题。本质上是**用空间换时间**的打法：金主爸爸只支持多少，我就换多少个 hybrid；他支持一个，我就换一个；支持两个，我就挑两个。

老师强调：这是密码学中**非常常规、非常非常重要的技术（hybrid argument）**，将来想做密码学的话必须吃透。

## 八、总结与下节课预告

- 通过上面的证明，我们知道了 **IND-CPA 和 LR-CPA 等价**；而 LR-CPA 显然（一眼）**包住 multiple message security**。
- 所以 IND-CPA 是一个**好东西**，满足了我们第二阶段的需求（multiple message security / reuse），并且定义简洁。
