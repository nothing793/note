## 一、开场：回应上节课 CI 定义的疑问

老师先解答上节课（或课间）同学关于 CI 定义的问题：

- 挑战者（challenger）先把**两个分布**告诉攻击者——这是必须告诉的，不能不给。
- 攻击者自己选一个 n（安全参数），然后挑战者**自己投一个比特** b（0 或 1），从对应分布采样，把采样结果给攻击者。
- 攻击者输出一个猜测比特 b'，猜“你给我的样本来自左边还是右边”。这个比特跟分布本身没关系，只是猜左右。
- 这就是关于 CI 定义的一个具体解答。

## 二、继续：用 PRG 实现加密（第一阶段目标）

上节课我们有了一个非常强的工具 **PRG（伪随机数生成器）**：从短的种子生成长的、看起来随机的串。

**回顾 one-time pad**：加密就是 m ⊕ k（简单异或），其中 k 是**纯随机**字符串——在 perfect secrecy 的定义里，密钥生成算法从 {0,1}^n 里均匀随机取 sk。

**简单的替换**：如果我们有了 PRG G，就把它替换成**伪随机字符串**：

- **密钥生成**：sk 是 n 比特字符串（从 {0,1}^n 取）。
- **加密**：c = m ⊕ G(sk)。
- **解密**：m = c ⊕ G(sk)。

**和 one-time pad 相比只改了一个地方**：把真随机字符串换成了伪随机字符串，其他什么都没变。

**好处**：

1. **正确性**很好验证。
2. **长度扩张**：G 是 PRG，输入短（n 比特）、输出长（L(n) 比特，L(n) 严格大于 n）。只要输出比输入多一个比特，PRG 就可以“想怎么着怎么着”（但不能太过分，L 还是 polynomial 的）。
3. **伪随机性（pseudorandomness）**：G 的输出看起来随机。
4. **消息空间扩张**：消息空间从 n 比特变成 L(n) 比特（因为 m 和 G(sk) 异或，消息可以到 L(n) 比特）。
5. **密钥比消息短**：密钥只有 n 比特，明文可以到 L(n) 比特，且 L(n) > n——这正好满足第二节课提出的、我们非常想要的“密钥空间小于消息空间”的目标（第二节课说的是密钥不小于消息空间是“不好的点”，现在反过来了）。

**直觉上的安全性**：G(sk) 这块看起来随机，所以它是个不错的 mask；加密后密文也看起来随机。但老师强调：**这只是直觉，不是证明**，下面要做严格的 reduction。

## 三、三个要素：assumption + definition + reduction

老师强调：provable security 必须有三个元素，希望大家有 sense：

1. **Assumption（假设）**：这里 assumption 就是“G 是一个 PRG”。我们这个算法的安全性依赖于 G 是 PRG；如果 G 不是 PRG，我们不知道它是否安全，我们也不 care——我们只说“如果 G 是 PRG，那么怎样”。
2. **Definition（定义）**：上节课讲的窃听安全游戏（EAV/IND 类），再完整复习一遍。
3. **Reduction（归约）**：这次是**人生中第一次**正式讲 reduction（如果之前没学过复杂度归约的话），会讲得非常非常慢，有任何不懂一定要提。

## 四、复习定义一：Perfect Secrecy 与“诱导分布”

**Perfect secrecy 的定义**：对任何 M1、M2，由 M1 导出的密文分布与由 M2 导出的密文分布**完全一样（identical）**。

**“由 M 导出的分布（induced distribution）”**——老师特意重新解释（因为很多同学默认知道，其实不知道）：

- 密钥生成算法 kg 输出 sk，sk 本身是一个分布（如 sk1, …, skn 每个均匀）。
- 固定一个 M，加密算法 Enc(sk, M) 的输出 c 的分布，就是“**由 M 导出的分布**”——它完全依赖于 sk 的分布，唯一的变量是 sk，再叠加 M 的加密。
- 例如：如果 kg 的分布变成了某个固定值，那么诱导分布也相应变成固定的；如果 sk 是什么样，密文就是什么样，两边完全绑定。

**Perfect secrecy 就是用“分布完全一样”这把精细的尺子来衡量。**

---

## 五、复习定义二：计算不可区分（CI）与 EAV 游戏

**CI 版本**：对任何 M1、M2，由 M1 导出的分布与由 M2 导出的分布是 **CI（计算不可区分）** 的。

- 老师比喻：我们买不起“完全一样”这把精细的尺子，就换了一把**看起来有点模糊、但能接受的尺子**——主体框架没变，只换了一把尺子。
- 因为我们已经花了很长时间接受 perfect secrecy，又花了很长时间接受 CI，从直觉上看这是对的。

**等价的 game-based 定义（EAV 游戏）**——更 base、有两个人（挑战者、攻击者）：

1. **第一步**：把 public 信息（加密算法怎么做、kg 怎么做、conversation 怎么做）全部告诉攻击者——符合 Kerckhoffs 原则（“客户服务原则”）；具体选的 sk 是什么不告诉。
2. **第二步**：挑战者选一个安全参数 n（“选一个 q partner/安全参数”）。
3. **第三步**：挑战者选取一个 sk（不告诉攻击者）。
4. **第四步**：攻击者选取 M0、M1（长度相等；以后默认，不再强调）。
5. **第五步**：挑战者自己投一个比特 b ← {0,1}。
6. **第六步**：b=0 时给 Enc(sk, M0)，b=1 时给 Enc(sk, M1)。
7. **第七步**：攻击者输出猜测 b'。

**等价性原理**：sk 是随机选的，所以 Enc(sk, M_b) 这个值可以看成**从第一个分布（M0 导出）或第二个分布（M1 导出）里的一次抽样**。如果 A 无法区分这两个值到底来自哪个分布，就说明它们是 CI 的。所以 EAV 游戏和 CI 定义本质等价。

**优势（advantage）**：A 至少有 1/2 概率赢（瞎猜）。我们怕的是“比 1/2 高很多的概率赢”。定义 advantage = |Pr[A 赢] − 1/2|；如果这个值是可忽略的（小的），就说算法是 EAV 安全的。

**PRG 的 game-based 定义**（与 CI 完全共通）：

1. 第一步：把安全参数和算法 G 全部公开（G 的 code 完全知道，唯一不知道的是选的是哪个 seed）。
2. 第二步：挑战者从 {0,1}^n 采一个 x，从 {0,1}^{L(n)} 采一个 y（纯随机）。
3. 第三步：挑战者投一个比特 b；b=0 给 x（即 G 的抽样），b=1 给 y（uniform 抽样）。
4. 攻击者猜 b'。

如果 A 无法区分，就说明 G(x) 与 uniform 是 CI 的——这就是 PRG 的 game-based 定义。

老师强调：**希望大家从各个角度理解，把定义内化**，不要只读书上的定义、不往深里想。这堂课就是帮大家内化，并分享老师读书时的认知技巧。

## 六、Reduction 的核心思想：外包公司比喻

现在有了 assumption（G 是 PRG）和 definition（EAV 安全），要做 reduction：

**要证**：如果 G 是 PRG，那么我们的构造是 EAV 安全的。

**Reduction 本质上是一个“外包”**：

- 假设有一个非常厉害的人 A，能干碎 EAV 游戏（能区分密文）。
- 我们（reduction）把他“包下来”，当作外包公司的员工：对外我们是**乙方**接活（接 PRG 挑战者给的活），对内我们是**甲方**，把活交给 A 去做。
- 换句话说，reduction 有**两个身份**：外面是乙方（接 PRG 的挑战），里面是甲方（指挥 A）。
- 核心：**把甲方给的任务和 A 能处理的任务对接（match）起来**——A 的能力变现为解决我甲方问题的能力。
- 如果 A 能打碎 EAV，我就能利用 A 的能力去打碎 PRG（拿到奖/解决公开问题）。

老师强调：A 是非常敏感的——**你只要让他感觉不爽，他自杀**（不玩了）。所以 reduction 每一步都必须精确处理，保证 A 看到的分布和他真正玩游戏时看到的分布**完全一致**；否则 A 不玩了，你最后依赖他的输出，你就完蛋了。以后的 reduction 不会像这次这么简单，员工必须精细对待。

---

## 七、Reduction 的详细步骤（B=0 的情形）

**目标**：如果 A 赢 EAV 的 advantage 是 δ，那 reduction 打碎 PRG 的 advantage 也是 δ（可能有 loss，但只要不太小就行）。

**Reduction 流程**：

1. **甲方（PRG 挑战者）给 reduction**：public parameter（加密算法、G 等）——第一步全部告诉 A（因为 Kerckhoffs 原则）。有了算法，加密/解密算法就有了，具体 sk 不知道。
2. **A 开始发力**：A 选 M0、M1。
3. **问题**：reduction 要加密，但**没有 sk**，怎么产生密文？
   - 正常情况下有 sk 才能加密，但现在 reduction 是“甩手掌柜”，没有密钥。
   - 本质：**reduction 要在没有密钥的情况下把密文加密出来**——这是它必须做的事情。
4. **解决办法**：甲方（PRG 挑战者）并不是啥都没给——它给了一个 string（样本）。
   - 当**B=0** 时，甲方给的 string 就是 **G(x)**（x 是甲方选的 seed）。
   - 我们知道 sk 是加密的充分条件，但**不是必要条件**——知道 G(sk) 也能加密，不一定要找到 sk 本身；找一个更弱的充分条件就行了。
   - 所以当 B=0 时，reduction 直接用甲方给的 string（即 G(x)）作为 mask，**假装它是 G(sk)**，加密得到密文给 A。
5. **模拟的正确性**：当 B=0 时，这个 string 就是 G(x)，x 是均匀分布的 n 比特，所以它和“从 G(sk) 分布里抽样”**完全一致**（exactly）。A 看到的流程和真实 EAV 游戏**百分之百一致**——reduction 完美模拟了 EAV 游戏。
6. A 最后输出 b'。reduction 拿 b' 做什么？

---

## 八、Reduction 的输出策略与概率分析

**策略**：reduction 不是纯白痴外包（接活赚差价），它要对 b' 做二次加工：

- 如果 **b' = 我（reduction）自己投的 b**，我就认为甲方给的是 G(x)（伪随机），输出“伪随机”；
- 如果 **b' ≠ b**，我就认为甲方给的是纯随机（uniform），输出“随机”。

**为什么这样猜**：

- 当 B=0 时，A 玩的是真正的 EAV 游戏，A 赢的概率 = 1/2 + δ（δ 是 advantage）。
- 当 B=1 时，甲方给的 string 是纯随机，A 玩的是 one-time pad 游戏（完美安全），A 的 advantage = 0，A 赢的概率 = 1/2。
- 两个 game 之间有 gap（δ），用 A 的输出作为锚点来区分：A 经常猜对 → 更可能在玩 EAV 游戏（B=0）；A 猜错 → 更可能在玩 OTP（B=1）。

**概率计算**：

- Pr[reduction 赢] = Pr[B=0] · Pr[A 赢 | B=0] + Pr[B=1] · Pr[A 输 | B=1]
  = (1/2)(1/2 + δ) + (1/2)(1/2)
  = 1/2 + δ/2。

**结论**：如果 A 有 δ 的 advantage 赢 EAV，reduction 就有 **δ/2** 的 advantage 赢 PRG 游戏。

- 这里有一个 **loss（损失）**：δ 变成 δ/2。但只要 δ 是不可忽略的，δ/2 也是不可忽略的（除非 δ 小到可忽略，那就无所谓了）。
- 所以：如果 PRG 是安全的（不存在能赢 PRG 游戏的 PPT 攻击者），那么这样的 A 不存在，我们的构造是 EAV 安全的。**第一阶段目标达成**。

---

## 九、重新审视定义：EAV 够不够？——reuse 需求

第一阶段达成后，重新看定义哪点值得往下跑：

- EAV 定义里，**A 只允许 make inquiry 一次**（只加密一次）——因为我们的构造完全脱胎于 one-time pad，继承了 “one time” 的属性。
- 但现实中我们**更希望**：密钥定死之后可以**多次使用（reuse）**——用同一个密钥加密第一条、第二条、……第 q 条消息。我们不希望像 OTP 那样只能用一次。
- 虽然追求短密钥（密钥是密文的 1/2，确实短了），但只能用一次很不爽；密钥长度和密文线性相关也不爽；我们希望**密钥是常数值，定死之后随便加密多少条消息都用它**。现实中不可能家里加密 10G 数据还要保存 1G 的密钥。
- 所以第二阶段目标：**在有短密钥的情况下实现 reuse（密钥重用）**。

---

## 十、Reuse 的定义：联合分布的计算不可区分

**如果实现 reuse，定义应该长这样**：

- 对任何消息序列 M0_1, …, M0_q 和 M1_1, …, M1_q（q 是 polynomial），
- 由第一个序列（M0 序列）**在同一 sk 下**导出的**联合分布**（sk, Enc(sk,M0_1), …, Enc(sk,M0_q)），
- 与由第二个序列（M1 序列）在同一 sk 下导出的联合分布，
- 二者是 **CI（计算不可区分）** 的。

**关键点**：

- 不再是单一分布，而是**联合分布**；
- 所有 sk 都是**同一个、定死的 sk**（exactly one sk），不是每次独立采样；
- 这是“由 message sequence 导出的联合分布”，两边对比。

如果构造满足这个条件，我们就比较 confident 它支持 reuse——因为每次用的 sk 都是一样的，只是选取不同的 message。

**Game-based 版本（升级版 EAV）**：

1. 公开 public parameter（把那一坨公开信息用 pp 代替，不再全部写出）。
2. 挑战者产生 sk。
3. 攻击者输出两个 message sequence（M0 序列、M1 序列）。
4. 挑战者投 b；b=0 时用**同一个 sk** 加密 M0 序列，b=1 时用**同一个 sk** 加密 M1 序列。
5. 攻击者猜 b'。

这和上面 CI 定义完全等价，只是做了一个扩张（从单条消息到序列）。

---

## 十一、EAV 构造为什么实现不了 reuse：确定性加密的问题

**新能力/新攻击**：A 现在可以选 message sequence，能做哪些“坏事”？

- 关键：如果加密算法是**确定性算法**，那么同样的 message 加密出来**完全一样**（exactly the same）。
- A 可以在第一个 sequence 里让前两个块一样，在第二个 sequence 里让前两个块不一样；然后观察：如果密文前两块一样，就说明是第一个 sequence（M0）；如果不一样，就是第二个 sequence（M1）。
- 虽然不知道密钥是什么，但**绝对能区分**——这就能以很大优势赢游戏。

**结论**：

- **确定性加密百分之百实现不了 multiple message 安全（reuse）**。
- 这也是为什么第一堂课说：密钥生成一定是随机算法；解密在绝大多数情况下是确定性算法；**加密算法可以是确定性的也可以是随机性的，但我们推荐随机性的**——这里给出了很大的理由。
- 多重消息安全（multiple message）对标的正是 reuse 需求；想实现 reuse，用确定性算法就是实现不了。
- 老师补上第一堂课留的“坑”的补丁。

## 十二、第一次尝试随机化：直接加随机数——为什么不行

目标明确：**随机化加密，引入随机数**。

**尝试 1**：简单粗暴地把随机数 r 也 XOR 进去：c = m ⊕ G(sk) ⊕ r。

- **问题：无法解密**。解密时只有 sk 和 c，没有 r；解密算法只有那两步，拿不到 r，所以不行。

**尝试 2**：把 r 直接甩给解密方（把 r 也放进密文）？——老师继续分析这种“更粗暴”的做法。

具体设定：

- G 从 n 比特到 L(n) 比特，L(n) > 2n；
- r 从 {0,1}^n 随机选，sk 从 {0,1}^n 选；
- 密文包含 r 和 m ⊕ G(sk)（或类似形式）。

**看起来对，但问题在哪？**

- 在 PRG 游戏里，攻击者**只看到 G(x)**，不允许看到关于 seed x 的任何信息。
- 但在我们的构造里，攻击者看到了 r（一半信息），这相当于**泄露了 seed 的一部分信息**。
- PRG 的安全性只保证“**你完全不知道 seed 时**，输出是伪随机的”；一旦泄露一部分信息，PRG 什么都保证不了。
- 具体攻击：令 G'(sk‖r) = r ‖ G(sk)。这可以构造出一个“新 PRG” G'，但 G' 的前 n 比特直接就是 r，完全泄露——说明“泄露一部分后仍伪随机”不是 PRG 能保证的。
- 更形式化：如果做 reduction，要把 r 做出来；但 PRG 游戏不给 r，reduction 无法模拟，义务变重了，match 不上。

**结论**：这条路不行。我们需要**进一步升级工具**：

> **即使一部分（比如 r）泄露出来了，剩下的部分（mask）仍然是伪随机的**——只要 sk 没泄露。

这是下一阶段的目标：开发下一款“共聚产品”，即更强的 PRG 变体（后续会讲，比如伪随机函数 PRF、或者能抵抗部分泄露的 PRG 等）。

## 十三、总结与下节课预告

- 本节课完成：用 PRG 构造 EAV 安全加密，并做了完整的 reduction（δ → δ/2）。
- 发现 EAV 只支持一次加密，不满足现实的 reuse 需求；reuse 的定义是联合分布的 CI。
- 分析发现：确定性加密无法实现 reuse；直接加随机数会泄露 seed 信息，PRG 保证不了。
- 下一步目标：升级工具，使得**即使一部分信息泄露，剩余部分仍伪随机**（只要 sk 不泄露）。
