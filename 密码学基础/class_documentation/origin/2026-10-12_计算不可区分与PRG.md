## 二、回顾：为什么必须走 assumption 这条路

1. 第二节课提出了一个非常好的 notion，叫 **perfect secrecy（完美保密）**，但实现它需要一个额外限制条件：**密钥空间不小于消息空间**（|K| ≥ |M|），这是已学知识。
2. 所以如果要设计一个好的加密系统，必须走 **assumption（假设）** 这条路径，或者说在 provable security 里就放在这儿。
3. 一开始走的路线是“直走”：只有一条线在门内，即“1+1=2”式的公理路线。我们找到了好的 definition，也证明了能做到，但它有一个 drawback（缺陷）——效率问题，不能接受。
4. 于是退而求其次，**引入 assumption 和 reduction**。
5. 上节课给出了第一个版本的 **one-way function（单向函数）**：一条线好过、不好回来，有单向性。并讲了：
   - 为什么要想 one-way function；
   - 几种 one-way function 的变种；
   - 从复杂度上的解释、从框架上的解释。
6. 现在等于说**已经有了新工具**，看看能不能用它去实现我们的目标（goal）——构造好的加密系统，且要求 **K 远远小于 message space**。

## 三、补充 one-way function 的性质（为构造做准备）

在做构造之前，先对 one-way function 的 property 做更细致的阐释（上节课没讲清楚的补充）：

**性质一：one-way function 只保护“全部信息”，不保护“部分信息”。**

- 直觉上单向函数不会泄露 X 的信息，但**看定义要仔细**：one-way 的定义是“不泄露你的全部信息”。
- 形式化地：不存在 PPT 攻击者，给定 f(x) 能找到一个 y 使 f(y)=f(x)（概率不可忽略）。也就是说，攻击者不能“完全还原”某个原像。
- 含义推导：哪怕攻击者能还原出 X 的 **1/2、1/3、1/5、4/5** 甚至很大一部分——只要还有那么一部分没被挖掉、没被攻破，它就仍然是 one-way 的。换句话说，**经过 F 之后，攻击者可以回答出前面那些比特，但后面的东西怎么都搞不定，它也是 one-way 的**。
- 结论：one-way function **只保证全部信息不泄露，不保护部分信息**。

**性质二：f(x) 不需要长得很 random，可以有结构（structure）。**

- 如果 F 是 one-way function，那么加一些结构/变换后的函数是不是 one-way？显然也是。
- 它可以用无数个 structure 去换掉 output，可以没有任何“保干净”的要求；**不必长得很随机、不必长得很好，可以很 weird、很有结构，只需要有些部分是好的就行**。
- 举例：一个 one-way function 的**第一个比特可能是定死的，第二个比特也可能定死**，只要某些部分比特比较“泛”就可以了。

老师强调：这两点（只保护全部信息、可以有结构）正是**直接用 one-way function 构造加密时会出问题的地方**。

## 四、直接尝试用 one-way function 构造加密：为什么不行

假设 F 是 one-way function，尝试构造：密文 c = F(sk)（或类似形式），看行不行。

**问题一：无法解密。** 拿到 sk 之后完全没办法解密（因为 F 不可逆，sk 本身也被“单向”掉了）。

**问题二：F 可能泄露全部信息（把 message 全干出来），但 sk 干不出来。** 即攻击者有可能把消息全还原出来，而这正是我们不能接受的。

所以**直接用 one-way function 肯定不行**。

## 五、回顾 one-time pad 的思路：把密钥分成“mask”和“好用的部分”

回顾之前（one-time pad）是怎么做的：

- 不是把 sk 和 message 当成一坨直接塞进去，而是可以看成**两个部分**：
  - 一部分可以看成一个 **mask（掩码）**；
  - 另一部分可以看成“好的东西/皮”，把消息包起来。
- 按照这个思想，我们要做的是：**把 mask 换个样子**，完全 follow 一次一密的格式。
- 具体地：把 sk 里这个“好的皮”换成**一层新的皮**——用 one-way function 生成的东西来做 mask。行不行？

**对照刚才讲的两点问题分析：**

- 多次使用问题不是核心（可以展示用几次，小问题）。
- **核心问题**是：F 的结构可能是固定的（比如前面全是 1，后面是什么东西），那么 M 异或（XOR）上 S 之后，**S 的前面部分全部被干掉了**，M 的前面这些比特就**没有任何保障**——这不能接受。
- 写成 G 更好理解：如果 G 前面全是一，那么 M 的前面的比特没有任何保障。

**结论**：one-way function 挺好，但在构造加密这个目标上，“in some fashion”还是不够。我们之所以考虑 one-way function：第一，必须考虑 assumption；第二，考虑 assumption 时必须有个“根儿”——这个根就是从 DCS（决策/复杂度）里、从 P≠NP 那个“口碑/信仰”里出来的 one-way function，是最接近信仰的“大表哥”。找到它没问题，因为它和 P≠NP 最近；但**它不够（insufficient）**，还是要对它进行**升级**。

我们的核心目的是构建一个 **sufficient** 的东西，最好是最重要的；做不到最重要，至少要做到充分条件——不能只罗列实现目标的必要条件，必须给出充分条件。

**两条路线的判断：**

- 直接拿 one-way function 当加密：**无法解密**，注定这条路不容易走通。
- 另一条线：它有 one-way 方面的印证，**有可能是条路子**，“现在长得下来像个人样”，我们按这条线走。这条线的问题在于 **structure**。

## 六、做梦/蓝图：需要“看起来随机”的东西

如果有一个 function，使得它**没有 structure**，比如看起来像纯随机——纯随机肯定不行（“王太太多了”=随机性太多/太强），先不说伪随机这么专业的词，用最最简单的“人话”：**看起来自己看起来随机的东西**。

如果我们有一个方法可以把某个东西弄成一个**看起来随机**的东西，把它当做 mask，我们就比较安心了——至少看起来这是能走通的路。

**目标（blueprint）**：搞一个看起来随机的东西，希望它有两点：

1. **不可区分性（indistinguishability）**：看起来随机；
2. **输出比输入长（length extension）**：f(sk) 的长度要大于 sk 的长度。如果 sk 长度不够大，我们直接用它在 OTP 里就行了，何必绕一圈给自己找麻烦？

记住目标：构建一个好的加密系统，**shorter security（更短的密钥/更短的安全参数）+ 上述两点**都必须有。

**关于“structure”的澄清**（同学提问）：

- 结构不一定指代数结构；前面 100 个比特全是 1，这也是结构（固定的东西）。
- 代数结构是更窄的说法（比如群/环上的运算）；一般说 structure 是比较宽泛的名词，指比较固定、不太好的东西出现了，看起来不随机。

## 七、如何精确定义“看起来随机（random-looking）”

### 7.1 先限定攻击者：PPT

- 什么叫 random-looking？先看谁在看：**超强计算能力**的攻击者能区分，那不就成 perfect 了吗？不行。
- 比喻：一个人高度近视，戴上非常精妙的眼镜能区分“谷子”和“米”；但如果配不起好眼镜，从地摊上买 10 块钱 2 斤的眼镜，就分不清。**超强攻击者 = 好眼镜**，我们搞不定；所以退而求其次，**只带 10 块钱眼镜的攻击者 = PPT 攻击者**，我们搞得定。
- 所以 random-looking 里的“looking”首先限定在**计算能力有限**：在 **PPT 下无法区分**。
- 形式化含义：对于任何多项式时间的攻击者，无法区分，区分优势（advantage）大于某个常数/多项式分之一？不——是**很小很小**，但不一定是均匀分布。攻击者输出 0/1，看他对分布的反映。

### 7.2 从“不 random”的例子反推

先说什么**不是** random（逐步逼近）：

- 例 1：0 和 1 的比例不一样（random 的东西希望 0 和 1 各占大约 1/2，不要求 exactly 1/2）。
- 例 2：满足比例大约 1/2 了，但某个 pattern 的比例不对——**任何 pattern 的比例都要差不多**。
- 例 3：更长/更复杂的模式，比如某些块的比例不对等。

但要小心：**把一眼假的东西去掉，剩下的不一定是真的 random**。比喻：一个瓷器上写着“微波炉专用”，肯定是假的；但一个瓷器上没写“微波炉专用”，也不一定就是古董。所以这些例子只是帮助思考，不是定义。

### 7.3 关键启发：两个分布之间的关系

回顾超强攻击者下什么做不到：**如果两个 distribution 是 identical（完全相同）的**，从这儿采样一个变量和从那儿采样一个变量给他，**超强攻击者也区分不出来**（即使再强也做不了）。

这给出一个启发：**考虑两个分布之间的关系**。如果攻击者无法区分这两个分布，那就好了——这是一个比较可能的方法，去画这个圈子（定义 random-looking）。

老师强调：前面这些例子**纯粹是帮助思考**，不是定义；思路是：从最简单的入手，感受不行的点在哪里，再尝试刻画行的点。

### 7.4 计算不可区分（Computational Indistinguishability, CI）的直觉

- 画一个 reduction 图：一个简单的 copy，从这儿外包，用普通的“无法区分”。
- 如果伪随机（pseudorandom）把它当 uniform，这是完全 mimic 以前做过的事情，只是把 AI（攻击者）换成拿到里面的东西。
- 先把这个 high-level 甩出来，大家觉得直觉 match，再细化。

**两个必须考量的因素**（因为攻击者是 PPT，不是无穷算力）：

1. **攻击者的运行时间**；
2. **地址/问题的规模（security parameter 的规模）**。

老师用两个小游戏/图让大家体会：

- 第一个游戏：给你 10 秒钟找不同点，可能找不到；给 1 分钟就可能找到。说明**运行时间必须精确考量**——问题规模可能是一分钟级别，但 10 秒钟就是搞不定。
- 第二个游戏：找相互 overlap 的点是 3 个还是 2 个，规模小的时候一眼真、数一下也行、10 秒差不多；规模变大就痛苦了。说明**固定时间下规模也很重要**。

结论：必须搞一把**尺子**，精准衡量攻击者的时间（不能简单说它是一个 T），也要精准衡量问题的规模。以后这堂课只会用 PPT。

## 八、安全参数（security parameter）

回顾第一堂课留的“坑”：给 generation 的输入，当时说这里有个坑先不管。今天讲清楚该把什么东西放进去。

- 为了刻画“攻击者时间”和“问题规模”这两个变量，分布不能再是固定分布，必须是**变量性的**，要用一个**参数**来处理。
- 定义 **安全参数（security parameter）**，通常用 λ（“栏目的/拿不拿/拉不到”）或 n 表示。
- 交叉验证：AES-256、RSA-2048/512 里的 256、512 就是安全参数。
- 第一节课的坑就变成：generation 输入 **1^λ**（“一天 35/打一天 35”即 1^λ），只打这个，产生的 sk。
  - 正常情况：从 λ 比特里取 1 个 sk（most case，不是所有 case）。
  - sk 的 size 至少是 λ（安全参数）。
- **AES-256 的含义**：这份设计可以抵抗**现阶段最好的攻击算法**，并且这些攻击算法的复杂度至少是 **2^256**（要攻破至少做 2^256 次运算）。前提条件：**best known**——只是现阶段人类能想出来的最好算法，没准明天 AI 就把它干碎了，这不知道。但设计安全参数时，从安全层面讲，涵盖的就是“现阶段已知最好攻击的复杂度是 2^λ”。
- 第二个作用：用安全参数作为**统一的尺子**去衡量问题的规模。
  - 回顾 PPT 定义：对每个固定的 A，总有一个常数 c（Q）；现在用这把尺子衡量问题规模。
  - 定义成一个 **family of distributions / ensemble**（分布族），不是单个分布，而是**由 index/参数 n 索引的分布序列（sequence of distributions indexed by n）**。选取 n=λ 时考虑对应分布；n 变大分布变复杂。

老师解释“为什么可以这么定义”：如果两个东西定死，就引入不了规模；而例子说明规模很重要，所以必须引入。index 只是为了和参数配平——**N 越大分布越复杂，只是正相关，不一定是 2^N**。

## 九、计算不可区分（CI）的形式化定义

**定义（CI）**：两个分布族 {X_n}、{Y_n} 是计算不可区分的，如果存在一个**可忽略函数 negl**（上节课定义的 negligible），使得对于**任何 PPT 攻击者 A**：

|Pr[A(X_n)=1] − Pr[A(Y_n)=1]| ≤ negl(n)

（即“这个概率减去这个概率是小的”。）

**几个关键澄清：**

1. **为什么只考虑“等于 1”而不考虑其他输出？** 因为输出 0/1 就足够了；输出多个也可以，但可以包装成一个比特（留作作业/思考）。攻击者本质上做的是**区分（distinguishing）**。
2. **不要求概率等于 1/2。** 很多人有误区，以为必须等于 1/2。实际上：把其中一个概率想成**基线 baseline**，我们要求的是“你能在基线上的提升是小的”，当参数足够大时。绝对值是多少不 care，只 care **差（gap）**。
3. **negligible 只在 n 足够大时有意义**：n 小时我们没做任何声明（n=1 时没有任何限制）。这是很多人（包括老师交流过的学生）的认知误区，要直接纠正。
4. **攻击者只调用一次分布**（定义里是对分布采样一次）。如果调用多次（比如给 X_1…X_p 都从分布采样）会怎样？这是留的问题——通过传递性/hybrid argument 可以处理，多调用与单次调用本质等价（“看一次和看 polynomial 次一样”）。

**CI 的美妙之处：传递性（transitivity）。**

- 如果 X ≈ Y 且 Y ≈ Z，则 X ≈ Z。以后就可以进行拆分（hybrid argument）。
- 老师演示：用 hybrid 序列，相邻两个只差一处，每个相邻对都是 CI 的，通过传递性得到首尾也是 CI 的。

**回应“攻击者只能看一眼不爽”的质疑：**

- 有人觉得定义里攻击者只能看一次太弱小，应该让他看很多次才 mining for。
- 但通过传递性可以证明：**看一次和看多次（polynomial 次）本质等价**，所以这个定义是精妙的，不是缺陷。
- 老师留了作业/思考：让 A 输出 stream、只输出一个比特，也是一样的；多调用也等价。大家通过怼定义来加深理解。

**老师对“怼定义”的态度**：给出定义后要批判性检验（“捶他”），从不同角度问。如果怼了没被反怼回来，理解就增加一分；不怼是不对的。

## 十、伪随机数生成器（PRG）的定义

有了 CI 这个统一框架，定义伪随机就非常简单：

- 用尺子：输入是一个 λ 比特的种子（seed），输出是 L(λ) 比特（L 是多项式，且 **L(λ) > λ**，即扩张）。
- **伪随机性**：{G(s) : s ← {0,1}^λ} 与 **uniform {0,1}^{L(λ)}** 是**计算不可区分**的（CI）。
- 即：G 的输出“长得像”均匀随机。

**PRG 的两个条件：**

1. **扩张性（length extension）**：对任何 n（λ 足够大时），输出长度 L(n) > 输入长度 n。因为我们的 goal 是用 sk 生成 mask 去 XOR 消息 M，所以必须有扩张，不扩张没意义（直接用 OTP 就行了）。
2. **伪随机性**：输出分布与均匀分布计算不可区分。

**关于分布的澄清（同学提问）：**

- 分布由 X（种子）的分布导出：X 是 λ 比特均匀随机（1/2^λ 每个），所以 f(sk) 的分布就是种子均匀分布经 G 导出的分布。
- 我们要对比的是：**G(sk) 的分布**（sk 均匀）与 **uniform {0,1}^{L(λ)} 的分布**，二者 CI。
- 有人问“统计距离是不是很近”——**不是**！统计距离可能非常非常大（接近 1），如果有无限 power 一眼假；但在计算能力有限（PPT）下看不清楚。这就是“米和谷子在地摊眼镜下分不清”的比喻：统计距离很远，但计算不可区分。
- index/参数：G 是一个 family，由 n 索引；当 n 调大时输入输出一起调大，只是正相关，不要求 exact match。

## 十一、用 PRG 构造加密（第一次尝试）

现在武器升级完成（有了 PRG），尝试构造加密：

- 密钥 sk 是 λ 比特（n 比特）。
- 用 PRG 生成 mask：G(sk) 是 L(n) 比特，L(n) > n。
- 加密：c = m ⊕ G(sk)（m 是 L(n) 比特）。
- 解密：m = c ⊕ G(sk)。

**正确性**：显然成立（XOR 可逆）。

**密钥比消息短**：sk 是 n 比特，m 是 L(n) > n 比特，实现了 shorter key。

**难点：如何证明安全性？** 不能说“我用了 PRG 所以安全”——这只是直觉，绝对不能当 proof。provable security 必须给出 assumption + definition + reduction 三样齐全。

- 不能拿 statistical privacy（统计保密）来证，因为 PRG 本来就不是统计保密，跟它不沾边。
- 要证明构造安全，首先要给出一个**合适的、大家认可的 definition**，有了 definition 才能做 reduction。

## 十二、安全性定义：从 perfect secrecy 自然扩展

**方法**：从 one-time pad 里那个好的、被认可的定义（perfect secrecy）中**吸取灵魂**，取其精华放到这儿——因为它被很好地“粘”/验证过，作为一个好的 mimic 比较好抓。这是一个通用的方法（将来做测试也可以看别人怎么做再做一个相关类型的 mimic）。

**Perfect secrecy 的定义**：对任何 M1、M2，由 M1 导出的密文分布与由 M2 导出的密文分布是 **identical（完全相同）** 的。

**Natural extension + CI 工具**：把“identical”换成“**computational indistinguishable（CI）**”——对任何 M1、M2，两个密文分布是 CI 的。这是我们的思想。

**另一种更 base 的方法：Game-based definition（Q 币/游戏基定义）**——这是密码学里常用的方法：

- 两个角色：**攻击者 A** 和 **挑战者（challenger）**。
- 第一步：把所有 public 信息（包括 encryption 怎么运行、distribution 怎么运行等）全部告诉 A——符合 **Kerckhoffs 原则**（“客户服务原则”）。
- 第二步：体现“区分 M1、M2”。方法：**放权给 A**，让 A 自己选 M1、M2（要求长度相等；长度不等的话太容易区分了，我们不 care 这种事）。
  - 为什么让 A 选？因为领先的攻击者肯定找最容易区分的来；如果 best case 都区分不了，那 for all 都区分不了（worst-case 论证思路）。
- 挑战者自己投一个硬币 b ← {0,1}（“自己 free 一个 coin”），把 sk 给 A（或公开），加密 M_b 得到 c，把 c 给 A。
- A 输出猜测 b'；**A 赢**当且仅当 b' = b。

**这里反直觉**：看起来我们需要 A 不赢，但显然他能赢（猜对概率至少 1/2）。真正 care 的不是他赢不赢，而是他赢的概率**跟 1/2 的关系**：

- A 啥也不干（不看密文），猜对概率是 1/2（基线）。
- 我们期望 **advantage（优势）**：|Pr[A 赢] − 1/2| 是**小的**（可忽略）。即 A 不会比 1/2 多很多概率去赢；他啥都不干和费半天劲得到的效果几乎一样——那这个加密就非常非常对了。

这个 game 本质上体现的就是：**M0 和 M1 的两个密文分布是计算不可区分的**。以后写 definition 也建议尝试用 CI 的方法去理解，从各个角度去看会理解深很多。

## 十三、Reduction 的核心思想（时间关系只讲直觉，下节课详细推）

- 核心思想：**如果你能赢我这个 game（以较高概率区分密文），那我就能打掉你这个 PRG**（把 PRG 的伪随机性打破）。
- 即：如果你能以较高概率赢（优势不可忽略），那么我打破 PRG 的概率也是不可忽略的。
- 比喻：**外包公司**——你能干这个事情没问题，我作为外包公司把你买过来，用你 A 作为核心技术去解决 PRG 的问题；解决了我就 be famous 了。
- 但我们相信 PRG 是好的（安全的），所以这样的 A **不存在**。也就是说：如果存在这样的 A，PRG 也不行；如果相信 PRG 行，那这样的 A 肯定不存在——对所有 A 都不行。
- 下节课会一步一步详细推这个 reduction。

**老师最后的话**：前两年很多同学上完课对 reduction 没有任何 sense，后续 advanced crypto 课很多老师反馈同学对 reduction 没 sense。所以这次讲得慢，包括 CI、这些定义，关键是多“怼一怼”（从各个角度批判性检验），帮助大家思考引申意义。
