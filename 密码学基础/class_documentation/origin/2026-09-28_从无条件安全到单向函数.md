## 二、回顾上节课：从“无条件安全”到效率问题

上节课的路线：

1. 从 security 角度“死命地推”，希望从最坚实的基石出发——类似“坚信 1+1=2”这样的公理（老师称之为“公里”，即公理/axiom），在此基础上构建一个好的密码系统。
2. 上节课讨论了一个“无条件安全”（unconditional security）的定义：它不基于任何假设，是非常结实的东西。
3. 但发现一个很大的 bug：**效率（efficiency）非常差**。在无条件安全的情况下，可以很好地实现“1 和 2”（指某些安全目标），但“3”（效率）完全无法接受。
4. 所以今天要**往回退一退**：不再追求无条件安全这个级别，而是引入**假设（assumption）**，从而获得 1、2、3（安全 + 效率）。
5. 上节课已经知道：如果不引入假设，只能实现 1、2，实现不了 3；但现实中 3 是必须的，甚至可能比 1、2 更重要。

因此这节课**第一次走入 group 里面的 assumption 到底长什么样子**。老师提到大家可能听说过 RSA、离散对数等，但不会一上来直接讲那些（那些是公钥里用的东西），而是**从最底层模型慢慢推**，画一个基本的地图/框架，说明这些假设不是拍脑袋随便找的，而是从最原始的问题一层一层叠上去的。

老师强调：这门课不是教大家“别人给你一个方案你就在这边做”，而是希望大家**深度思考**——assumption 的选择也是需要深思熟虑的。

## 三、攻击者的刻画：为什么选多项式时间（PPT）

### 3.1 无条件安全下攻击者能力无穷大

- 说“无条件安全”时，攻击者的能力（power）是**无穷大**的：无穷计算能力、无穷存储能力，可以跑任何算法，包括量子算法等等。
- 举例：大数分解（给出两个大素数，给定 N，输出 P 或 Q）。在无穷算力攻击者眼中，大数分解和计算 1+1=2 是**等价**的，非常简单（枚举即可）。
- 所以必须**画一条线**，限制攻击者的能力，使假设有意义。

### 3.2 线不能画得太大，也不能太小

- **太大**（无穷算力）：大数分解没意义。
- **太小**：比如一个攻击者“甭管你输出啥，我都输出 1”——这是非常傻的 dummy，屁用没有；到这个级别连 1+1=2 都算不了，任何数都等于 1，也没意义。
- 所以要找一个**合适**的边界：既能涵盖现实中那些算法，又不能小到荒唐。

### 3.3 选择多项式时间（polynomial time）

有同学回答“多项式时间”，老师肯定：现在一般选择的就是**多项式时间**。但老师反复追问：**为什么多项式时间是好的？**

**例子**：老师博士一年级上复杂度课时，老师说“有一个算法复杂度是 3 的 80 次方，这是一个非常好的算法，因为它是常数”。但现实中这个算法非常垃圾。这说明：说“多项式时间”时一定要深入反复理解，不能别人说多项式时间就认。

关键点：**看增长速率，不是看绝对数值**。多项式时间刻画的是增长趋势。

老师从多个角度解释为什么 poly 是“硬通货”：

1. **现实中绝大多数高效算法都是 poly 的**，且很多限制在低次（比如 1 到 3 次左右，n、n²、n³，中间可能有 log 因子）。这是统计性观察，不是说所有。
2. **传递性/语言无关性**：一个算法在 C++ 里是多项式时间，转成 Java 或 Python 也是多项式的；不会出现在这个语言里是多项式、到那个语言里就变成指数级的情况。老师说“封闭性”这个词不太严格，但意思是：只要在一个语言里是 poly，在其他语言里编也是 poly，不用考虑底层原语是什么。
3. **可组合性（composition）**：如果 F 是 poly，G 是 poly，那么组合起来也是 poly；可以叠加，但不能叠加太多次（常数次叠加没问题；如果叠加次数本身爆炸就不行）。在常数级别的组合下，poly 是封闭的。

### 3.4 现实世界中的“好算法”与“坏算法”分布

老师画图说明：

- 现实中好的高效算法基本集中在多项式时间这一块（n、n²、n³ 等低次）。
- 坏的东西（如 3 的 80 次方这种极度垃圾的例子）在很外面。
- 而解决 RSA、离散对数这类问题的算法，都是指数级或亚指数级（sub-exponential）的——即 super-polynomial。
- 老师用“癌细胞”比喻：希望现实中好算法都离这条线远远的，切割得干净；不希望癌细胞扩散得很厉害，希望它待在那儿，好的组织被清晰包进去。

### 3.5 攻击者本质上是什么？

- 攻击者本质上**是一个算法**（老师说自己第一印象把它当成人，但它本质上是算法）。
- 衡量算法复杂度时，一般把它推导/归约到**确定性图灵机**上看 steps（步数）。
- 然后老师展示形式化定义：一个图灵机 M 是多项式时间的，如果存在一个常数 C，使得对于任何长度为 n 的输入字符串，M 最多在 n^C 步内停机（running time 的上界是 n 的 C 次方）。
- 但确定性不够：第一节课说过算法很多时候希望是**随机的（randomized）**。所以再加一条**随机带（random tape）**，变成三条带子。随机带上的随机是**纯随机**（真随机，不考虑随机数质量好不好），由“神仙”给的，可以随便挥霍。
- 随机算法的定义与确定性类似，唯一区别是加了随机带；运行时间上界仍然是 n^C。

### 3.6 PPT 的定义

于是我们有了对攻击者的刻画：**概率多项式时间（Probabilistic Polynomial-Time，PPT）**——即随机的、多项式时间的攻击者。以后说起攻击者，一般就限定在这个角度，统称 PPT。

## 四、寻找困难问题：从信仰 P≠NP 出发

### 4.1 需要攻击者在多项式时间内解不了的难题

- 回到主题：我们要找一个 assumption，使得它有用；它应该是**攻击者解不了的东西**（如大数分解，希望攻击者解不了）。
- 我们要找难题，使得攻击者在多项式时间内解不了。**为什么这么期望？** 因为如果他能解，那这几百年来牛逼的数学大家早就把它解了——我们是这样“欺骗自己”的：没有说它真的解不了，只是说如果在约定时间内被解了，那这些大牛早就提出来了。

### 4.2 停机问题：真困难但没用

- 首先想到的著名困难问题：**停机问题**（判断一个图灵机是否停机）。它确实解不了，是非常著名的困难问题，但**对我们没多大用**。

### 4.3 P≠NP：计算机人的信仰

- 作为计算机人，更喜欢的是 **P≠NP** 这个信仰。如果 AI 证明出来 P=NP，那老师也认了，“那就失业吧”；但现在它还是我们的信仰。
- 基于 P≠NP 提出困难问题，比如 **NP 完全问题（NP-complete）**。P 是多项式时间可解的语言类，NP 是多项式时间可验证的语言类；如果 P=NP，那什么都别说了，直接蔓延过来。
- 但 NP 完全问题**不是无条件困难**的：它只是在“现在/多项式时间内”不困难；如果 P=NP 它就不困难了。老师强调：这是**我们的信仰**，你要是想构造一个基于它的加密算法，那基本上也是世界级贡献（飞沫思维=非凡思维）。
- 目标：用这一类基于信仰的困难问题去构造一个 assumption，并且它正好有用——能实现加密算法。

## 五、从加密系统的必要条件推出单向函数（One-Way Function）

### 5.1 加密系统需要的两条必要条件

老师从加密系统出发，看它需要什么：

- **正确性**：加密后能解密。
- **高效性**：给定密钥 k 和消息 m，能很快计算密文 c（加密不能太慢）；解密先忽略，最后补上。
- **安全性**：攻击者或任何算法只拿到密文 c 时，想得到 k 或 m 是**难**的（从 c 反推 k/m 难）。

这两条（正向好算、反向难算）是任何有意义的加密系统的**必要条件**（不充分，但必须满足）。先从必要条件入手去推 assumption。

### 5.2 单向函数的直觉

这给我们的感觉就是**单向性**：像二极管一样，只能从一个方向走，不能逆行；像高速公路只能往前开，不能逆行。函数进去就出不来：有 k、m 可以算 c，但有 c 不能反推 k、m。

这个函数就叫 **单向函数（One-Way Function）**：它是一个 function，并且“这边好过，那边不好过”。

### 5.3 从最极端的“好”出发：worst-case 单向函数

老师想提一个**跟 1+1=2 最近**的东西——假设越少越好，不想提得太高（安全性特别不好），要提一个离“基石”最近的、假设最少的东西。

这就是 **worst-case 单向函数**（最坏情况单向函数），它是起点，之后慢慢扩张成其他类型的单向函数。

定义（两个条件）：

1. **易于计算（easy to compute）**：存在多项式时间算法，对任何 x 都能算出 f(x)。
2. **难以还原（hard to invert）**：不存在这样的 PPT 攻击者，使得他**每个**都能还原。

关键理解“还原（invert）”：

- 还原不是要求一定把原来的 x 计算出来；而是说**计算不出一个 y 使得 f(x)=f(y)**（即找不到一个原像）。
- 例子：截断函数 f(x) 把 x 的一半切掉。它不是单向函数，因为把任何一半补上任意数都能相等——攻击者很容易找到碰撞。
- 所以单向函数中，攻击者“赢”的条件是：只要他找到任何一个 y 使得 f(y)=f(x) 就算赢；不要求 y 和 x 相同。

关键理解“worst-case（最坏情况）”：

- 对于任何攻击者，他**不可能把所有的 x 都搞定**；总有几个搞不定的。至少有一个搞不定，就叫 worst-case。
- 即：哪怕攻击者能还原绝大多数，也总有一两个“别扭”的点还原不了。

### 5.4 worst-case 单向函数与 P≠NP 的关系

- worst-case 单向函数和“NP not in BPP”（NP 不在 BPP 中）是**等价**的（老师提到 BPP，大家现在认为 BPP=P，但没人证明出来，这是世界级贡献难题；先不管）。
- 换句话说，它跟我们“信仰”很近很近。老师讲故事：这个 assumption 的根源来源于原始信仰 P≠NP；它是我们信仰力量的传承——如果这个东西坏掉，后面所有的话都是 garbage；如果你信这个东西，它就慢慢进行力量的传承。
- 第一条原则：我们找 assumption 要满足原始信仰，不是乱来的。

### 5.5 worst-case 单向函数“没用”

- 但 worst-case 的定义是：不存在攻击者能**百分之百**还原；即对任何攻击者，总有那么一两个点还原不了。
- 问题是：攻击者可以还原绝大多数，只有少数几个不能还原——这**没法用**！
- 加密时我们希望的是**全部不能还原**（任何东西都不能还原），而不是“绝大多数能还原、少数不能”。攻击者如果能把绝大多数 message/key 都搞出来，我们不能接受。
- 所以虽然它很好地传承了信仰力量，但真的没法用，必须调整。

### 5.6 退而求其次：strong 单向函数

- 我们希望“所有东西都不能还原”，但这**不可能**：比如提前定死一个 X，不管什么输入都输出 X——这是一个 dummy 算法，它在 X 这个点上绝对能还原（至少有一个饱和点）。
- 所以“所有都不能还原”太过分，退而求其次：**不能还原的点是绝大多数，允许很小很小一部分可以被还原**。
- 比喻（“金主爸爸”的要求）：饭里绝大多数是米，可能有那么一两粒沙子，我们希望吃不到；不能接受“全是沙子里面放几粒米”（那是 worst-case 反过来，吃不下去）。也不能要求“必须全部是米”（搞不起）。
- 即：能接受很小比例的可还原点，绝大多数不可还原。

**如何定义“小（small）”？**

- 用小=1/大来定义；先定义“大”，再取倒数。
- **大 = super-polynomial（超多项式）**：不是多项式，即对于任何常数 C，都无法被 n^C 支配；等价地，对于任何 C，存在无穷多个 n 使得 f(n) > n^C（老师用“存在一个 N，当 n>N 时 f(n)>n^C”来刻画，并强调这是**存在性**的，不是对所有 n 都满足）。
- 例子：2^n 是 super-poly；n^100 不是（它是 poly，因为存在 C=100 使它被 n^C 支配）；2^(log n)² 不是 super-poly（它等于 n^(log n)，可以被 n^C 支配？老师课上讨论后认为它被 n 的某次方支配，不是 super-poly）；而 2^(n^ε) 这类（离散对数算法常见复杂度）是 super-poly。
- 老师强调定义要抓住**增长速率**，并且 super-poly 的定义是“存在一个 N，越过之后就被支配”，但也提醒：真正想要的是越过某条临界线之后一直表现得很亮眼，而不是脉冲函数/阶梯函数——即对任何 C，存在 N，使得对任何 n>N，f(n)>n^C。
- **小（negligible，可忽略）**：小 = 1/super-poly。密码学里通常不用 small，而用 **negligible**，语义完全等价。

**strong 单向函数的定义**：

- 存在一个可忽略函数 negl，使得对于任何 PPT 攻击者 A，A 拿到 f(x) 后能还原成功的概率小于 negl(n)。
- 即：能还原的部分非常非常小。
- 关于 n 小的时候：下节课会讲，n 本身是参数，n 小时不 care（比如密钥只有 1 比特，肯定容易被猜，本身有信息量问题，不相关）；密码安全性建立在参数足够大时是好的就行了。

### 5.7 现实中的函数很难达到 strong

- 从 worst-case 到 strong，看起来适合“金主爸爸”的先进要求；worst-case 离信仰最近，但做不到 strong。
- 现实中我们用的一些函数，也很难实现 strong 这个等级。
- 所以**逼着还要再往回退一步**：允许很多能搞定，但希望你搞不定的部分也不是那么小（不像 strong 那么小）。比喻：允许饭里很多沙子，但饭团里米也不能太少，不能让我过分到找不到 1 厘米的米。
- 这个降低条件不是不想代表几种办法，而是真的搞不定，必须给自己划一条能搞定的线。
- 老师提醒：图上画的 worst-case 和 strong 看起来近，事实上它们有天差地别（本质等价性的讨论下节课讲，通过构造可以证明某些等价性）。

## 六、week 单向函数及其构造

### 6.1 week 单向函数的定义

- 存在一个多项式（poly）的东西，而对于任何 PPT 攻击者 A，A 可以还原的部分**不是可忽略的**（即有一个不可忽略的 fraction 还原不了？老师表述为：所有攻击者总有至少这么一个 fraction 你还原不了；换句话说，可还原部分不能小到 negligible）。
- 老师这里讲得较绕，核心是：**允许攻击者还原不少，但要求存在一个不可忽略比例的部分攻击者还原不了**（即“搞不定的部分不是那么小”）。

### 6.2 构造：乘法函数

- 老师说这个 one-way function 大家可能第一次听，感觉很神秘，但构造非常简单：**乘法**。f(x,y)=x·y。
- 但显然这**不是**单向函数：对于任何 x，取 y=1，f(x,1)=x，攻击者很容易还原（任何 x 都能被搞定）。
- 做一点改动：f(x,y)=x·y，但要求 x≠1 且 y≠1（“只要有一个等于 1 就都等于 1 了”，所以排除）。这样大多数值比如 100，不管怎么乘都可以分解成 2 和 50（2×50=100），绝大多数都能搞定；但我们期望有些地方搞不定。
- 讲构造时老师只讲**性质/直觉**，不做 reduction（第一个 reduction 在线上面，时间关系不讲），说明它为什么“牛逼”：
  - 当 x 和 y 都是**大素数**时，给出 x·y 计算 x、y 是很难的（大数分解）。
  - x 和 y 是从 n 比特里**随机选**的；如果 x、y 同时为大素数的概率不低（数学上可证明：n 比特随机数中是素数的比例不低，约 1/n 量级，老师给了比较松的界），那么只要 x、y 落在这个“好的素数”比例里，我们就很难分解。
  - 换句话说，只要有一个不小的比例落在好地方，它就是一个 week 单向函数。

### 6.3 从 week 到 strong 的扩张

- 假设有 N 个 week 单向函数 f₁, f₂, …, f_N。
- 定义 F(x) = f₁(x₁) ‖ f₂(x₂) ‖ … ‖ f_N(x_N)（把输入 x 分成 N 份，分别作用后拼接）。
- 通过这个扩张，F 就变成了 **strong** 单向函数：只要有一个 f_i 搞不定，你就搞不定——哪怕你解出来很多，但有一个卡住你就吐血了。
- 所以通过简单的扩张，可以看到 week 和 strong 的**等价性**（在构造意义上没有本质不同）。这条线（从 worst-case 到 week 到 strong）是为了让我们更好地构造这样的函数。
