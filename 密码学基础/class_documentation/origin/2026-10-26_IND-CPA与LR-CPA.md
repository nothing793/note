# 10.26  承接前次课程（IND-CPA 与 LR-CPA 的定义与等价性）内容还原


## 一、开场：继续上节课的 IND-CPA 游戏（Phase 1 允许任意询问）

老师接着上节课的内容，展示 IND-CPA 游戏的完整结构。首先强调：**Phase 1 中攻击者可以任意询问加密信息，且这些 message 完全由 A 自己选取**。

- 攻击者额外获得的信息（询问得到的密文）**可以跟后面的 M0*、M1* 强相关**，甚至直接就是 M0*/M1* 本身——老师明确说“我现在不做任何限制”，把 A 能拿到的信息全部放开，看他能做成什么。
- A 拿到这些消息后，相应地把密文发过去（挑战者回答）。
- 但 A 还不满意，**还可以继续问 message**——比如问到了 M100，还可以继续问 M101，**问到满意为止**，什么时候满意？什么时候输出 b'（猜测比特）。

**老师点出问题**：在 multiple message security 的对话里，还有一个**静态局限性**——攻击者在做决定之前是“全盲”的。现在要对他进行**高强度的增强**：

> 你做这个决定之前，不再是线下全盲的；你现在可以**依靠这些询问得到的密文**去做决定。如果我连这个都能保住（即攻击者拥有这些信息后仍然安全），那你显然就是一个 multiple-message-secure 的；我连更强的高手都能打得过，打你肯定能打得过。所以这边我们只是对 A 进行增强，A 只强不弱。

## 二、简化：把“发很多消息”改成“发两个消息”

老师指出定义里有个**臃肿的点**：每次发很多消息。做 reduction 时如果以这种形式，作为单个定义非常不简洁，所以做一个**取巧的简化**：

- 不再发一坨消息，而是**只发两个消息 M0*、M1***（要求长度相等）。
- 挑战者拿到这两个消息后，加密其中一个（按比特 b）返回密文。
- 这个简化**不损失任何安全性**：简化后的版本照样能包住（比增强版只强不弱），照样比原来强。如果简化损害了安全性，那肯定不行。

## 三、IND-CPA 的五个阶段（著名定义）

老师给出 IND-CPA 的完整五阶段定义（这是图灵奖得主 Goldwasser–Micali 提出的著名 notion）：

1. **Initial phase（初始化阶段）**：挑战者把 public parameter（安全参数、算法等）发给攻击者。
2. **Phase 1（询问阶段一）**：攻击者可以**任意询问**加密信息，message 完全由 A 自己选取（“你问我答”）。
3. **Challenge phase（挑战阶段）**：A 基于已有信息**选取两个消息 M0*、M1***（length equal）。
   - 关键：**M0*、M1* 完全可以跟 Phase 1 询问的消息强相关**——可以把 Phase 1 得到的密文直接放在 M0* 上、M1* 上，可以设成任何函数，“你想怎么搞怎么搞，我不做任何限制”。
4. **挑战者投 b**，加密 M_b* 返回给 A。
5. **Phase 2（询问阶段二）**：A 还不满意，**可以再来一轮“你问我答”**——看了挑战密文之后，还可以继续问、继续看，**很多轮，只要是多项式次**。
6. **Guess（猜测阶段）**：A 拿到全部信息后，输出猜测 b'。

老师强调：相比于我们一开始非常认可的 EAV 定义，IND-CPA **仅仅给 A 多加了 Phase 1 和 Phase 2 这两个东西**，其他完全一样。所以问题来了：**凭什么给 A 这个额外待遇？背后的原理是什么？**

## 四、为什么允许攻击者“选择明文”（Phase 1/2 的合理性）

**最朴素的加密应用认知**：Alice 和 Bob 通信，攻击者在旁边窃听；message 是 Alice/Bob 自己选的。攻击者“呆呆地”去窃听密文，**凭什么能看到他想看到的密文**？人家加密 M=100，你凭什么想让人家加密 M=1？按正常道理，你不应该看到 M=1 的密文。

**但现实中，攻击者有能力诱导 Alice/Bob 去加密他想要的信息**。老师举了**中途岛战役**的经典例子（这是 IND-CPA 思想的一个真实应用）：

- 二战中途岛战役时，白宫和海军司令部认知不一致：海军认为日本要攻击中途岛，白宫认为另一个岛，不确定该集中防守哪里。
- 美军在窃听到的日本海军密文中，经常看到一个加密符号 **“AF”**，但不知道 AF 对应什么明文（无法解密）。
- 于是美军**散布假消息**：中途岛缺少淡水（或电力）。
- 随后收到日本电文：“**AF is short of water**”——通过这个“钓鱼执法”，确定了 AF 代表的就是中途岛。
- 所以美军在中途岛集中防守，赢得了战役。

**结论**：攻击者确实有人文手段（钓鱼、诱导）使用户加密相应的明文。现实中真的有攻击者可以拿到他想要的密文。所以赋予 A 这个权利**并不过分，而且非常 nice、非常必要**。

## 五、IND-CPA 为什么能防住“确定性加密攻击”（high-level 直觉）

老师回顾之前的攻击：攻击者发两个消息——一个两条相等（M0=M0），一个两条不相等（M1≠M2）。如果是确定性加密，C1=C2；如果不是，C1≠C2，一眼就能区分。**IND-CPA 能不能防住这个攻击？** 如果连这个都防不了，那想都不要想。

**确定性加密为什么实现不了 IND-CPA**：

- 攻击者可以选取 M1 得到密文，再选取 M2 得到密文；然后把 M0* 设为 M1、M1* 设为 M2，观察挑战密文和哪个相等，就能判断是哪个。
- 换句话说，IND-CPA 在抵抗这种攻击时没问题。

**IND-CPA 好的核心原因**：

> 因为 M0*、M1* 的选取完全可以跟 Phase 1 询问的消息**强相关**，所以你加密的时候也必须做到：**即使加密同一个消息，加密出来的密文必须长得完全不一样**。如果消息加密的也是 M1，那么这个消息和这个消息必须看起来非常不一样才行，否则一眼能看出来。**即使对于同一个明文，用不同的随机数加密出来的密文必须长得非常非常随机**——这就是 CPA 的好处，也是 IND-CPA 的 high-level idea。

老师强调：这只是 high-level 直觉，我们的目标是 multiple message security（reuse），必须证明 IND-CPA 真的能保证 multiple message security，才能真正被 convince。

## 六、证明策略：找一个与 IND-CPA 等价、且一眼能包住 multiple message 的新 notion（LR-CPA）

老师说明：证明 IND-CPA ⇒ multiple message security 有无数种方法，这里只展示其中一种。

**策略**：找一个**新的 security notion**，满足：

1. 它与 IND-CPA **等价**；
2. 它**一眼就能包住（严格强于）multiple message security**（即如果满足这个 notion，就显然满足 multi-message）。

这个 notion 就是 **LR-CPA（Left-or-Right CPA 游戏）**。

### 6.1 LR-CPA 的结构（三个阶段的交互式游戏）

LR-CPA 本质上也是**三个阶段**（和 multiple message 的“三个阶段”对应）：

1. **初始化/挑战阶段**：挑战者自己**先把 sk 和 b 都选好**（b 是挑战比特）。
2. **交互式 challenge phase**：A 发送 M0_1、M1_1，挑战者回答 **Enc(sk, M_b1)**（即按 b 选左边或右边加密）；A 根据密文再选 M0_2、M1_2，挑战者回答 Enc(sk, M_b2)；……一直到第 q 个，回答 Enc(sk, M_bq)。
3. **Guess**：A 输出 b'。

**与 multiple message 的区别**：

- multiple message 是**静态策略**：A 必须一次性把全部 message 准备好交上去。
- LR-CPA 是**动态策略**：A 看到密文之后，可以**一步一步调整策略**，再选下一组 message。
- 所以 LR-CPA 中 A 收到的信息就是“这一坨”叠起来，**A 只强不弱**（严格强于 multiple message）。

**逻辑**：如果 A 连 LR-CPA 都打不过（LR-CPA 安全），那显然 multiple message 也打不过（因为 LR-CPA 更强）。所以 **LR-CPA 安全 ⇒ multiple message 安全**。

### 6.2 证明 LR-CPA 与 IND-CPA 等价（reduction 方向）

**要证**：LR-CPA 和 IND-CPA **等价**。

老师特别讲了证明方向的“反直觉”之处，强调**严格走定义**：

- 要证的是：“如果 IND-CPA 安全，则 LR-CPA 安全。”
- 反过来说（逆否）：**如果存在攻击者 A 能攻破 LR-CPA，那么就存在 reduction 能攻破 IND-CPA**。
- 老师提醒：这个方向有点反直觉，不清楚时就严格把定义写下来、对照着走；还可以对照上节课 PRG 的 reduction。

**Reduction 的双游戏结构**（老师反复强调这是 reduction 的本质）：

> reduction 本质上在玩**两个游戏**：一个是他和真正的“金主爸爸”（外部挑战者）玩，一个是内部对 A 玩的游戏。做 reduction 时，**把左边的放到外面，右边的放到里面**。

具体到 LR-CPA ⇒ IND-CPA：

- **外面**：reduction 和 IND-CPA 的挑战者（金主爸爸）玩。
- **里面**：reduction 扮演挑战者，和攻破 LR-CPA 的 A 玩。
- 逻辑：如果 A 能以高概率攻破 LR-CPA，那么 reduction 就能以高概率攻破 IND-CPA。

### 6.3 Reduction 的详细步骤（逐步模拟）

老师一步一步展示 reduction 如何“骗”A：

1. **第一步（public parameter）**：IND-CPA 挑战者给 reduction 的 public parameter，**直接转发**给 A（不需要改装，因为这里不是改装 PRG，而是玩 IND-CPA）。
2. **第二步（生成 sk 和 b）**：正常 IND-CPA 中挑战者要自己生成 sk 和 b；现在 reduction **不知道 sk**，所以**假装有**这个 sk（“假装防锈的，假装有的，他没有真有”）。
   - A 说：你假装有没有问题我不管，我也不需要你给我 sk 的信息，但**你必须做好加密**——我发一个 M，你必须回答我。
3. **Phase 1 询问**：A 每次发送 M，reduction 需要回答 Enc(sk, M_b)。但 reduction 不知道 b，怎么办？
   - **策略**：把 M 同时作为 M0 和 M1 发给金主爸爸（即令 M0 = M1 = M）。**甭管金主爸爸的 b 是什么，他回答的都是 Enc(sk, M)**——通过这个简单策略就解决了。
   - 可以看到 LR-CPA 完全能把 Phase 1/Phase 2 发酵出来的新能力**包住**。
4. **继续询问 M2、M3……**：同样把 M 同时作为 M0=M1 发过去，拿到密文后直接转发给 A。
5. **Challenge phase**：A 发 M0*、M1*。reduction **直接把这两个甩给金主爸爸**（作为 IND-CPA 的挑战消息），金主爸爸返回 Enc(sk, M_b*)。
   - 注意：这里 reduction **自己投 b 的环节少了**——它把金主爸爸的 b 直接用了（“金主爸爸里面的秘密他全用了”）。
6. **Phase 2**：A 继续问，reduction 同样用 M0=M1 的策略回答（把同一个消息同时作为左右发过去）。
7. **Guess**：A 输出 b'。reduction 的策略是“**你猜什么，我猜什么**”（直接把 b' 作为自己的猜测），不做任何处理。

**概率分析**：

- 如果 A 赢了（b' = b），那么 reduction 也赢（因为 reduction 用的 b 就是金主爸爸的 b，A 猜对 b 等价于 reduction 猜对）。
- 所以 Pr[reduction 赢] ≥ Pr[A 赢] = 1/2 + δ（δ 是 A 攻破 LR-CPA 的优势）。
- 结论：reduction 的优势至少是 δ，δ 不小，所以 reduction 能攻破 IND-CPA。

老师强调：这个分析和上次 reduction 不太一样，但逻辑很直接——**A 赢显然这边就会赢**，因为用的东西完全一样。

## 七、核心难点：如何用“1 块钱”满足“无穷欲望”的攻击者（hybrid argument）

老师提出两个定义之间的矛盾点：

- 在 LR-CPA 里，A 可以**享受很多次关于 sk 和 b 的信息**（可以问很多次、花很多钱）。
- 但在 IND-CPA 里，A **只能问一次**（“只能花 1 块钱”）。
- 问题：**如何用 1 块钱去满足这个无穷欲望的攻击者？**

### 7.1 难点具体化

Reduction 的策略：

1. 第一步 public parameter 直接转发（没问题）。
2. Reduction 想依靠金主爸爸的能力，自己不生成 sk 和 b（“自己不确诊，不去产生这个 SK 和 b”）。
3. A 开始问 M0、M1：
   - 如果 M0 = M1，很简单，直接甩过去（同时作为左右）。
   - **但 A 为什么要听你的？M0、M1 是 A 自己选的，如果 M0 ≠ M1，你怎么伪装？** 你现在既没有 sk，也没有 b，但要回答一个 Enc(sk, M_b) 给 A——这是你的任务。
4. 金主爸爸（IND-CPA 挑战者）**只给你 1 块钱**：你只能发一次 M0、M1，拿到一个挑战密文后，他就进入“只回答一次”的模式。
   - 你可以“上来就把金主爸爸的所有钱花完”，满足 A 一次；但 A 是**无穷欲望**的攻击者，第二次问题就搞不定了，金主爸爸不再搭理你。
   - 你自己随机选 b 的话，怎么保证你选的 b 和金主爸爸的 b 相等？不相等就会很麻烦。

### 7.2 解决：用“时间换空间”——hybrid argument（混合论证）

**核心思想**：金主爸爸只让花 1 块钱没问题，但你挡不住我**玩很多次游戏**（不同的变种）。

- 比喻：**分期付款**——我第一天花你一块，第二天换你一块，一共 100 天就能换你 100 块钱。
- 把 LR-CPA 游戏**拆解成很多个 hybrid 游戏**，每个游戏只花一次金主爸爸的钱；合起来就组装成功了。

**Hybrid 游戏的定义**（把“回答左边还是右边”定死，不猜）：

- **Game Left**：甭管 A 怎么问，**全部回答左边的**（M0 的加密）。这是定死的，没有 b。
- **Game 1**：除了**第一个**回答右边的（M1），其他都回答左边的。
- **Game 2**：前两个回答右边的，剩下的回答左边的。
- ……
- **Game i**：前 i 个回答右边的，剩下的回答左边的。
- ……
- **Game Right**：**全部回答右边的**（M1 的加密）。

**关键对应**：

- **B = 0** 时，挑战者玩的是 **Game Left**（全部左边）。
- **B = 1** 时，挑战者玩的是 **Game Right**（全部右边）。
- 中间是各种 hybrid Game i。

**证明思路**：

1. 我们知道 **Game Left 和 Game Right 是 CI 的**（计算不可区分）——这正是 multiple message security 要证的（左信息的联合分布 vs 右信息的联合分布无法区分）。
2. 相邻两个 hybrid 游戏 **Game i 和 Game i+1 只差一个位置**（第 i+1 个消息从左边变右边）。
3. 每个相邻对都可以用**一次 IND-CPA 的金主爸爸的钱**来证明它们是 CI 的：
   - 对于 Game i 和 Game i+1，前 i 个消息都回答左边，第 i+1 个位置分别回答左/右，之后都回答左边。
   - 把第 i+1 个位置的 M0、M1 作为挑战消息发给 IND-CPA 挑战者，拿到挑战密文；其他位置的消息用“M0=M1 同时发过去”的策略回答。
   - 如果 A 能区分 Game i 和 Game i+1，就能攻破 IND-CPA。
4. 利用 **CI 的传递性**：Game Left ≈ Game 1 ≈ Game 2 ≈ … ≈ Game Right，所以 Game Left 和 Game Right 是 CI 的。
5. 于是 multiple message security 得证。

**老师比喻**：这就像小学中学里画**辅助线**——直接证 LR-CPA 搞不定太累，我们找一些中间体（hybrid）作为辅助线，帮我们解决问题。本质上是**用空间换时间**的打法：金主爸爸只支持多少，我就换多少个 hybrid；他支持一个，我就换一个；支持两个，我就挑两个。

老师强调：这是密码学中**非常常规、非常非常重要的技术（hybrid argument）**，将来想做密码学的话必须吃透。

## 八、总结与下节课预告

- 通过上面的证明，我们知道了 **IND-CPA 和 LR-CPA 等价**；而 LR-CPA 显然（一眼）**包住 multiple message security**。
- 所以 IND-CPA 是一个**好东西**，满足了我们第二阶段的需求（multiple message security / reuse），并且定义简洁。
- 下节课：如何**升级 PRG**，得到一个新的、更强大的工具，来实现 IND-CPA。
