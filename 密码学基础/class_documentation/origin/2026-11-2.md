## 四、理想构造：纯随机函数（12:30–18:00）

- 如果 R 足够长，希望它是随机的；不需要推进性（不需要延展）。
- 从两个角度理解纯随机函数：
  1. **枚举角度**：把所有 N 比特到 N 比特的函数都枚举出来（有限集合），从中均匀取样一个。这就是随机函数。
  2. **映射角度**：随便安排一个映射；每个输入对应的 value 是纯随机的。
- 好处：即使给出很多点（如 F1 的值），只要给出一个没出现过的点，该点的值仍是纯随机；各个点的值完全独立。
- 若选中了一个函数，剩下的都确定了；但“随机”是对**选择函数的过程**而言的——先定死前 100 个点，再从满足这些约束的函数子集中随机选。
- 把 SK 想象成**下标 index**：SK 决定选哪个函数，SK 本身不告诉攻击者。这样看起来就像纯随机，甚至像 perfect security。

---

## 五、缺陷：SK 太大（18:00–22:30）

- 分析集合大小：所有 N 比特到 N 比特的 mapping，S = (2^N)^(2^N) = 2^(N·2^N)。
- 要准确表达每个函数的分布，SK 长度至少要 log S ≈ N·2^N 比特——**SK 直接爆炸**。
- 我们想要的是 poly 大小、大约 N 比特的 SK。
- 纯随机函数“真的好，但养不起”。退而求其次：找一个**子集** T，体量约 2^N，这样 SK 就是 N 比特。
- 希望从子集里随便选一个元素，其 input-output behavior 在攻击者眼中仍像纯随机。

## 六、用不可区分性（CI）角度理解，以及“读代码”攻击（22:30–29:30）

- 用 CI 角度：左边是关于 G 到 G_t 的均匀分布，右边是 F1 到 F_S 的分布；希望攻击者无法区分。
- 但出现明显问题：攻击者（多项式时间）能**读完**左边函数的代码（描述较短），却**读不完**右边纯随机函数的代码（真值表/描述一定很长很长）。
- 于是有简单的 distinguisher：**能读完的是左边，读不完的是右边**——直接套 CI 就不对了。
- 反思：我们真的需要两者代码不可区分吗？我们真正需要的是**input-output 的分布**，而不是函数本身的代码分布。
- 结论：这个方向做了无用功——第一达不到，第二没必要达到。

## 七、黑盒（oracle）视角与 PRF 定义的雏形（29:30–36:30）

- 只看 output，用**黑盒方法**：把函数锁在黑盒里，只看到输入输出。
- 攻击者 D 进入“你问我答”模式：要么从左边抽一个黑盒，要么从右边抽一个黑盒；D 可以询问任意输入，得到输出。
- 目标：构造一个更小的子集，使得从子集里随便抽取一个元素，其 input-output behavior 与纯随机函数的 input-output behavior 是 CI 的。
- 注意：**G1 到 Gt 这“一坨”的表达是可以给攻击者的**（比如“所有椭圆曲线”“所有 N×M 矩阵的线性变换”），但**具体选哪一个（具体参数 AB）不能告诉**——这由 SK 决定。
- T 虽然比 S 小很多，但仍要足够大，仍是指数级别。
- 这正是 PRF 的关键：很多学生第一次觉得“这一坨都不能给”，其实**可以给这一坨信息，但具体选哪个不告诉你**。

## 八、PRF 的定义（42:00–44:00）

- 一个函数族是 PRF，如果：
  1. 第一步：挑战者把整个函数族（“包”）给攻击者；然后随机选一个 SK（下标），决定具体用哪个函数。
  2. 攻击者做两件事：模拟“从函数族中随机选一个函数”的黑盒，或者模拟一个纯随机函数的黑盒。
  3. 存在可忽略函数，使得对任何多项式时间攻击者 A，A 无法区分这两种情况。
- 黑盒处理：A 只关心“我问你答”，不关心内部怎么运行。
- 与 PRG 对比：PRG 是固定函数（N 到 2N 比特）；PRF 是一个函数族（一个“包”），SK 决定选哪个函数。
- PRF 的输入可以是**任意分布**，不需要服从任何分布属性；只要 SK 不泄露，即使输入是攻击者选的，输出分布依然好。

## 九、PRF 的“长度”问题与 PRG 的对比（44:00–48:30）

- 疑问：PRF 输入输出等长，不满足“输出比输入长”，怎么达到 PRG 的目标？
- 回答：PRF 本身不要求延展；但**一个 PRF 可以轻松构造 PRG**：G(x) = (F_x(1), F_x(2), …)，想要多长有多长。
- 关键对标：
  - PRG 里 **X 不能被看到**；
  - PRF 里 **SK 不能被看到**，其他无所谓。
  - 期末考试常考这种对比。
- PRF 的好处：输入不需要任何分布要求；即使知道 F(1) 的值，F(2) 的分布依然纯随机（只要 2 没被问过）。
- 结论：PRF 轻松涵盖 PRG；PRF 与 PRG 在复杂度上本质等价（下节课展开）。

## 十、复杂度等价性与“P vs NP”的题外话（48:30–55:00）

- 下节课会说：PRG、PRF 等在复杂度上本质完全等价；看似每一步都在升级，但三个东西完全等价。
- 构造 PRG 可能需要 N^3/4 个 PRF 等，但本质上是 poly 的。
- 只要有一个是有效的，全部打通；PRF 的安全性从根上依然和单向函数一样可靠。
- 题外话：最近一些结果让大家很慌，做密码的人开始尝试 P≠NP 之类；如果最后证明 P=NP，今天讲的东西全是 garbage。目前只是“晃动一下”，有一些攻击算法。
- 下节课内容：如何从 PRG 构造 PRF；PRG 只要实现 1 比特扩张（N 到 N+1），就能得到 N 到任意 poly 长度的 PRG。

## 十一、用 PRF 构造 IND-CPA 加密（55:00–01:05:00）

- 目标：构造一个 IND-CPA 安全的加密方案。
- 有了 PRF，构造很直接：加密时用随机数 R，计算 F_SK(R) 与明文异或；密文包含 R 和密文主体。
- 正确性：解密时用同一 SK 和 R 重新计算 F_SK(R)，异或还原。
- 密文两个部分：前 N 比特是 R（随机数），后 N 比特是 F_SK(R) ⊕ m。
- 密钥 SK 本质上就是“下标”，决定选函数族中的哪个函数；函数族本身（如“所有椭圆曲线”）是公开信息，具体参数不公开。
- 注意：R 不一定要纯随机，**只要加密过程中不重复**即可（后面归约中会用到“无碰撞”条件）。

## 十二、PRF 的“懒惰采样”模拟（01:05:00–01:14:00）

- 重写 PRF 定义，从 CI 角度改成更 base 的写法，再和 IND-CPA 串联。
- 挑战者要模拟两种黑盒：
  - 左边：真正的 PRF（用 SK）；
  - 右边：纯随机函数。
- 模拟纯随机函数时，**不必把整个真值表列出来**（那太累），用**懒惰采样（lazy sampling）**：
  - 维护一张表；
  - A 问输入 x：若表中有，返回表值；若没有，随机选一个 y，写入表，返回 y；
  - 这样对 A 来说，看到的东西与“勤劳地列出整个真值表”的挑战者**分布完全一样**。
- 对 B=0（PRF 分支）：直接回答 F_SK(x)；B=1（随机分支）：懒惰采样。
- 类比：甲方不 care 你是熬三个夜晚画的还是 AI 画的，只要一模一样；所以能用懒惰采样就用，效果是 identical 的。

## 十三、IND-CPA 归约证明（01:14:00–01:33:00）

**目标**：证明 Π 是 IND-CPA 安全的，即若存在 A 能攻破 Π，则能构造 B 攻破 PRF。

**归约结构**：

1. B 作为 PRF 游戏的攻击者，拿到函数族信息；B 自己扮演 IND-CPA 的挑战者与 A 交互。
2. B 不自己生成 SK，而是用 PRF 游戏给的 SK（A 眼中 SK 从未泄露，所以可以）。
3. **B 猜 b'（PRF 游戏的比特）**，而不是直接用 IND-CPA 的 b；B 内部自己选一个比特 d 作为 IND-CPA 的挑战比特。
4. 加密查询 m：B 选随机 R（要求纯随机/不碰撞），问 PRF oracle 得到 F_SK(R)，返回密文 (R, F_SK(R)⊕m)。
5. 挑战阶段：A 提交 m0, m1；B 自己选 d，选随机 R*，问 oracle 得 F_SK(R*)，返回 (R*, F_SK(R*)⊕m_d)。
6. 其他查询同样处理。
7. 最后 A 输出 d'；B 比较 d' 与 d：
   - 若 d' = d，B 输出 b' = 0（认为在玩 IND-CPA，即 PRF 分支）；
   - 若 d' ≠ d，B 输出 b' = 1（认为收到的是纯随机数，即随机函数分支）。

**分析**：

- **B=0（PRF 分支）**：A 玩的就是真正的 IND-CPA 游戏。若 A 有优势 ε，则 B 猜对的概率 ≈ 1/2 + ε/2（具体为 1/2 + advantage 的一半）。
- **B=1（随机函数分支）**：A 收到的是纯随机数（一次性 pad），A 赢的概率恰好 1/2，与 d 无关；B 猜对概率 = 1/2。
- 因此 B 的优势 ≈ ε/2，若 ε 不可忽略，则 B 攻破 PRF，矛盾。
- 需要处理 **collision（碰撞）**：R 随机选取，若 R_i = R_j（包括与 R* 碰撞），归约会出问题（“出血”）。碰撞概率 ≤ Q²/2^N（Q 为查询次数），是可忽略的；出现碰撞就“认灾”，归约失败概率可忽略。
- 前提：A 的查询次数是多项式级别的；1 - negl 的条件必须成立，否则归约炸掉。

**思想与 PRG 归约相同**：通过观察 A 有没有猜对，来判断 B 处于哪个分支（PRF 还是纯随机）。

## 十四、答疑与补充（01:33:00–结尾）

- 有同学问：SK 选定后，函数不是固定的输入输出吗？怎么做到随机？
  - 回答：SK 选定后函数确实固定，但攻击者**不知道选了哪个**；就像老师有一万套考题，选了一套但不告诉你，对你来说仍是随机的。随机性在于“选择函数”这一步，而不是选择之后。
  - 真值表本身不是“含义”，而是一个表值；纯随机是对“选择”而言的。
- 归约中 B 自己选 d，通过 A 是否猜对来推断分支；与 PRF 游戏“猜 b”本质一致。
- 归约中若 A 输了，B 才可能赢（在 B=1 分支下）；具体输出逻辑课上讨论过，核心是“A 赢 ⇒ B 猜 B=0；A 输 ⇒ B 猜 B=1”这类对应关系。
- 碰撞情况：小概率相等，出现就认灾，损失可忽略。
- 保证 A 问的次数是多项式级别（PPT），否则 1 - negl 不成立。

## 十五、本节要点总结

1. **PRF 定义**：函数族 + 随机下标 SK；攻击者可获得整个函数族描述，但不知道具体选哪个函数；黑盒访问下，与纯随机函数不可区分。
2. **PRF vs PRG**：PRF 不要求延展，但可构造 PRG；两者复杂度等价。对标点：PRG 隐藏 X，PRF 隐藏 SK。
3. **懒惰采样**：模拟纯随机函数只需维护查询表，按需采样，分布与真值表完全一致。
4. **PRF → IND-CPA**：加密 (R, F_SK(R)⊕m)；归约通过“B 猜 b'、内部选 d、观察 A 是否猜对”把 IND-CPA 优势转化为 PRF 优势；碰撞概率可忽略。
5. **考试提示**：可能考定义 + 证明；多写不空着；注意 PRG/PRF 对比这类常考点。
