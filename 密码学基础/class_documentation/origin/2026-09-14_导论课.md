## 二、什么是密码学：从词源到核心应用

**课堂互动**：问大家“说起密码学，脑海里想的是什么？”有同学回答“各种信息的保护手段”，教师肯定了这一回答。教师补充：更多人会联想到口令/登录密码（passcode），他夫人向别人解释他的方向时，文科生常问“你丈夫是研究加密密码/登录密码的吗？”——其实密码学跟口令不太相关，但它确实是一种**保护手段**，关键是要考虑它到底保护什么。

**词源**：cryptography 由两个希腊字母组成，语义学追溯其本义是“隐藏”+“书写”，本质上研究的是**隐写术**——最原始的应用环境是把写作的内容隐藏起来。

**最 fundamental 的应用：信息传输**。Alice 和 Bob 想通信，但通信信道可能被劫持（如两位军事主官意见交流，信使传递路径已被间谍渗透），所有传递的信息都公开给攻击者。密码学最 fundamental 的 application 就是：**在不安全信道中，如何保证 Alice 和 Bob 传输信息的安全**。

**核心观察**：Alice 和 Bob 必须有点别人没有的东西。如果 Alice 有的、Bob 有的，攻击者也有，就无法把信息隐藏起来。由此推论：通信前 Alice 和 Bob 必须各自拥有一个 secret key（就像登录网页时用的密钥，服务器与用户需提前共享密钥）。密钥具体怎么产生，这里先“挖个坑”，课程中后期再填。现在假设有一个非常 nice 的“神仙”/oracle，在通信前提前把 key 同时分发给 Alice 和 Bob（暂且不管这条线怎么运行）。

**基本流程**：有了密钥后，发送方用密钥和 message 做编码（encryption），把编码后的密文发给 Bob；Bob 收到后用同样的 key 解码（decryption）得到 message。攻击者/窃听者没有 key，因此有了保证 message 安全的机会。

## 三、密码系统的六个基本元素

一个成熟的密码系统包含**三个空间 + 三个算法**：

**三个空间**：
- 明文空间 M（message 从哪来）
- 密文空间 C（加密后到哪去）
- 密钥空间 K（k 属于哪里）

**三个算法**：
1. **密钥生成算法（Key Generation）**：核心作用是 oracle 如何产生密钥。它 take 一个东西（第三堂课再解释是什么），输出一个 key。
2. **加密算法（Encryption）**：输入 SK 和 message，输出密文。
3. **解密算法（Decryption）**：输入 SK 和密文，输出明文。

（第一次课写得严格一点，以后不再写这么严格。算法暂时就理解成脑海里那个“算法”东西，不按图灵机解释。）

## 四、三个算法的属性分析

**问题一：算法是否需要保密？**

- 军方加密算法等特殊情况需要保密，但正常情况下我们希望算法**不保密**。原因：即使算法被知道，系统仍然是安全的，那才是真正的安全；如果安全性依赖于算法保密，一旦算法泄露（如通过人文攻击骗出来）就不安全了。
- 这就是 **Kerckhoffs 原则**（奥古斯特·柯克霍夫原则）：算法完全公开，即使算法完全公开的情况下依然安全，才是好的安全算法。
- 第二个论证：算法公开后，才会让世界上聪明人去攻击它。比如算法征集（如 AES 等），都是被全球顶尖科学家攻击了很多年依然安全，才被公开应用。整门课都 follow 这个传统：希望这些东西完全公开。

**问题二：算法是随机算法还是确定性算法？**

- **密钥生成算法**：应该是 **randomized**。如果是确定性算法，攻击者就可以运行确定性算法直接得到 SK，进而攻破 message。所以 key generation 必须随机。
- **解密算法**：**确定性**（高概率）。在 beginner 接触的范围内应该全是确定的，只有极少数很 weird 的算法可能考虑非确定的东西。因为希望发过去的东西能解密，而不是发过去一个 garbage 解密不了——功能性需要有所保障。
- **加密算法**：**既可以是确定性也可以是随机，现阶段绝大多数用的是随机算法**。确定性算法的问题会在第五、六堂课解释（当尝试理解“什么叫安全”时，会看到确定性算法的缺陷）。一些古典加密算法是确定性的，容易形成固有认知，所以现在要强调：加密算法应当随机。至于“加密算法是随机的话怎么对敌手公开”——公开的是算法电路本身，告诉敌手电路长什么样、key 和 message 怎么接进去，但不告诉那一步的具体值。

## 五、密码系统“好”的属性与正确性的形式化

一个密码系统想要：正确性、安全性、高效性等——“既要又还要”。但关键是要把这些属性**用数学语言 formal 出来**。正确性争议不大，但“安全性”在 A 脑子里和 B 脑子里可能完全不一样。必须用确定性的数学语言把安全性定义下来，使讨论不是“公说公有理婆说婆有理”。

**正确性**：希望解密的人解出来的东西，真的是加密的人发出去的信息，即解密后的信息 = 加密前的信息。

**形式化表达**：用概率论方法。解密后的东西形成一个分布，加密后的东西形成一个分布。因为密钥空间里可能有很多 SK，对某个 SK 解密很好，但可能有那么一个非常坏的 SK 解不出来——需要处理这种“不喜欢的”情况。希望对于每个 SK、每个 message，解密结果等于原文；通过这样的写法把坏的情况直接“忘掉”。

- 这是“完美正确性”：对于每个 key、每个 message，解出来都是加密前的东西。
- 但有时可以做一些 relaxation：比如 key 空间很大但坏 key 只有一两个、处理得比较少，某些情况下能容忍。
- 于是用概率方法理解：变成可调的东西，概率分布是 over SK。加密是随机算法，会诱导出 K 上的分布，进而诱导出关于密文的分布。完美正确性时，这个分布就等于 m 本身（分布退化为定值）。用概率形式可以表达“大于 99%”这类可调的、更 flexible 的正确性，不再只能表达完美正确性。这个关键词以后不再解释，本课重点在后面什么是 security。

## 六、什么是“安全”：从传统安全到可证明安全

**课堂互动**：已经有了三个算法和知识之后，如果让你定义一个 formal 的、跟数学沾边的“安全”，一个密码系统是安全的应该长什么样？有同学说“复杂度低”。

**古代/传统如何定义安全**：古代设计密码算法的逻辑是“我比你聪明你就得信我的”——科学家提出算法，大家尊重他都在用，直到某天一个“宅男”直接把它攻破、给出 attack，算法就完全不能用了，然后需要另一个更聪明的科学家提出新算法，日复一日。在 Shannon 理论可证安全提出之前，这是整个密码学的研究路径。

- **Traditional security**：算法如果没有人攻破就是安全的。这是从反馈/结果的角度说的——只需要“你干不死我”，不需要任何证明。
- 这个逻辑很不爽：你不知道“明天”或“干脆什么时候”会来。尤其有了计算机之后，攻破变得简单；有了 AI 之后更简单，“最近的进展把我们都催得没饭吃了”。

**凯撒密码的例子**：
- 最简单的凯撒密码非常脆弱：a 变 b、b 变 c……把密钥给定死了，而密钥生成应是随机算法，所以设计完全不合理。
- 改成“移位密码”（置换密码）：k 每次从 0～25 之间选取（如 k=3 时 a→d，k=4 时 a→e 等），把 k 变成 1～25 上的均匀分布。
- **攻击一：暴力攻击**。密钥空间只有 26 个元素，try all possible keys 解密，看哪条像人话（明文应是文化/有意义的内容而不是 garbage），就能定位到正确 key。被干掉的原因是 key space 太小。如果 key space 大到正常电脑暴力攻击搞不定，就抵抗了暴力攻击——**但抵抗暴力攻击不代表安全**，只是抵抗了暴力攻击。
- **攻击二：频率分析**。这个算法是确定性的：每次加密 a 都映射到同一个密文字母，如果语言环境中 a 出现概率高于 b，密文中对应字母的概率也会更高，这就是可利用的信息。英文中 e 出现最多，可用频率信息做探索。这从小小角度说明了为什么将来更喜欢 randomized 的表达。
- 课堂还展示了一段用置换做的密文，说明用纸笔在 10 分钟内破译虽然看起来很扯、很费劲，但方法就是：第一步数频率（小学生能干，纸上 3～5 分钟）；第二步做图、猜测（出现最高的 r 先猜成 e，第二高的猜 t 等），高概率的几个先拉开差距；然后语义分析、代入、迭代，一层层往下叠，最后完全解出来。

**传统安全的缺陷**：这种“没人攻破就安全”的 philosophy 不好，因为它依赖于“别人有没有攻破”这个反馈属性。构建无条件安全的东西非常难（要 100% 安全、无条件安全很难），所以现实中要找**世界公认的背书**——找一个基石。如果信任基础换成全人类的共识（如“两点之间线段最短”），信心会更高。可以从数学上找一些难的数学问题、困难的计算机问题，比如假设 P≠NP，信心会足一点（虽然有些极端科学家声称做出来了，但大家普遍认为 P≠NP）。以它为基石来构建好的密码系统。

## 七、可证明安全（Provable Security）的三个基本元素

这是本课程的核心话题：**学会可证明安全**。前面传统安全纯粹靠个人声誉背书；可证明安全则要说“我这套密码系统是可证明安全的”。

三个基本元素：
1. **Assumption（基石/前提）**：一个全人类公信的东西，可以想象成 P≠NP 这类假设。
2. **Definition（安全刻画）**：你想实现什么样的安全——把“message 保密”等目标刻画成数学。
3. **Reduction（归约）**：连接 Definition 和 Assumption 的桥梁。意思是：我的安全性与你（假设）强绑定。如果我提了一个很牛的 assumption/definition 说“我这东西是安全的”，你不认怎么办？我就给出一个 reduction：**如果你能攻破我的系统，我就用你的攻击去解决 P≠NP 这个共识问题**。因为全人类信这个基石，所以全人类必须信我的系统——保持因果关系。如果你能干碎我的 definition，我就打碎全人类的共识。

如何理解 definition、如何构建 proper reduction、如何选 assumption，都是可以展开很多的话题，这门课就是一点点从这个角度拆解开：如何选取合适的方式、如何选取合适的 assumption、如何做 reduction。

**重要提醒**：assumption 只是全人类的共识，不代表它一定对。它比个人强大（可能经过上百年锤炼还没被干掉），但历史上也出过事情——从底层把上面碎掉，地基碎了房子就没用了。所以 assumption 一定要选好；同时要兼顾“好用”：有些假设信心很足但很难用、不知道怎么用它构建东西，所以要在“好用可靠”之间选取，一点点往上走，找到合适的东西、合适的内审（definition）去做，中间还要兼顾效率等——这是 provable security 设计的核心概念。

## 八、密码学的现代应用小例子（拓展视野）

现代密码学的应用远不止加密通信。第一堂课讲几个不太 serious、好懂但不那么严格的小例子：

### 1. 安全多方计算（Secure Multi-Party Computation, MPC）

场景：A 有信息 x，B 有信息 y，两人想共同计算函数 f(x,y)，A 想得到结果、B 也想得到结果，但 A 不希望 B 知道 x，B 也不希望 A 知道 y。

**类比**：两个女生想比体重但不想泄露自己的体重——去公园找个跷跷板（物理方法）。问题是在网络世界（cyberspace）里怎么建立这个“跷跷板”。

**交友软件例子**：A 看到 B 的图片选择喜欢（1）/不喜欢（0），B 同样。希望最后只得出“A 和 B 是否同时喜欢对方”：都为 1 则匹配成功继续发展；有一方不喜欢就及时止损。同时希望三种情况无法区分：如果 A 选 0，结果必然是 0，B 知道 A 不喜欢他；但 B 不想让 A 知道自己是不是“舔狗”（B 选 1 而 A 选 0 时，A 不应知道 B 喜欢他）。所以要求：输出 1 的情况与另外两种输出 0 的情况无法区分。

**扑克牌协议**（用 3 张红桃、2 张黑桃）：中间放一张共用红桃，A 和 B 各有一张红桃一张黑桃。选 1 则把红桃放得离中间红桃更近，选 0 则放黑桃（或反过来放）。四种情况中，需要做到：两方都选 1 的那条线能与另外三种情况区分开（通过排列区分），同时另外三种情况彼此无法区分。通过一个 shift（A 在背后做置换/切牌，B 猜是否交换）来实现：A 把牌拿到背后，以 1/2 概率交换、1/2 概率不动，摊出来后问 B“我有没有交换”。如果两球/牌真的完全一样，B 猜对的概率只有 1/2；如果 B 每次都能猜对，A 的信心就越来越足（100 次都对，概率极低），从而确信 B 真的能区分。这里有个问题：**必须 A 和 B 都是 honest 的**——如果一方内心选 0 却故意选 1，就想看 B 是不是“舔狗”，信息就泄露了。所以要保证参与者不玩 malicious，或者构造即使 malicious 也能搞定的协议，这需要高级技术。这个例子也说明：**definition 本身非常重要**，它告诉你 A 和 B 的表现方式；表现方式不同对应不同的 definition，不同 definition 下安全性完全不一样。

### 2. 零知识证明（Zero-Knowledge Proof）

**GPA 例子**：去面试，公司要求 GPA 超过 90 分，但你不想让对方知道你真正的 GPA、不把成绩单给他。如何在不泄露成绩单的情况下让对方确认你的成绩超过 90？对方得不到任何信息，但能被说服——这是零知识证明。区块链很火带火了 ZKP，这是一个非常大的方向。隐私保护计算/隐私计算中，MPC 是基石；ZKP 在区块链/稳定币方向有大量落地应用，这两个方向很容易形成落地应用。

**色盲与两个球的例子**：A 是色盲，有两个外形一模一样、只有颜色（红/绿）不同的球，A 无法区分颜色。B 的任务是让 A 确信“这俩球不一样”，但不告诉 A 哪个是红、哪个是绿。方法：A 把球拿到手背后，以 1/2 概率交换、1/2 概率不动，摊出来后问 B“我有没有交换”。如果两球真的一样，B 只能纯猜，猜对概率 1/2；如果 B 每次都能猜对（n 次，如 100 次），A 的信心就非常足，确信 B 真的知道一些自己不知道的事情——即两球确实不一样。这就是零知识证明的直观思想。

**零知识证明最神奇的一点**：正常逻辑应先定义什么叫 knowledge，再定义什么叫 zero knowledge；但 knowledge 完全无法定义（你眼中的 knowledge 在别人眼中可能是 garbage，教授也无法证明“这东西就是 knowledge”）。**ZKP 在没有定义什么叫 knowledge 的情况下，定义了什么叫 zero knowledge**。直观理解：问“这堂课有没有学到新内容”——“新内容”无法定义；但如果你在宿舍里对着空气把老师讲的东西全部讲一遍，说明你肯定没学到新知识（学了跟没学一样，没有 additional 的知识）。所以 zero knowledge 的核心：A 没有获得 additional 的信息。做 definition 时，不 care 你“有”什么知识，只 care 你看到我的东西、运行之后有没有得到新的东西；证明“你折腾半天跟没折腾一样”，就是安全的——这是一种很好的思路。

## 九、下堂课预告与结尾

下堂课将从 Alice-Bob 通信出发，尝试做一个密码系统的 definition。按 Kerckhoffs 原则，除密钥外其他东西攻击者全知道，所以安全性仅仅依赖于密钥的安全性。

**一个看似正确但会被反例击碎的定义**：第一个想法是“攻击者折腾半天，对密钥一无所知”——这看起来对，但一个反例就能击碎它。因为**真正要保护的对象是 message**，message 才是“爹”；密钥只是“大表哥”，是保护安全的**必要条件**而非重点。做 definition 时一定要抓住 message。

课程结尾：今天主要给一些 high-level 的 idea，让大家知道密码学到底在玩啥。很多学校的密码学课程不是这么上的，教师想做一点正确的事情，所以 PPT 可能只剩一两页，其余全是板书。希望大家多听、回去思考、多记笔记；有兴趣可读经典教科书（常读常新，教师自己每次读都发现有不懂的地方）。今天就到这。
